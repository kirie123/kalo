# 右键菜单

日期：2026-08-27
状态：方案（本次实现）

## 现状

全应用只有一处右键菜单：文件面板（`kalo-desktop/src/components/FilePanel.tsx`）的文件树和改动列表，
两个 `onContextMenu` 把 `{x, y, entry}` 存进本文件的 `MenuState`，由同文件内的私有 `ContextMenu`
组件渲染（`fixed inset-0` 遮罩 + 绝对定位的卡片，Escape 关闭，点条目后关闭）。

其他能看到路径 / 能操作的行，右键都没反应：

1. **「编辑了 N 个文件」卡片的文件行**（`ChangedFilesCard.tsx` 的 `FileRow`）
   左键 = 打开 `FileViewerModal`（改动 / 全文两个 tab）。想在资源管理器里定位这个文件，
   只能进 modal 里复制路径再自己去粘贴 —— **没有「打开所在文件夹」**。
2. **侧边栏聊天条目**（`Sidebar.tsx` 的 `SessionRowItem`）
   只有 hover 才出现的「...」按钮，里面是 `SessionMenu` 自己手写的下拉：重命名、删除会话。
   这套下拉又重复实现了一遍 outside-click / Escape 关闭逻辑，和 FilePanel 的那套并行存在。

后端能力是齐的，不需要改 Rust：

- `open_path(path, reveal)`（`src-tauri/src/main.rs:340` → `files.rs:396`）
  `reveal=false` 用系统默认程序打开；`reveal=true` 在文件管理器里定位（Windows 走
  `explorer /select,<path>`，目录则打开自身）。自定义 command，不是插件，`capabilities/default.json`
  无需新增权限。
- 前端封装 `openPath(path, reveal = false)`（`src/lib/pi-bridge.ts:279`），FilePanel、FeedsSettings、
  NoteEditor 等处已在用。

## 目标与非目标

目标：

- 抽一个共享菜单组件，三处（改动文件行、侧边栏聊天条目、文件面板）复用，样式与关闭行为只写一遍。
- 改动文件行 / 聊天条目右键可用，且都有「打开所在文件夹」。
- 聊天条目的「...」下拉和右键菜单**同一份菜单项**，不会一边加了另一边漏。

非目标（本期不做）：

- 侧边栏**项目行**（现在是 hover 出现的 + / × 小图标）。
- 用户消息里的**附件卡片**（`UserBubble.tsx`，左键已能用默认程序打开）。
- 多选、子菜单、快捷键提示。

## 方案

### 1. 共享组件 `src/components/ContextMenu.tsx`

```ts
export interface MenuItem {
  label: string;
  action: () => void;
  /** 危险操作（删除），用 --danger 着色 */
  danger?: boolean;
}

export default function ContextMenu(props: {
  at: { x: number; y: number };
  items: MenuItem[];
  onClose: () => void;
}): ReactElement

export function useContextMenu(): {
  at: { x: number; y: number } | null;
  /** 行的 onContextMenu：preventDefault + stopPropagation，记下光标位置 */
  onContextMenu: (e: MouseEvent) => void;
  /** 点击式入口（「...」按钮）：贴着按钮下沿、右边缘对齐弹出 */
  openAtRect: (el: HTMLElement) => void;
  close: () => void;
};

/** 三处都要的两个菜单项工厂，省掉各自重复 toast 处理 */
export function copyPathItem(path: string, label?: string): MenuItem;
export function openPathItem(label: string, path: string, reveal?: boolean): MenuItem;
```

实现要点：

- **portal 到 `document.body`**。会话区被 CSS `zoom` 缩放（`ChatView.tsx:42`，Shift+滚轮 0.8~1.6），
  `position: fixed` 在被 zoom 的祖先里会跟着缩放、偏移；`FileViewerModal` / `ImageLightbox`
  也是因此走 portal。菜单在 body 下，坐标就是 `clientX/clientY` 的视口坐标，与 zoom 无关。
- 视觉沿用 FilePanel 现有的：遮罩 `fixed inset-0 z-50`，卡片
  `min-w-40 rounded-lg border border-edge bg-card py-1 shadow-2xl`，条目 `px-3 py-1.5 text-xs`。
- 关闭：遮罩点击、Escape、点完条目自动关。遮罩自身 `onContextMenu` 阻止默认并关闭，
  免得右键连点弹出 WebView2 原生菜单。Escape 走 **capture 阶段 + `stopImmediatePropagation`**，
  这样菜单开着时按 Escape 只关菜单，不会顺带退出 FilePanel 的全屏预览或 modal。
- 出界夹取：`x = min(at.x, innerWidth - 180)`，`y = min(at.y, innerHeight - items.length * 34 - 16)`，
  再对 0 取下界。

### 2. 改动文件行（`ChangedFilesCard.tsx`）

`FileRow` 加一个 `onContextMenu` 透传，菜单项在卡片层用 `ChangedFile` 拼，路径一律用 `fullPath`：

| 菜单项 | 行为 | 条件 |
| --- | --- | --- |
| 查看改动 | 打开 `FileViewerModal`（= 左键） | 有 `lastDiff` |
| 查看全文 | 同上，无 diff 时的措辞 | 无 `lastDiff` |
| 用默认程序打开 | `openPath(fullPath)` | |
| 打开所在文件夹 | `openPath(fullPath, true)` | |
| 复制路径 | 剪贴板 + toast「路径已复制」 | |
| 添加到对话区 | `chatStore.addAttachments([fullPath])` | |

失败统一 `chatStore.pushToast(\`打开失败：…\`, "error")`，与 FilePanel 一致。

### 3. 侧边栏聊天条目（`Sidebar.tsx`）

删掉 `SessionMenu` 手写的下拉与 outside-click / Escape effect，改为 `SessionRowItem` 算一份
`MenuItem[]`，两个入口共用：行 `onContextMenu`（光标处）、「...」按钮 `openAtRect`（贴按钮）。

1. 重命名 → 现有 `onStartRename`（行内 input）
2. 打开项目文件夹 → `openPath(session.cwd, true)`（`SessionRow` 自带 `cwd`；目录 reveal = 直接在
   资源管理器里打开该目录）
3. 复制项目路径 → 剪贴板 + toast
4. 删除会话（`danger`，`session.pending` 时不出现）→ 保留 `window.confirm` 二次确认

细节：右键要 `stopPropagation`（别让父级 `ProjectRow` 一起吃）；行处于重命名编辑态时不弹菜单，
避免抢掉 input 的 blur 提交。「...」按钮的可见性由 `menu.at` 决定（菜单开着时常显，否则 hover 才出现），
和原来 `open` 状态的效果一致。

### 4. 文件面板（`FilePanel.tsx`）

删掉私有 `ContextMenu`，菜单项内容一字不改（打开文件 / 查看 diff / 打开所在位置|路径 /
添加到对话区 / 复制路径），改由共享组件渲染；`MenuState` 换成 `useContextMenu()` 的 `at` +
一个 `menuEntry`。「查看 diff」的可见条件（tracked 且非 untracked）从原来的 `onViewDiff` 参数
下沉成组件内的 `entryMenuItems(entry)`，行为不变，三处样式自然统一。
