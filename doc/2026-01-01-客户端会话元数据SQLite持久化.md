# 客户端会话元数据 SQLite 持久化

**日期**: 2026-01-01  
**影响范围**: `kalo-desktop/src-tauri/src/`（新增 `session_meta.rs`）、`kalo-desktop/src/lib/`（新增 `session-meta.ts`）、`kalo-desktop/src/lib/chat-store.ts`  
**动机**: 客户端当前的 UI 扩展数据（每轮成果物、上下文用量历史、UI 状态）存在运行时内存中，切换会话后丢失。引入 SQLite 持久化层，在不改变 harness session 文件（单一真相源）的前提下存储客户端专属数据。

---

## 架构决策

### 数据分层

```
~/.kalo/sessions/abc123.jsonl    ← harness 消息记录（真相源，只读）
~/.kalo/kalo-desktop.db          ← 客户端 SQLite（扩展数据，客户端管理）
```

SQLite 数据库存放在 `~/.kalo/kalo-desktop.db`，与 harness 数据目录并列。一个数据库服务所有会话，以 `session_path`（harness jsonl 的规范化路径）为外键。

### 设计约束

1. **harness 文件只读**：不修改 jsonl 格式，SQLite 是纯附加层。
2. **降级安全**：SQLite 不存在或读取失败时，降级为当前行为（纯内存），不报错不崩溃。
3. **async/non-blocking**：Rust 侧用 `tokio-rusqlite`（在 tokio 线程池里跑阻塞调用），前端写入走 `void` fire-and-forget，不阻塞对话流。
4. **幂等写入**：同一 `(session_path, turn_id)` 的数据重复写入做 UPSERT，不会重复。
5. **Schema 版本化**：`schema_version` 表记录当前版本，升级时按版本号依次执行 migration SQL。
6. **测试可测**：Rust 单测用 `:memory:` 数据库，前端逻辑（计算、聚合）提取到 `src/lib/session-meta.ts` 纯函数可单测。

## Schema

```sql
-- 版本控制
CREATE TABLE IF NOT EXISTS schema_version (
    version INTEGER PRIMARY KEY
);

-- 每轮成果物（files changed/created/deleted per turn）
CREATE TABLE IF NOT EXISTS turn_changes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_path TEXT NOT NULL,
    turn_id TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    file_path TEXT NOT NULL,
    action TEXT NOT NULL CHECK(action IN ('create', 'edit', 'delete')),
    lines_delta INTEGER,
    UNIQUE(session_path, turn_id, file_path)
);
CREATE INDEX IF NOT EXISTS idx_turn_changes_session ON turn_changes(session_path);

-- 上下文用量历史
CREATE TABLE IF NOT EXISTS context_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_path TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    tokens INTEGER,
    context_window INTEGER,
    percent REAL,
    trigger TEXT,  -- 'message_end' | 'agent_end' | 'compaction_end'
    UNIQUE(session_path, timestamp, trigger)
);
CREATE INDEX IF NOT EXISTS idx_context_history_session ON context_history(session_path);

-- UI 状态（每个会话一行，JSON 存储可扩展字段）
CREATE TABLE IF NOT EXISTS session_ui_state (
    session_path TEXT PRIMARY KEY,
    collapsed_entries TEXT NOT NULL DEFAULT '[]',  -- JSON array of entry ids
    pinned_messages TEXT NOT NULL DEFAULT '[]',    -- JSON array of entry ids
    notes TEXT NOT NULL DEFAULT '{}'               -- JSON object: entryId -> note text
);
```

初始 `schema_version` 为 `1`。

## 与 chat-store.ts 的集成点

### 读取时机（切换会话后）

`reloadLatestPage` 末尾调用 `loadSessionMeta(rt.view.sessionFile)`，将结果存入 `SessionRuntime.meta`：

```typescript
// SessionRuntime 新增字段
meta: SessionMetaPayload | null = null;
```

### 写入时机

| 事件 | 写入内容 |
|------|---------|
| `agent_settled` | `saveTurnChanges`（从 `runChanges` 转换） |
| `message_end` / `compaction_end` / `agent_end` | `saveContextSnapshot`（fire-and-forget） |
| 用户折叠/取消折叠工具调用 | `setUiState`（debounce 500ms） |
| 用户 pin/unpin 消息 | `setUiState` |

### ChangesEntry 持久化

`pushRunChanges` 当前只将 `ChangesEntry` 插入内存 timeline。集成后同步调用 `saveTurnChanges`，切换会话时从 `meta.changes` 恢复并重建 `ChangesEntry`。

## 兼容性与迁移

### 现有会话

首次启动新版本时：
- 检测 `~/.kalo/kalo-desktop.db` 不存在 → 自动创建并初始化 schema
- 历史会话的成果物和上下文历史**不做回填**（首次使用时开始记录）
- 降级安全：读取失败（DB 损坏/权限问题）时，`loadSessionMeta` 返回空数据，UI 降级为当前纯内存行为

### Schema 升级

未来新增表字段时：
1. 在 `session_meta.rs` 的 `migrate()` 中新增版本 2 的 SQL
2. `migrate()` 从 `schema_version` 读取当前版本，依次执行缺少的 migration
3. 用户更新后首次启动自动升级，无需手动操作

## 实现顺序

1. **Rust 基础层**：`session_meta.rs`（DB open + migrate + CRUD），配套 `#[cfg(test)] mod tests` 用 `:memory:` 覆盖建表/迁移/CRUD。
2. **Tauri 命令**：在 `main.rs` 注册命令，`AppState` 持有 `Arc<SessionMeta>`。
3. **前端纯逻辑**：`session-meta.ts`（类型定义 + 纯计算函数 + IPC 适配），配套单元测试（vitest，只测纯函数）。
4. **chat-store 集成**：读（`reloadLatestPage`）+ 写（`agent_settled`、`message_end`、`compaction_end`）。
5. **UI 状态回放**：切换会话时从 `meta.uiState.collapsedEntries` 恢复折叠状态；从 `meta.changes` 恢复 `ChangesEntry`。

本改动影响以下设计域：

- **数据流**：客户端新增 SQLite 持久化层，`SessionRuntime` 新增 `meta` 字段
