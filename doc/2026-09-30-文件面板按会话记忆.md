# 文件面板按会话记忆

日期：2026-09-30

## 问题

1. **收起面板 = 关掉打开的文件**：`App.tsx` 里 `{panelOpen && page === "chat" && <FilePanel />}`
   用条件渲染收起面板，`FilePanel` 一卸载，它自己的全部状态（打开的文件、目录树展开
   集合、浏览位置、diff 标签）就丢了。收起再展开，文件预览消失、树也缩回根目录 ——
   用户报的「收缩放开文件区，打开的文件就关闭了」。
2. **文件区不分会话**：即便不收起面板，切换会话时 `cwd` 变化会触发面板根变化，把
   预览、展开态一起清掉。文件区其实是「这个会话在看什么」，A 会话打开的文件不该被
   B 会话的浏览动作抹掉，回到 A 也应该还在。

## 方案

### 一、收起不再卸载（App.tsx / FilePanel.tsx）

聊天页常驻挂载文件面板，收起时只隐藏（`hidden` 类 = `display: none`），卸载只发生在
离开聊天页（设置/演化/笔记/专家/自动化）时。这样收起/展开连目录缓存、git 快照、
diff 行都不需要重取，用户看到的就是「原样的文件区」。

面板可见性（`panelOpen`）仍归窗口布局：它是「文件面板」这个开关本身，和侧边栏折叠
同类，按运行期记住即可，不按会话分。

### 二、会话级记忆（lib/file-panel-memory.ts）

把「属于这个会话的文件区状态」从组件 state 里挪到按会话分桶的记忆 store：

| 进记忆 | 说明 |
| --- | --- |
| `preview` / `previewTab` | 打开的文件与源码/diff 标签（核心诉求） |
| `rootOverride` / `backStack` | 用户手动浏览到的目录与后退栈 |
| `expanded` | 目录展开集合 |
| `changesOnly` / `artifactsOpen` | 「仅变更」与「产物」两处折叠状态 |
| `pendingArtifact` | `present_files` 活时声明的"待打开"交付物：只在本会话是当前会话时被面板消费一次，随即清空（后台会话跑出来的产物不弹到别的会话，见 [产物呈现通道](2026-09-28-产物呈现通道.md) § 自动打开） |

不进记忆的：目录列表、git 状态、diff 行数（可从磁盘/引擎重取）；右键菜单、路径输入
框草稿（临时态）；全屏（阅读模式的一次性动作，切会话/重挂载时退出全屏）；列宽
`treeW`/`previewW`（已有 localStorage，属窗口布局）。

`FilePanel` 不再是这些字段的来源，而是记忆的视图：渲染期用 `usePanelMemory(uid, cwd)`
取当前会话的记忆，交互时 `patch` 回去（`useSyncExternalStore`，版本号驱动重渲染）。

写入方不止面板自己：`present_files` 的活时自动打开由 `chat-store` 调
`queuePanelArtifactOpen(uid, cwd, item)` 写进**声明它的那个会话**的桶，面板只消费
"当前会话"的那一条（旧实现是全局事件总线，写的是当时正在看的会话 —— 后台会话的
产物会串到别的会话文件区）。

### 三、会话身份（chat-store 的 `sessionUid`）

记忆按「会话」分桶，需要一个在会话文件落盘前后都稳定的身份。`activeSessionKey` 不合
用：pi 在第一条 assistant 消息前不写会话文件，新对话先以池键 `fresh-N` 存在，文件落盘
后 chat-store 会把它重键到会话文件路径（`rekeyRuntime`）——同一个对话换了名字，记忆会
断在这里。

因此 `SessionRuntime` 增加 `uid`（构造时取 key，之后不再改），随快照发布为
`ChatState.sessionUid`。它对一个对话实例稳定：新对话从 `fresh-N` 到落盘后的会话文件
路径，`uid` 不变；恢复一个已有会话时 `uid` 即会话文件路径。

再补一层别名（`adoptPanelMemory`）：会话文件落盘后，把记忆从 `fresh-N` 键换到会话文件
键，之后读写都走文件键。原因是引擎池有 LRU 驱逐（`MAX_PARKED`），同一运行内被驱逐的
会话再从侧边栏打开时是新建的运行时，`uid` 已经是会话文件路径 —— 没有这层别名，那次
打开就会看到空白的文件区。别名只由面板在同一份快照里看到「本会话的 uid + 它自己的
会话文件」时登记，不是靠渲染时序猜出来的。

注意 `chat-store.ts` 已超 800 行预算（只许缩），所以本次先把 `readTodos`/`latestTodos`
两个纯函数移入 `chat-store-helpers.ts`，再加这个字段，行数不越基线。

### 四、换根时展开态作废

记忆里记的不是「当前根」而是「这份展开集合属于哪个根」（`root` 基线 = 当时的
`rootOverride ?? cwd`）。取记忆时若基线对不上（会话 cwd 被改过、记忆来自别的根），
展开集合作废、其余照常恢复：

- 用户切工作目录后，旧根的目录路径不该继续展开（那些路径可能已不在树里）。
- 浏览到别处（`navigate`）由面板自己清展开集合并写入新基线，后退栈保留 —— 后退栈
  里是绝对目录，换根后依然可用。
- 打开的文件不因换根关闭：那正是「打开的文件不该自己关掉」的初衷。

## 边界

- **不跨应用重启**：记忆是内存态，与草稿、附件等会话态一致；重启后文件区从空白开始。
- 不按会话记忆面板的显隐，也不记忆全屏。
- 会话删除后记忆条目不回收：条目只有几个字符串，量级为 KB，不做淘汰。
- 引擎驱逐后再打开同一会话：靠上面那层别名接上（本运行内）；崩溃自动恢复沿用同一个
  运行时不换 uid，也不受影响。
