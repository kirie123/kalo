# 定时任务可用性与功能回归

## 已发现的问题

定时 agent 的引擎使用长驻 RPC：执行期间发送 `agent_end`，重试和后台续写全部结束后发送 `agent_settled`，进程不会自动退出。仅在 `session_exit` 结算会使任务永久显示运行中，阻止后续调度。手动运行仍走冷却判断、运行中编辑重建防重入状态、错误在持久化后才写入输出，以及启动确认过早，也会造成界面与真实执行不一致。

初始回归：桌面纯逻辑 729 项与 Rust 101 项通过；网关 147 项中，Windows 停止后台命令的用例超时，需要定位进程终止原因。

## 调度与完成

- 每次 agent 启动生成独立的关联标识，以既有 `session_request.taskId` 字符串字段传递。任务定义 ID 保持不变，返回的启动成功/失败必须匹配该次关联标识，过期确认不能影响新运行。
- 调度器在 `agent_end` 记录最后 assistant 消息，收到 `agent_settled` 才结算，重试和后台续写不提前结算；最后 assistant 消息的 error/aborted 状态记为失败。结算完成后请求关闭该次无人值守会话，进程退出不能重复覆盖已完成结果。
- 增加 gateway → Rust 的 `session_close { sessionId }`，仅允许关闭 `source=gateway` 的会话。桌面会话不受影响。启动探测、模型设置或 prompt 发送失败必须回报并清理无人值守进程。
- 运行中修改任务保留运行锁和执行记录；删除后旧回调不能更新重建的同 ID 任务。暂停只停止未来调度。
- 手动运行忽略启用开关和冷却，但运行中的任务返回明确错误，禁止重叠。

## 保存与操作反馈

- 计划表的新增、修改、删除先持久化，成功后再发布状态。失败应返回操作错误，不允许界面显示成功。
- 调度写操作增加可选 `requestId`，网关返回 `schedule_reply { requestId, ok, error? }`；Rust 复用已有请求等待器，10 秒超时，前端既有 Promise 只有收到确认后才成功。
- 编辑任务保留专家身份与执行历史，前端不把旧快照当成运行结果的权威来源。
- watch 启动失败、超时与 stderr 异常先设置输出，再持久化和广播。工作目录无效时失败，不静默换到网关目录执行。干净的无输出检查继续保持静默。
- 最终回复按会话归属路由：聊天走原聊天通道，定时任务走全文分段推送；不把桌面会话的回复发到飞书。修复定时任务被交给只接受聊天会话的处理器、正文因此静默丢失的问题。该行为只做本地注入传输测试，不发送真实消息。

## 平台和校验

Windows 使用系统目录中的 taskkill 终止受控子进程树；macOS 使用独立进程组。系统差异集中在进程适配层，定时器与后台任务复用。回归脚本只使用隔离临时目录与本机命令，不发送飞书消息，不调用真实模型，不修改用户任务表。

修复根目录检查脚本在 Windows 无法启动无扩展名 npm shim 的问题；通过 Node 执行包提供的 JS CLI，避免 shell 拼接和 `.cmd` 差异。补上网关改动的类型和测试路由，发布全检查同时覆盖网关。

验证包括桌面纯逻辑、网关调度与任务生命周期、Rust 测试、类型和生产构建；实际 UI 与原生窗口行为另行记录验证范围，不将单测等同于完整人工验收。

## 验证结果与边界

- `npm run check -- --with-tests` 通过：桌面 729 项、网关 159 项、Rust 101 项，共 989 项；类型、行数与桥接检查通过。
- `node scripts/smoke-gateway.mjs` 通过。用重建后的宿主平台网关二进制再运行相同脚本也通过，覆盖 NDJSON 校验/确认、落盘、冷却内手动重跑、删除和 RPC 完成后的释放。
- Vite 生产构建、Rust 桌面可执行文件编译、宿主平台网关 sidecar 重建通过。构建输出和临时数据不入库。
- Windows 的复现中 taskkill 返回拒绝访问，原实现只检查进程创建是否抛异常、未检查退出码；适配层现已监听失败并回退直接终止受控主进程。受系统权限限制时，不能把主进程终止等同于确认所有后代都已终止；macOS 仍使用独立进程组终止。
- 没有调用真实模型、发送飞书消息或修改用户任务表。真实服务鉴权、模型回复质量、macOS 原生运行与完整桌面 UI 操作不在此次自动化验收结论内。
