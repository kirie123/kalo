# edit 匹配失败诊断增强

日期：2026-09-21
范围：`kalo-harness/packages/coding-agent`（`edit` 工具的失败报错）
触发背景：同一会话里 `edit` 以 `Could not find edits[0] ...` 连续失败 3 次，模型据此判断「中文文件不能 edit」，改用 `write` 全量重写。

## 1. 现象与根因

### 事故样本（会话 JSONL，2026-09-17）

目标文件 `router_agent.py`（CRLF），`edits[0].oldText` 第 9 行是：

```
挂在 /internal/rooms/{room_id}/... 下，不进 openapi。n
```

而文件实际内容是 `...不进 openapi。`。用码点核对：`0x3002`（。）后面紧跟 `0x6e`（`n`）再 `0x0a`——`oldText` 里多了一个孤立的 `n`，精确匹配失败；模糊归一化（NFKC、行尾空白、智能引号、破折号、特殊空格）都不涉及这个字符，救不回来。

另外两次失败（同一会话，行 531 / 2957）漂移点各不相同：

- `from app.mission.background import spawn_replan` 明明存在，但同一次调用里的其他字段对不上；
- `\texports_at: string;\n}\n\n/**` 缺少或多余空白。

→ 不是网关改写转义，也不是中文/CRLF 的问题，是**模型重建 `oldText` 时的自然字符漂移**。

### 现有行为

`edit-diff.ts` 的匹配管线是「精确 `indexOf` → `fuzzyFindText`」。CRLF、行尾空白、全角引号、破折号、特殊空格都已有容错（`normalizeForFuzzyMatch` 会 `trimEnd` 每行，所以 `\r` 自动被裁掉）。真正失败时只抛一句：

```
Could not find edits[0] in <path>. The oldText must match exactly including all whitespace and newlines.
```

没有任何「差在哪」的信息。模型拿不到定位线索，就自己编解释（「中文文件不能 edit」）并退化成 `write` 全量重写——代价大、还有丢内容风险。

## 2. 目标与非目标

目标：

- 匹配失败时报错附带：最近匹配区域（行号 + 相似度）、首个差异行（文件行 vs oldText 行）、差异性质（多/少尾部字符）、下一步建议；
- 保留既有报错前缀与既有容错行为，不改任何成功路径。

非目标：

- 不自动纠错、不自动改写 `oldText`；
- 不改前两级（`exact` / `fuzzy`）的匹配语义；后续新增的容错阶梯见 `doc/2026-09-21-edit-匹配容错增强.md`；
- 不动 `packages/agent/src/harness/tools/edit-diff.ts` 这份副本（见 §6）。

## 3. 方案

### 3.1 新模块 `edit-diff-diagnostics.ts`

`normalizeForFuzzyMatch` 从 `edit-diff.ts` 移入新模块（`edit-diff.ts` 改为 import 并 re-export，导出面不变），新模块不反向依赖 `edit-diff.ts`，避免循环引用。

```ts
export interface ClosestMatchDifference {
  line: number;                  // 1-based，首个不一致行的文件行号
  fileLine: string | undefined;  // 该位置的文件行；文件已到结尾时为 undefined
  oldTextLine: string;           // oldText 对应行
  extraInOldText?: string;       // 文件行是 oldText 行的前缀时：oldText 多出来的尾部字符
  extraInFile?: string;          // 反过来
}

export interface ClosestMatchDiagnostic {
  startLine: number;             // 1-based，最近窗口起止行
  endLine: number;
  similarity: number;            // 0..1
  oldTextLines: number;
  difference?: ClosestMatchDifference;
}

export function describeClosestMatch(content: string, oldText: string): ClosestMatchDiagnostic | undefined;
export function formatClosestMatchDiagnostic(diagnostic: ClosestMatchDiagnostic): string;
```

### 3.2 算法

- **行相似度**：两侧行先做 `normalizeForFuzzyMatch`；相等 → 1；否则 `(公共前缀长 + 公共后缀长) / max(长度)`。
- **窗口相似度**：`oldText` 各行与文件窗口逐行相似度的均值；文件缺行计 0。
- **候选窗口**：
  - 文件行数 ≤ 1000 且 `oldText` 行数 ≤ 200：全量扫描所有起点（小文件，保证结果最优）；
  - 否则锚点法：取 `oldText` 最长的 3 个非空行，在文件里找行相似度最高的若干行，反推窗口起点并做 ±2 漂移，候选数封顶。
- **首个差异行**：窗口内第一个归一化后不相等的行；某一侧是另一侧的前缀时判定为「尾部多字符」，把多出来的字符拼进提示。
- **行切分**：丢弃末尾因换行产生的空字符串，行号按编辑器所见（1-based）。

### 3.3 报错文案

前缀原样保留，诊断追加在后：

```
Could not find edits[0] in router_agent.py. The oldText must match exactly including all whitespace and newlines.
Closest match: lines 10-12 (99% similar).
  line 12 file   : `挂在 /internal/rooms/{room_id}/... 下，不进 openapi。`
  line 12 oldText: `挂在 /internal/rooms/{room_id}/... 下，不进 openapi。n`
The oldText line has 1 extra trailing character that is not in the file: "n".
Re-read the file with the read tool, then retry with text copied verbatim from the file.
```

约定：

- 单行窗口写 `Closest match: line 12 (99% similar).`，多行写 `lines 10-12`；
- 相似度四舍五入到百分比；
- 差异行内容用反引号包裹；超过 160 字符截断为「头 96 字符 + … + 尾 60 字符」；
- 相似度 < 0.5 时把末句换成 `No closely matching region was found. Verify the path and re-read the file before retrying.`；
- 差异行在文件末尾之外时，`file` 侧显示 `(end of file)`。

### 3.4 集成点

`applyEditsToNormalizedContent` 改为按策略阶梯遍历（见 `doc/2026-09-21-edit-匹配容错增强.md`）；全部级别都未命中时，把最后一个未命中的 `edit.oldText` 与原始内容传给扩展后的 `getNotFoundError(path, editIndex, totalEdits, content, oldText)`，诊断文本由 `formatClosestMatchDiagnostic` 生成。`computeEditsDiff` 预览路径复用同一函数，自动获得同样信息。

## 4. 兼容性

- 前缀不变：`Could not find the exact text in <path>.` / `Could not find edits[i] in <path>.` 原样保留（现有测试断言 `/Could not find/`、`/Could not find the exact text/`）。
- 只在抛错路径追加文本，成功路径零变化；空 `oldText`、重复匹配、越界等既有报错不变。
- 诊断函数不抛异常（纯字符串运算 + 空输入返回 `undefined`），不会把可恢复的 edit 失败变成崩溃。

## 5. 测试计划

新增 `packages/coding-agent/test/edit-diff-not-found-diagnostics.test.ts`：

- 真实事故样本回归：`oldText` 带孤立 `n` → 报出正确行号、差异行两侧内容、`extraInOldText === "n"`；
- 单 edit / 多 edit 报错前缀 + 诊断段落同时存在；
- 多行 `oldText` 中第 N 行漂移 → `difference.line` 精确；
- 无相近内容（完全不相关文本）→ 相似度低、末句降级为验证路径提示；
- 文件行数少于 `oldText` → `fileLine` 为 `undefined`；
- 长行截断；
- 回归：智能引号/行尾空白/CRLF 的容错成功路径不受影响。

## 6. 影响

- 模型可诊断性提升；`write` 全量重写的退化场景预期减少；
- 渲染层无需改动（TUI 与桌面端直接透传 tool result 文本）；
- `packages/agent/src/harness/tools/edit-diff.ts` 是另一份副本，本次不镜像；若该副本也需要同样诊断，后续按同一算法移植。
