# Widget 卡片主题适配与导出菜单

## 背景

`show_widget` 工具产出的内联可视化组件（图表/示意图/交互卡片）在时间线里以
`WidgetCard` 渲染，内容跑在一个 `srcdoc` 沙箱 iframe（`WidgetSandboxFrame`）里。

引擎侧 `show-widget` 扩展的设计系统（`getCoreDesignSystem`）明确要求组件
**只用宿主注入的 `--cb-*` CSS 变量取色**：

```
--cb-panel-bg-primary   页面/iframe 背景
--cb-text-primary       正文文字
--cb-text-secondary     次要/暗淡文字
--cb-border-default     边框
--cb-accent-primary     主强调色
```

## 问题

沙箱 iframe 从来没有定义这五个变量。于是组件里 `color: var(--cb-text-primary)`
之类的声明全部落到浏览器默认值（近黑），在暗色主题下文字与深色背景几乎同色，
看不见（见 6.png：折线图的图例、轴标签在暗色下发灰发黑）。

同时卡片头部只有展开/收起，没有导出入口——用户想把图表存成图片或复制源码没有通道。

## 方案

### 1. 主题变量注入 + 实时切换

`WidgetSandboxFrame` 用 `THEME_TOKEN_MAP` 把宿主的语义 token 映射到引擎的
`--cb-*` 变量：

| 引擎 `--cb-*`            | 宿主 token   |
| ----------------------- | ------------ |
| `--cb-panel-bg-primary` | `--bg-card`  |
| `--cb-text-primary`     | `--text`     |
| `--cb-text-secondary`   | `--text-dim` |
| `--cb-border-default`   | `--border`   |
| `--cb-accent-primary`   | `--accent`   |

- `resolveThemeVars()` 用 `getComputedStyle(document.documentElement)` 读出宿主
  当前值（亮/暗由 `.dark` class 决定），组装成 `--cb-*` 映射。
- 挂载时把快照写进沙箱 `<style id="cb-theme">`，作为 `srcdoc` 的一部分。
- 宿主切换主题（`<html>` 的 `class` 变化）时，`MutationObserver` 触发一次
  `widget:theme` postMessage，沙箱只改写 `#cb-theme` 的 `textContent`，
  不重渲染组件——图表实例、canvas 不受影响。

映射是唯一真源：引擎新增 `--cb-*` 变量时，在 `THEME_TOKEN_MAP` 补一行即可，
不要在沙箱 CSS 里写死颜色。

### 2. 卡片右上角「更多操作」菜单

`WidgetHeader` 在展开/收起 chevron 左侧加一个 `⋯` 按钮，点击用现成的
`ContextMenu`（`useContextMenu().openAtRect`）弹出：

- **另存为…** — 把 `widget_code` 原样写盘（HTML 或 SVG，按 `render_mode`）。
- **保存为图片** — 仅 HTML 组件（SVG 组件本身即矢量，无需光栅化），把当前
  渲染截成 PNG 存盘。
- **复制代码** — `navigator.clipboard.writeText(widget_code)`。

菜单项走 `save()`（`@tauri-apps/plugin-dialog`）选路径，结果用
`chatStore.pushToast` 反馈成功/失败，错误对用户可见且可操作。

### 3. PNG 截图链路

浏览器无法直接把 iframe 的渲染截图，方案是在沙箱内部自截：

1. 卡片调 `frameRef.current.capture()` → 通过 `useImperativeHandle` 暴露的
   Promise，向沙箱 post `widget:capture`（带 `reqId`）。
2. 沙箱 `captureToPng` 把 `#root` 克隆一份，把每个 `<canvas>` 替换成它的
   `toDataURL()` 快照 `<img>`（`foreignObject` 不会渲染实时 canvas），
   连同页面内 `<style>` 一起塞进一个 SVG `foreignObject`。
3. 把 SVG 画到离屏 `<canvas>`（按 `devicePixelRatio` 上采样，上限 2x），
   先用 `--cb-panel-bg-primary` 填底再 `drawImage`，最后 `toDataURL('image/png')`。
4. 结果经 `widget:capture:result` 回传，宿主 4 秒超时兜底（resolve null）。

CSP 里 `img-src` 已含 `data:`，SVG data URL 图片能加载。跨域 CDN 图片会污染
canvas 导致 `toDataURL` 抛错，已 try/catch 并回传 error，不崩卡片。

### 4. 新增桥接命令 `writeFileBytes`（契约变更）

PNG 是二进制，`writeFileText` 不适用。新增：

- 前端 `pi-bridge.ts`：`writeFileBytes(path, base64)` → `invoke("write_file_bytes", …)`。
- Rust `files.rs`：`write_file_bytes(path, base64)` 解码 base64、按需建父目录、写盘；
  空路径或非法 base64 返回可读错误。命令在 `main.rs` 的 `invoke_handler` 注册。

路径处理与既有 `write_file_text` 一致，跨平台（Windows/macOS）走同一套 `PathBuf`
语义，无平台特化分支。

## 边界与非目标

- SVG 组件不提供「保存为图片」（源码已是矢量，用「另存为…」存 `.svg`）。
- 主题实时切换只换 `--cb-*` 变量值，不重新执行组件脚本；依赖脚本读取变量的
  组件（如运行时读 CSS 变量画 canvas 的图表）在切换后不会自动重绘，需用户
  折叠再展开——属已知取舍，非目标。

## 验证

- `kalo-desktop`：`node node_modules/typescript/bin/tsc --noEmit` 通过；
  `cargo test write_file_bytes` 两个用例通过（base64 解码建父目录、拒绝空路径/坏 base64）。
- 契约检查 `scripts/check-bridge-contract.mjs`：71 个命令全部 Rust 已注册。
- 人工：亮/暗主题各看一次折线图图例/轴标签可读；`⋯` 菜单三项分别存 HTML、
  存 PNG、复制代码。
