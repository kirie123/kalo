# 右栏文件页签（打开的文件各占一个页签）

日期：2026-10-10
状态：已实现
相关：`doc/2026-10-03-右栏页签面板.md`（本文改掉它的「常驻文件页签」）、
`doc/2026-09-30-文件面板按会话记忆.md`（文件区记忆的字段随之改名）、
`doc/2026-09-28-产物呈现通道.md`（自动打开改在右栏消费）

## 0. 背景与问题

右栏页签条里有一个常驻的「文件」页签：它不可关闭、内容 = 目录树 + 一个预览列。
它把所有「文件」这件事塞进一个页签里，于是 **打开的文件不是页签** —— 打开
DEPLOYMENT.md 之后，页签条上仍然只有「文件」两个字，真正的文件名藏在预览列的
一行标题里。用户的要求是：**页签条上没有「文件」页签，只有打开的文件各自的页签**。

## 1. 目标

1. 页签条 = 打开的**文件页签**（可多开，每个都是文件名）+ 浏览器 / 终端 / 跟随页签，
   页签左对齐，`+` 紧跟最后一个页签之后（无页签时在最左）。
2. 没有打开任何文件、也没有其它激活页签时，右栏 = 文件树占满整栏（即原「文件」页签
   去掉页签之后的形态）。
3. 文件页签激活时：左预览列 + 右文件树列（与今天的布局相同，树列宽度仍可拖）。
4. 浏览器 / 终端 / 跟随页签激活时占满整栏，文件树不显示（与今天切页签的行为一致）。
5. `+` 菜单只剩 **浏览器 / 终端**：打开文件的正路是在文件树里点。
6. 文件区状态继续**按会话记忆**：A 会话打开的文件不显示在 B 会话的页签条上，
   切回 A 仍然在。

## 2. 非目标

- 不做文件页签的拖拽排序、不做右键菜单（关闭其它/关闭右侧）。
- 不做「打开文件…」系统文件选择框（`+` 菜单不提供打开文件）。
- 不改引擎 / sidecar 契约，不需要重建 `pi-*.exe`。

## 3. 状态模型

页签分成两处存，各管各的「激活」：

| 位置 | 范围 | 内容 |
| --- | --- | --- |
| `lib/panel-tabs.ts` | 应用级（不随会话变） | 浏览器 / 终端 / 跟随页签；`activeId` 可为空串 = 没有激活的非文件页签 |
| `lib/file-panel-memory.ts` | 会话级（按 `sessionUid` 分桶） | `openFiles`（打开的文件的顺序与各自的 源码/diff）+ `activeFile`（激活的文件路径，null = 没有） |

两者答的是两个不同的问题：

- `panelTabs.activeId` 决定**谁占屏**：非空 = 某个浏览器/终端/跟随页签；空 = 文件侧。
- `activeFile` 是**文件侧内部**当前在看的文件（null = 没有，只看树）。
- 激活文件页签 = 设 `activeFile` 并把屏交回文件侧（`activeId = ""`）；激活应用级页签只设
  `activeId`，**不动 `activeFile`** —— 关掉那个页签回来还是原来那个文件（与文件页签
  出现之前的形态一致）。
- 「空态」（文件树铺满）就是 `activeId === "" && activeFile === null`。

由此会话切换是自然的：文件页签及其激活态跟会话记忆走，浏览器/终端/跟随页签留在
应用级（切会话不关终端，与今天一致）。

### 3.1 文件页签的数据

```ts
interface PanelFile {
  name: string;              // 页签标题
  path: string;              // 绝对路径，身份（去重按 pathKey）
  relPath: string | null;    // 相对仓库根，null = 不在仓库里（决定能不能看 diff）
  view: "source" | "diff";   // 这个文件页签自己在看什么
}
```

去重按 `pathKey()`（Windows 下大小写不敏感），重复打开只激活已存在的页签。

### 3.2 记忆里的新操作（纯函数，单测覆盖）

| 函数 | 语义 |
| --- | --- |
| `openFileInMemory(mem, file)` | 已打开则只更新 caller 给出的字段（`relPath` / `view`，省略的保持原值）并把焦点移到它（用存下来的路径写法）；否则追加到末尾。返回 `{ openFiles, activeFile }` |
| `closeFileInMemory(mem, path)` | 移除该页签；关的是激活页签时焦点先落**左邻**，没有左邻则落右邻（即补位的那一个），都没有才 null；关非激活页签不动焦点 |
| `setFileViewInMemory(mem, path, view)` | 改一个文件页签的 源码/diff |
| `activateFileInMemory(mem, path)` | 只改 `activeFile`（`null` = 回到树）；路径按大小写/分隔符不敏感匹配，写回页签自己的写法 |

`preview` / `previewTab` 两个字段被 `openFiles` / `activeFile` 取代；`pendingArtifact`、
`rootOverride`、`expanded`、`backStack`、`changesOnly`、`artifactsOpen` 不变。

## 4. 组件

- `components/RightPanel.tsx`：页签条渲染两段 —— 先 `mem.openFiles`（文件页签，文件图标 +
  文件名 + **×**），再 `panel.activeId`/`panel.tabs`（浏览器/终端/跟随，带 ×），
  然后 `+` 菜单（浏览器 / 终端），紧跟在页签之后。文件页签的 × 直接写会话记忆。
  **`pendingArtifact` 的消费搬到这里**：右栏常驻挂载，交付物不管当前激活的是哪个页签，
  都要能落地成「新建文件页签并激活」；原来在 `FilePanel` 里消费，浏览器页签激活时
  那个面板虽然还挂着但不再合适（它没有激活文件页签的权限）。
- `components/FilePanel.tsx`：仍是「文件区」这个整体（预览列 + 拖手 + 树列），但预览列
  渲染的是**当前激活文件页签**；没有激活文件时树列占满。树列自身（标题/路径栏/git 条/
  产物/树/右键菜单）不变。
- `components/FilePreviewPane.tsx`（新）：从 `FilePanel.tsx` 拆出的预览行 + 预览体
  （文件名 + 源码|diff + 全屏 + 关闭 + 正文），供 `FilePanel` 渲染激活文件用。拆出来是
  为了让 `FilePanel.tsx` 不越过 800 行的机器检查红线。
- 预览行**不改位置和内容**（用户要求文件名/源码|diff/全屏/关闭都留在这一行）；文件页签
  自己**也**带一个 ×（2026-10-10 追加：用户给了参考形态 `[图标 文件名 ×] [+]`，
  `+` 要贴着眼签），两处等价，都关这一个页签。

## 5. 打开与关闭的路径

| 入口 | 行为 |
| --- | --- |
| 树 / 变更列表 / 产物行点文件 | `openFileInMemory` + `panelTabs.activeId = ""`（激活该文件页签） |
| 预览里点文档内的链接 | 同上，并且保持全屏 |
| 预览行的 源码/diff | `setFileViewInMemory` |
| 预览行的 ✕ | `closeFileInMemory`（关的是激活页签时焦点落左邻）+ 退出全屏 |
| 页签条上文件页签的 × | `closeFileInMemory`；关非激活页签不动焦点，关掉最后一个时 `activeFile` 变 null（`FilePanel` 顺带退出全屏） |
| 页签条上点文件页签 | `activateFileInMemory` + `activeId = ""` |
| 页签条上点浏览器/终端/跟随 | `panelTabs.activate(id)`（不动 `activeFile`：关掉它回来还是那个文件） |
| 关闭最后一个文件页签 | `activeFile` 变 null → 右栏回到文件树 |
| `present_files` 活事件 | RightPanel 消费 `pendingArtifact` → 新建（或激活）该文件页签 |

## 6. 测试

- **vitest（纯逻辑）**：`lib/file-panel-memory.test.ts` 补 `openFileInMemory` /
  `closeFileInMemory`（含左邻焦点、大小写去重）/ `setFileViewInMemory` /
  `activateFileInMemory`；`lib/panel-tabs.test.ts` 改成新模型（没有文件页签、
  `activeId` 可为空、关闭激活页签落左邻）。
- **人工验证**：树里连开三个文件 → 三个页签；关中间一个 → 焦点落左邻；点页签上的 ×
  与点预览行的 ✕ 都能关；关最后一个 → 回到文件树；切到浏览器页签 → 树藏起来、页签内容
  占满；切会话 → 文件页签跟着换；切回来 → 原来的文件页签与激活态还在；`present_files`
  在新会话里自动开一个文件页签。

## 7. 已知限制

2026-10-24 更新：文件侧新增常驻的文件树按钮，浏览器或终端激活时也能返回文件区，不再需要关闭它们。文件预览标题行改为路径面包屑、内容/更改与操作菜单，保留全屏和关闭；具体布局及按会话记忆的 `treeVisible` 字段见 `2026-10-24-文件面板导航与筛选.md`。以下为初版限制，其中回到文件树的限制已解除。

- 页签条不持久化：重启后没有文件页签（回到文件树）。文件区记忆本来就是内存级。
- 文件页签的 × 与预览行的 ✕ 等价；多开时没有「关闭其它 / 关闭右侧」，只能一个个关。
- 打开文件的正路是文件树；`+` 菜单没有「文件」项，所以当浏览器/终端/跟随页签占满
  整栏时，回到文件树的办法是关闭它们（或在文件树里先开着文件页签）。
