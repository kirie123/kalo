# bash 后台模式：长跑命令交给 Job Runtime

日期：2026-09-24
状态：已落地（harness + 既有网关端点，无新增引擎协议）

## 0. 问题

bash 工具只有同步执行：命令要么在 timeout 内跑完，要么被强杀。长跑命令（训练、回测、构建、抓取）现在只能：

1. 模型自己拼 `nohup` / `Start-Process -WindowStyle Hidden` 启动，再 `sleep` 轮询、`tail` 日志——状态靠模型手写，跨 turn 就丢；
2. 用户手动开一个终端跑。

Job Runtime（P0-1）已经有"可看、可停、跑完主动通知、桌面任务面板可见"的完整能力，缺的只是让 bash 工具能把命令放进去。

## 1. 方案

bash 工具增加可选参数 `run_in_background`：

- 前台路径不动（本地 spawn + 流式输出 + 截断落盘），后台路径改为把命令交给网关的 Job Runtime 并立即返回 job id；
- 读取、停止、通知全部复用既有 `job_output` / `job_list` / `job_kill` 与完成通知（忙注入、闲唤醒），不新增 job 工具、不新增引擎协议。

不新增"启动任务"工具是刻意的：模型的动作是"跑一个命令，而这件事恰好在后台"，启动由生产方（bash 工具）触发；工具面里没有 `job_start` 就不会出现"起一个任意东西"的用法。

## 2. 执行路径

后台分支（`POST /jobs`，网关既有 HTTP 端点，127.0.0.1 + endpoint.json 里的 token）：

```
bash(command, run_in_background: true)
  → 复用前台同一套 spawn 上下文：commandPrefix 前缀 + PI_* 会话变量 + spawnHook 改写
  → POST /jobs { kind: "bash", label: 命令首行（截 120 字）, cwd, cmd, env }
     header x-kalo-session = 会话 id（owner 围栏）
  → 网关 startCommand：落盘 <id>.json、重定向日志到 ~/.kalo/agent/jobs/<id>.log、
    detached 启动（Windows breakaway，活过 gateway 重启与桌面退出）
  → 工具返回：[background] job bash-3 started: ...
      Call job_output("bash-3", wait=true) ...; you are notified when it finishes.
```

job id 前缀是 `kind`，所以后台命令是 `bash-1`、`bash-2`……桌面任务面板按既有 `job_status` 事件显示它们，无需改前端。

env 传递整份前台 spawn 环境（`getShellEnv()` 的 PATH + PI_* 会话变量），网关侧以 `{...process.env, ...job.env}` 合并——后台命令与前台命令看到同样的环境。

## 3. 与前台路径的差异（有意为之）

| 维度 | 前台 | 后台 |
|---|---|---|
| 超时 | `timeout` 可选 | 无超时，结束用 `job_kill`；`timeout` 与 `run_in_background` 同时给出直接报错 |
| 输出 | 流式回工具卡，超限截断 + 落临时文件 | 不回流；用 `job_output` 增量读取（单次上限 256KB），日志在 `~/.kalo/agent/jobs/<id>.log` |
| 进程归属 | 随会话/中止被杀 | 脱离进程组，活过 turn / 会话 / gateway 重启 |
| 依赖 | 无 | 需要 Kalo 网关；不可用时**直接报错**，不做静默本地降级 |

不做静默降级的理由：本地降级没有增量读取、完成通知、owner 围栏与面板可见性，等于第二套语义；真要做本地后端，应作为与 jobs-gateway 平行的 `jobs-local` 实现补进来，而不是藏在 bash 工具里。

自定义 `operations` 的 bash 工具（SSH、沙箱等远程执行）不开放后台模式：默认 starter 只会在本地起进程，命令跑在错误的主机上。此时 `run_in_background` 报"当前 bash 工具不支持后台模式"。

## 4. 围栏与生命周期

- owner = 会话 id（`x-kalo-session`）：本会话可见/可停；桌面操作员视图可见全部；别的会话看不到。
- 任务记录落盘 `~/.kalo/agent/jobs/`，与定时任务同域，gateway 重启后按落盘恢复。
- 完成通知走既有链路：忙时注入下一步，闲时唤醒（有界），不轮询。

## 5. 提示词

- 参数描述里写清用法、限制（不能配 timeout）、依赖（需要网关）；
- bash 工具的 `promptGuidelines` 增加一条：长跑命令用 `run_in_background` 启动，用 `job_output` 等待，不要 `sleep` 轮询。

## 6. 测试

- jobs client：`start()` 的 POST /jobs 形状、会话头、网关报错原样透出；
- 后台启动模块：命令 → label 截断、env 过滤、cwd 不存在与网关不可用的报错映射；
- bash 工具：后台分支调用 starter 并返回 job id、`timeout` 冲突报错、starter 失败原样上报、自定义 operations 时后台不可用。

## 7. 影响面

- 引擎侧（kalo-harness）：bash 工具 + kalo-jobs 扩展新增文件；需重建 sidecar（`scripts/build-engine.sh`）后才在桌面端生效。
- 桌面端：无代码改动；任务面板、`job_output` / `job_kill` 直接可用。
- 契约：无新增 NDJSON 命令，新增的只是 harness 对既有 `POST /jobs` 端点的使用。
