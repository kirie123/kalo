# edit 匹配容错增强（策略阶梯）

日期：2026-09-21
范围：`kalo-harness/packages/coding-agent`（`edit` 工具的 `oldText` 定位）
前置：`doc/2026-09-21-edit-匹配失败诊断.md`（失败时的诊断输出，已落地）

## 1. 背景

诊断解决「失败后能不能看懂」，容错解决「小漂移能不能不改就过」。当前匹配只有两级：精确 `indexOf` → `normalizeForFuzzyMatch`（NFKC、每行 `trimEnd`、智能引号、破折号、特殊空格；CRLF 在进匹配前已归一为 LF）。下面几类漂移仍然会失败：

- **缩进差异**：模型用 2 空格，文件是 4 空格或 tab（`trimEnd` 只去行尾，管不了行首）；
- **行内空白差异**：模型把 `a  =  b` 写成 `a = b`；
- **块级锚定**：多行 `oldText` 首尾行正确、中间一两行有出入。

这三类都能在不改变精确匹配语义的前提下补上：按「最小改写代价」排序，逐级放宽；只有全部 `edits[]` 都能在同一级落位才采用该级。

## 2. 目标与非目标

目标：

- 新增三级定位策略，覆盖缩进 / 行内空白 / 块锚点三类漂移；
- 每级都要保持 kalo 的既有契约：唯一匹配、非重叠、未命中时给出诊断、未触碰的行保持原字节；
- 精确匹配路径零变化；越是「激进」的策略，改写范围越受约束。

非目标：

- 不引入 `replace_all`（kalo 的契约是「每次调用要求唯一匹配」）；
- 不主动改写 `newText`（不剥离行尾空白、不做任何规范化，写了什么就写什么）；
- 不做混合行尾的逐段保留（kalo 统一归一到文件主导行尾再写回，现有语义不变）；
- 不修改 `packages/agent/src/harness/tools/edit-diff.ts` 副本。

## 3. 策略阶梯

按顺序尝试；每一级都把**文件内容与 `oldText` 做同一套归一化**，然后要求该次调用的每个 edit 都能在这一级落位（含唯一性检查）。全部 edit 落位的第一个级别即采用它，并在后续所有替换、重叠检查都使用该级别的归一化空间。

| 级别 | 归一化（逐行、保持行数） | 定位方式 | 适用漂移 |
|---|---|---|---|
| `exact` | 无 | 子串 `indexOf` | 完全一致 |
| `fuzzy` | NFKC、行尾 `trimEnd`、智能引号/破折号/特殊空格 → ASCII（现有行为） | 子串 `indexOf` | CRLF、行尾空白、全角引号、NBSP |
| `trimmed` | 在 `fuzzy` 基础上每行 `trim()`（去行首缩进 + 行尾空白） | **整行块**匹配 | 缩进用 2 空格 vs 4 空格 / tab |
| `whitespace` | 在 `trimmed` 基础上把行内连续 `[ \t]+` 折叠成单空格 | **整行块**匹配 | 行内空白排布差异 |
| `anchored` | 同 `trimmed` | 块锚点 + 中间 LCS 相似度 | 多行首尾正确、中间个别行不同 |

#### 为什么 `trimmed` / `whitespace` 必须是「整行块」匹配

这两级会改写匹配到的那几行：替换时被命中行块整体从归一化空间取回，只有 `newText` 是原样写入的。如果允许匹配「一行中的一段」，该行未被替换的部分会带上归一化的痕迹（比如行内双空格被折叠），等于偷偷改了用户没要求改的内容。限定整行块之后：

- 命中范围 = 若干完整行，块外内容与块内未覆盖部分都不会被归一化污染；
- `oldText` 不以换行结尾时，块尾换行不属于替换范围，语义与精确匹配一致。

现有 `fuzzy` 级别保持「可匹配行内片段」的历史行为，不变。

#### `anchored` 的护栏

- `oldText` 至少 3 行（2 行时首尾锚点就是全部内容，等价于 `trimmed`，无收益）；
- 首行、末行都非空（`trim` 后）才作为锚点；
- 候选 = 文件中同时满足「首行 trim 相等」与「末行 trim 相等」的行块；
- 中间部分用字符级 LCS 相似度 `2·LCS/(|a|+|b|)` 评分，候选数 > 1 时阈值 0.7，唯一候选时 0.5；
- 必须**恰好一个**候选通过阈值，否则视为歧义（报重复匹配）或未命中；LCS 长度超过 4000 字符直接退化为相等判断，避免 O(n·m) 卡顿。

## 4. 报错与反馈

- 全部级别都失败 → 沿用现有 not-found 报错 + 最近匹配诊断（诊断不受策略阶梯影响）；
- 某一级出现重复匹配（同一空间内出现多次）→ 沿用现有「Found N occurrences」报错；
- 命中级别不是 `exact` 时，成功消息追加 `(approximate match: <级别说明>)`，让模型知道这次不是逐字命中、应复核结果：
  - `fuzzy` → `whitespace-normalized`
  - `trimmed` → `indentation-insensitive`
  - `whitespace` → `whitespace-insensitive`
  - `anchored` → `block-anchor`

  精确命中不追加，现有 UI 文案与既有断言不受影响。

## 5. 实现落点

- 新模块 `src/core/tools/edit-match-strategies.ts`：策略定义、`trimmed` / `whitespace` 归一化、整行块定位、锚点定位 + LCS；
- `src/core/tools/edit-diff.ts`：`applyEditsToNormalizedContent` 改为按策略阶梯遍历（替代现有「精确 or 模糊」二选一），返回值增加 `matchedWith` 字段；`fuzzyFindText` 保留导出、行为不变；
- `src/core/tools/edit.ts`：成功消息按 `matchedWith` 追加说明；预览路径（`computeEditsDiff`）自然复用。

## 6. 兼容性与风险

- 精确匹配路径与现有模糊路径的结果不变（阶梯前两级就是现有两级）；
- 唯一性/重叠/诊断/行尾恢复等既有行为不变；
- 新策略可能匹配到模型没想改但文本恰好「归一化后相同」的区域——由「整行块 + 唯一性 + 逐级放宽」三重约束限制，且命中后会在成功消息里标出「approximate match」提醒复核。

## 7. 测试计划

新增 `packages/coding-agent/test/edit-match-tolerance.test.ts`：

- `trimmed`：文件 4 空格 / 模型 2 空格、tab vs 空格 → 成功且未触碰行保持原字节；
- `whitespace`：行内多空格 vs 单空格 → 成功；
- `anchored`：多行首尾一致、中间一行不同 → 成功；中间差异过大 → 仍未命中（带诊断）；
- 唯一性：同一空间出现两个候选 → 重复报错；
- 优先级：既存在精确命中又存在归一化命中 → 选精确；
- 安全边界：行内片段漂移（非整行）不被 `trimmed` / `whitespace` 匹配（保持精确/模糊的原有结果）；
- 成功消息：非精确命中带 `approximate match`，精确命中不带；
- 回归：现有 fuzzy 用例（引号 / NBSP / 多 edit / 保留未触碰行）全部保持通过。

## 8. 回放验证（真实失败样本）

2026-09-21 把同一会话里 3 次真实失败调用的参数对当前仓库状态重跑 `applyEditsToNormalizedContent`：

- 3 例全部仍判未命中，原因都不是缩进 / 行内空白 / 块锚点类漂移，而是**内容本身不同**（`return None` vs `return await ...`；`import spawn_replan` vs `import spawn_compile, spawn_replan`；`exports_at` vs `sha256`）。
- 阶梯拒绝它们是正确行为：例如 531 那例若按「行内片段近似」硬套，会把同行的 `spawn_compile` 一起改掉。
- 这印证了取向：阶梯只处理「归一化后等价」的漂移，真正的漂移交给诊断（见 `doc/2026-09-21-edit-匹配失败诊断.md`）与模型重读。
