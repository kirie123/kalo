# 运行中会话的侧边栏排位冻结

## 问题

侧边栏（项目下的会话列表 + 「聊天」历史列表）一律按会话文件的 `modifiedMs` 倒序排列。会话每写入一条消息，`list_sessions` 扫到的 mtime 就更新一次，于是：

- 同时跑着的两三个会话，每次有新消息就互相换位；
- 用户正盯着某个跑批的会话看进度，它会在列表里上下跳动，难以点中；
- `App.tsx` 里 pending 轮询（2s）与 run 起停都会触发重扫，跳动频率很高。

用户诉求：**正在运行的会话，排序暂时不要动。**

## 方案：跑起来的那一刻锁住排序键，跑完解锁

引入一张「冻结表」：`sessionKey -> 冻结时的排序键`。

- 一个会话从「非运行」变成「运行中」时，把它**当前的 `modifiedMs` 记进冻结表**；
- 只要它还在运行，排序一律用冻结值，忽略后续 mtime 增长；
- 运行结束（或该行从列表消失）时，把条目从冻结表移除，它立刻回到按真实 mtime 的正常位置（只跳这一次）。

效果：

- 运行中的会话在整场 run 里位置不动，多个运行中的会话彼此也不换位（各自冻结值固定）；
- 非运行会话照旧按最近修改排序，可以从运行中的会话旁边"绕过去"，这是预期行为；
- 不引入新的持久化：冻结表活在侧边栏的 ref 里，App 重启后自然按真实 mtime 排。

### 排序键与 key 的选择

- 排序键就是 `modifiedMs`（与现状一致），冻结只是把它替换成一个固定快照值。
- 冻结表的 key 用 `normPath(row.path)`（`\`→`/` + 小写），与 `runningByFile` 的 pool key 一致；乐观行（`pending:*`）的 path 本身就是它的 key，不需要特殊分支。
- 乐观行落盘后 path 会从 `pending:xxx` 变成真实 `.jsonl`：冻结表里的旧条目因为「行已消失」被清掉，新 path 若仍在运行则以当时的 mtime 重新冻结。新会话本来就在列表最顶，这次重新冻结不产生可见跳动。

## 实现

全部逻辑在 `kalo-desktop/src/lib/session-rows.ts`（纯函数，可单测）：

```ts
export type FreezeTable = Record<string, number>;

/** 增量更新冻结表：新跑起来的行入表，已停/消失的行出表。无变化时返回原对象。 */
export function updateFreeze(
  prev: FreezeTable,
  rows: SessionRow[],
  isRunning: (path: string) => boolean,
): FreezeTable;

/** 按（冻结键 ?? modifiedMs）倒序排列。 */
export function orderRows(rows: SessionRow[], freeze: FreezeTable): SessionRow[];
```

- `mergeSessionRows` 只负责合并 + 去重 + 默认倒序；排位冻结由 `orderRows` 单独一层套在外面。
- `updateFreeze` 在无变化时返回 `prev` 引用，避免侧边栏无谓重排。
- 排序稳定性：并列（同一冻结值/同一 mtime）时保持输入顺序，输入顺序来自 `mergeSessionRows` 的倒序结果，故不会随机抖动。

`Sidebar.tsx`：

```ts
const freezeRef = useRef<FreezeTable>({});
const merged = mergeSessionRows(sessionGroups, pendingSessions);
freezeRef.current = updateFreeze(freezeRef.current, merged, isRunning);
const allRows = orderRows(merged, freezeRef.current);
```

`updateFreeze` 对同一输入幂等，因此在 StrictMode 的双渲染下结果一致；ref 只作为跨渲染的派生缓存。

同时删掉 `looseSessions` 里那次多余的 `.sort((a, b) => b.modifiedMs - a.modifiedMs)`——它会把冻结顺序重新打回 mtime 顺序。项目行（`ProjectRow`）与「聊天」列表都直接吃 `allRows` 的顺序。

`visibleRows`/「显示更多」不变：运行中的行本来就在 `mustShow` 里，冻结不影响可见性。

## 测试（`session-rows.test.ts`）

- 运行中的会话 mtime 涨了也不上移；
- 运行结束后回到 mtime 应有的位置；
- 两个运行中的会话不互相换位；
- 非运行会话仍按 mtime 正常排；
- 冻结表无变化时 `updateFreeze` 返回同一引用；
- 行消失（会话被删）后冻结条目被清理，不泄漏。
