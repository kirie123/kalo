# 通用证券与分钟历史扩展

## 用户路径与界面结构

侧栏保留四个入口：总览、市场研究、策略实验、数据中心。市场研究内用局部页签切换行情、ETF 资金、两融；策略实验内切换代码策略、ETF 轮动。原有页面 ID 与工具结果定位保持有效，研究助手仍携带当前页、证券、冻结数据集和实际编辑代码。

```text
投行                 市场研究                     讨论此页
  总览               行情 / ETF 资金 / 两融
  市场研究           范围选择     数据快照
  策略实验           指标摘要
  数据中心           趋势与明细

策略实验             代码策略 / ETF 轮动
  新建实验           名称、冻结数据集、策略起点 → 创建并编写
  编辑草稿           代码编辑器                  运行回测
                     回测设置（按需展开）
  查看结果           收益曲线、指标              继续修改
                     实验记录（草稿和已完成报告）
```

两融的个券入口移入范围下拉，避免把某家公司作为永久页签。现存个券观察仍保留，名称明确为已同步证券。研究池与历史实验折叠收纳，避免导航无休止增长。

页签使用独立点击热区与内缩悬停底色：热区保持36px以上，悬停底色有横向留白与6px圆角，不触碰导航底部分隔线；选中态使用独立细线，不因悬停改变宽度或位置。键盘焦点保留可见描边，减弱动效设置下关闭过渡。投行图标沿用统一24px SVG网格、1.5px圆端线条，分别以四格总览、K线行情、实验瓶、数据库表达四个入口；助手、同步、折叠、关闭与下拉箭头同属该图标体系，替换文字字符图标。

## 数据契约

### 策略实验的创建与阅读流程

“新建实验”是明确的创建动作，打开独立创建页，不再只切到已有代码/报告页面。创建页选名称、已有冻结数据集及 KDJ/空白起点；同步其他证券收进按需展开区域。确认后生成独立草稿 ID，同一数据集可保存多个策略。取消返回实验记录。运行中禁用新建与继续修改，避免正在执行的结果与新草稿混淆。

编辑页优先展示代码，区间、现金、底仓、数量、费用与数据质量放进“回测设置”；只在实际返回成功报告后切到结果页，失败留在原草稿。结果页不显示同步表单或编辑器，只提供继续修改和实验记录。继续修改完整复制报告的代码、区间、资金与费用，生成新草稿，不覆盖原报告。报告数据集若已不在目录中，仍能阅读报告，但不能假借其他数据集继续回测。

草稿以 `kalo.investment.experiments.v1` 的版本化列表保存于本机 WebView 存储，包含独立 ID、更新时间与完整 ScriptSpec。旧版按数据集保存的草稿只读导入，保留旧键。解析或存储失败必须展示，不覆盖无法解析的原存储。实验记录分别列出草稿与已完成报告，数据集缺失的草稿保留并标明不可编辑。草稿 ID 只属于前端，不改变 Rust 回测或 Agent 工具契约。

助手上下文随创建、编辑、结果、记录视图分别更新；结果携带实际报告代码及参数，编辑携带当前草稿，不混入另一份实验。首次恢复旧任务定位不得覆盖用户已打开的新建页；后续 Agent 回测成功仍自动展示结果曲线。视图切换将内容滚回起点，保留右侧助手。Windows/macOS 共用 React 和 WebView 存储，不引入平台路径。

验收包括：新建不复用旧报告、同一数据集的两个草稿互不覆盖、取消保留原草稿、继续修改完整保留原参数、失败不退出编辑、实际 Rust 回测成功展示曲线、切页返回可继续编辑、原生小窗口/暗色/键盘焦点及裁切审计。

助手快捷动作按结构化 `page` / `mode` 选择，不再依赖标题文案：创建页讨论策略和同步所选数据；编辑页检查或运行当前草稿；报告页解读结果与检查实际策略。侧栏既有轮动历史明确命名为“ETF 轮动记录”，代码草稿与报告统一从代码页的“实验记录”进入。任务状态与活动通知共用已展示报告 ID，重复完成通知不再抢回用户刚切换的页面。

本次原生验收：贵州茅台5分钟策略故意使用无效代码，Rust 编译失败后编辑器与草稿仍保留；修正后成功生成80笔成交报告。继续修改复制全部回测参数，同数据集两份草稿独立，取消新建不产生草稿，切换市场研究后返回能恢复编辑。新建页同步159915的15分钟免费数据，122个完整交易日、1952根K线，同步后保持创建页；随后回测114笔成交并展示曲线，立即新建并等待下一次后台通知仍保持创建页。助手上下文核对到当前草稿ID、数据集、证券与周期；旧版草稿存储逐项比对未变。900宽暗色、下拉展开、设置展开、悬停和键盘焦点通过，投行区域审计 `cut=0, hidden=0`；全窗口两个既有边缘投影保持隐藏。仅Windows原生实测，macOS共用逻辑未原生复验。

提交检查：changed-aware TypeScript 校验与791项前端测试通过；新增纯逻辑回归覆盖同数据集多草稿互不覆盖、报告完整复制、无效存储拒绝覆盖。此次只改前端交互，无Rust或引擎协议改动。

`marketSync` 接收六位证券代码或带 SH/SZ/BJ 后缀的代码，周期支持 5m、15m、30m、60m。新增可选 `settlementDays`，仅 ETF 可指定 0 或 1；省略时保守采用 T+1，并在数据集中记录该假设。股票固定 T+1。腾讯证券报价用于核实代码、名称、证券类别和当前涨跌幅边界，不能把指数、债券、B 股误作 A 股。

分钟主源使用新浪最多 1970 根历史，成交量单位为股/份。腾讯原始及前复权日线用于交叉核验交易日、价格范围、收盘和公司行为。5 分钟通常约 40 个交易日，60 分钟通常约 490 个交易日；实际覆盖以返回数据为准，不承诺任意起始日。原始证据、供应商、采集时间、哈希随冻结数据集保存。

按证券与周期合并本地已有完整历史，只接受一致重叠区间；冲突不覆盖旧数据、不拼接不连续窗口。数据集保留公司行为日期，允许同步长历史，但尚未实现分红送转现金/持仓账务，回测不得跨越这些日期。默认区间从最后一次公司行为后重新预热 30 根开始，用户可选择更早且不跨公司行为的区间。不是把复权价格当成真实成交价。KDJ 在公司行为处重置，策略可见历史截断到最近公司行为之后，防止更早的价格跳变进入信号。

## 撮合与验证

普通股票和 ETF 的数量步长 100；科创板最少 200、其后步长 1；北交所最少 100、步长 1。股票价格步长 0.01，ETF 0.001。ETF 不计股票印花税和过户费；股票沿用现有税费。T+0 ETF 买入后增加可卖库存，T+1 买入只增加持仓。证券规则与周期冻结进数据集及报告。

涨跌幅采用同步时核实的规则；历史 ST、上市初期和规则变更无法仅凭当前报价还原，明确记录研究假设。公司行为、停牌或分钟缺口不允许填零、补价或默默删去内部交易日。时间必须为北京时间、完整交易时段；当日尚未冻结数据不进入回测。下一根开盘时间按周期计算，午休和跨日订单规则保持明确。

## 验收

长历史上下文只携带覆盖起止、交易日数、K线数与隔离日期，不附上几百个交易日数组。目录报告保留代码、参数、总数和费用摘要，不携带逐笔明细；任务完成摘要最多20笔订单并显式标记截断。完整明细仍保存在原生报告并分页展示，避免每次目录查询重复消耗大量模型上下文。

纯逻辑测试覆盖代码规范化、证券类型/数量规则、单位转换、不同周期时段、重复/缺口、历史合并冲突、公司行为范围门禁、ETF 税费与库存。原生桌面用股票和 ETF 分别同步、运行代码、检查报告及助手上下文；长区间报告采用分页明细，日期选择不渲染数千项下拉。

Windows 与 macOS 共用 Rust HTTP、数据模型和 React 控件；无新平台专属路径或进程逻辑。提交前执行 changed-aware 检查，保留原生截图与真实数据验证记录。
