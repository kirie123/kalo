# 子 Agent 卡片里的压缩气泡（activity feed 新增 compaction 条目）

日期：2026-09-18

## 背景

子 agent 是完整的 `AgentSession`，因此与主会话共享同一套自动压缩：每轮 LLM 调用前
（`prepareNextTurn`）与每轮结束后都会检查阈值，超了就压缩上下文
（见 `doc/2026-01-01-每轮LLM调用前检查压缩.md`）。本机 122 个子会话文件里 36 个带
compaction 条目，其中就有单个子 agent 中途压缩后继续跑到正常结束的实例。

但压缩对用户完全隐形：

- 主会话压缩会在对话流里留下一枚常驻气泡（`doc/2026-09-09-自动压缩气泡常驻与摘要展开.md`），
  它由主会话自己的 `compaction_start` / `compaction_end` 事件驱动。
- 子 agent 的压缩事件**到得了**扩展的订阅者（`AgentSession._emit` 发给所有 listener，
  现在的回调只拿它重置 idle 计时器），却不进 activity feed：`ChildActivity` 只有
  `text` / `tool` 两种，`details.activity` 里没有任何压缩痕迹。
- 桌面侧 `ToolCallGroup.tsx` 的 `AgentActivityItem` 同样只有这两种，没有可渲染的形态。

后果：一张跑了 261 步的子 agent 卡片，中途压缩过一次也不显示；用户看到的是一段
"没有断点"的活动流，上下文被换掉这件事无从判断。

## 目标与非目标

目标：

- 子 agent 每发生一次压缩，在它的活动流里留下一条时序正确的条目：运行中显示
  "正在压缩上下文…"，结束后定格为成功 / 失败 / 取消三态。
- 条目带上压缩前 token 数与摘要（截断），与主会话气泡的信息量对齐，可展开看摘要。
- 不改桌面与引擎之间的传输通道：沿用既有的 `details.activity`，只新增一种 kind。

非目标：

- 不改主会话的压缩气泡逻辑（`compaction-entries.ts` 与 `CompactionBubble.tsx` 不动）。
- 不往转录（`renderTranscript`）里写压缩行：转录是"本轮消息"的渲染，压缩是会话级
  基础设施事件，混进去会让每轮转录的语义变模糊；需要的用户可读会话文件或桌面卡片。
- 不做历史回放：活动流本来就只在工具调用记录里存活（重开会话后由工具结果的 details
  还原），压缩条目跟着同一条路径走，不额外持久化。
- 不给压缩条目做"点开摘要全文"之外的交互（无跳转、无时长统计）。

## 契约：`details.activity` 新增 compaction 条目

引擎侧类型（`kalo-harness/packages/coding-agent/src/extensions/subagent/activity.ts`——
与 `index.ts` 分离的纯模块，`index.ts` 从它导入类型与折叠函数）：

```ts
type ChildActivity =
  | { kind: "text"; text: string }
  | { kind: "tool"; toolCallId: string; name: string; label: string; status: "running" | "success" | "error" }
  | {
      kind: "compaction";
      /** 触发原因，与主会话气泡同一套语义。 */
      reason: "manual" | "threshold" | "overflow";
      status: "running" | "done" | "failed";
      /** 压缩前上下文 token 数（成功时有）。 */
      tokensBefore?: number;
      /** 摘要文本，截断到 MAX_ACTIVITY_TEXT_CHARS（成功时有）。 */
      summary?: string;
      /** 摘要是否被截断（true 时桌面显示"已截断"提示）。 */
      summaryTruncated?: boolean;
      /** 被取消时为 true。 */
      aborted?: boolean;
      /** 失败原因（失败时有）。 */
      errorMessage?: string;
    };
```

字段来源（子会话事件，`AgentSessionEvent`）：

| 事件 | 映射 |
| --- | --- |
| `compaction_start { reason }` | push 一条 `{ kind: "compaction", reason, status: "running" }`，随即 `emit()` |
| `compaction_end { result }` | 该条改 `status: "done"`，填 `tokensBefore: result.tokensBefore`、`summary`（截断） |
| `compaction_end { aborted: true }` | 该条改 `status: "failed"`、`aborted: true` |
| `compaction_end { errorMessage }` | 该条改 `status: "failed"`、`errorMessage` |

`compaction_end` 原地更新**最后一条 running 的 compaction 条目**；若它已被
`MAX_ACTIVITY_ITEMS` 裁剪掉（理论边界，压缩期间的条目增长）则退化为追加一条已结算条目。

摘要截断的理由：`details.activity` 每次 `emit()` 都整体复制并随工具更新推送，一份
未截断的摘要有 1 万字符量级（实测 14417），而 `emit()` 在每个消息 / 工具事件后都会跑，
这份体积会被重复搬运很多次。因此摘要进 feed 前截到 `MAX_ACTIVITY_TEXT_CHARS`（2000），
并用 `summaryTruncated` 标出来；要看全文的读者去读子会话文件或工具结果的转录路径。

桌面侧镜像（`kalo-desktop/src/lib/subagent-activity.ts`）——`AgentActivityItem` 增加同名字段，
仅保留渲染需要的部分；组件（`ToolCallGroup.tsx`）从该模块导入类型与文案映射。

## 引擎实现（kalo-harness）

1. 新建 `extensions/subagent/activity.ts`：`ChildActivity`（扩一种 kind）、
   `MAX_ACTIVITY_TEXT_CHARS` / `MAX_ACTIVITY_ITEMS`、`trimActivity()` 与折叠函数
   `applyCompactionActivity(activity: ChildActivity[], event: AgentSessionEvent): void`
   （事件类型直接 `import type` 自 `core/agent-session.ts`，避免类型漂移）。
2. `index.ts` 从该模块导入；`runTurn` 已有的 `session.subscribe` 回调里，对
   `compaction_start` / `compaction_end` 调用折叠函数并 `emit()`。
3. 裁剪统一走 `trimActivity()`：工具 push 与压缩 push 共用同一条路径，不新增计数。
4. 不动 `ChildOutcome` / `SubagentDetails` 的结构：活动流已经是 `details.activity` 的一部分。

## 桌面实现（kalo-desktop）

`ToolCallDetail` 里子 agent 的活动流目前是二选一渲染（`kind === "tool"` 否则按 markdown
文本渲染）。未知 kind 会被当成 text 渲染，所以必须显式加分支：

- `kind === "compaction"` → 一行虚线胶囊（视觉复用 `CompactionBubble` 的边框与字号），
  含状态图标（running 用 `spinner`，failed / aborted 用 `--danger`）与文案：
  - running：`正在压缩上下文…`
  - done：`上下文已自动压缩`（`reason === "manual"` 时为 `上下文已压缩`），右侧补
    `185k tokens` 一类的压缩前量级
  - failed：`上下文压缩失败：<errorMessage>` / `上下文压缩已取消`
- 有 `summary` 时点击胶囊向下展开摘要（截断提示"摘要已截断"），无摘要时不可点击。
- 条目位置保持活动流的时序：压缩发生在哪两个工具调用之间就显示在哪里。

文案映射同样是纯函数（`lib/subagent-activity.ts` 的 `compactionActivityView()`，返回
`{ label, meta? }`），组件只负责画：桌面组件的测试边界在 `src/lib/`，把映射留在组件里
就测不到（见 `kalo-desktop/AGENTS.md`）。

纯展示改动，无新命令、无新 Rust 代码（`session_paging.rs` 不解析 `details`，整包透传）。

## 验证

- 单测（harness）：`packages/coding-agent/test/kalo-subagent-compaction-activity.test.ts`
  直接喂 `compaction_start` / `compaction_end`（成功、aborted、errorMessage 三种）事件，
  断言条目字段与原地更新；再断言超长摘要被截断且 `summaryTruncated` 为 true。
- 单测（桌面）：`kalo-desktop/src/lib/subagent-activity.test.ts` 覆盖三态文案与
  `tokensBefore` 缺席时的 `meta` 处理（`npm test`）。
- 人工验证（桌面）：派一个会压缩的长任务子 agent，卡片活动流里应依次出现
  "正在压缩上下文…" → "上下文已自动压缩 · <tokens>"；点击可展开摘要。
- 回归面：`details.activity` 的消费方只有 `ToolCallGroup.tsx`，旧会话的历史条目没有
  compaction kind，渲染分支需保持向后兼容（缺省什么都不显示）。
