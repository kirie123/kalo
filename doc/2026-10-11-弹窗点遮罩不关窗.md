# 表单弹窗：点遮罩不关窗（2026-10-11）

## 问题

配置类弹窗（自定义 Provider、新建项目、定时任务、Skill、记忆、MCP 服务器）此前都是这一行写法：

```tsx
<div className="fixed inset-0 z-40 flex items-center justify-center bg-black/50" onClick={() => onClose(false)}>
```

点弹窗外的半透明遮罩即关闭。表单越长，这个「顺手」的出口越像陷阱：用户两次反馈「点中间面板之外，
配置模型的面板就消失」，第一次丢的是填了一半的 provider 配置（Base URL / API Key / 模型列表）。

## 根因：click 的目标不是「最后点到的元素」

`click` 事件的目标是**鼠标按下与抬起两个目标的最近公共祖先**。所以在表单里拖选文字、拖「模型列表」
文本框右下角的缩放把手（`resize-y`）时，只要抬手落在弹窗外，事件目标就成了遮罩，弹窗被当成
「点了空白处」关掉。这不是手抖，是浏览器的事件语义——用 `onClick` 判定「是否点了遮罩」从根上不可靠。

## 方案

新增 `kalo-desktop/src/lib/modal-backdrop.ts`，一条规则覆盖所有表单弹窗：

```tsx
const backdrop = usePinnedBackdrop("点「取消」或「保存」关闭这个窗口");
...
<div className="fixed inset-0 z-40 flex items-center justify-center bg-black/50" {...backdrop}>
```

- **遮罩不关窗**：出口只留「取消」/「保存」（新建项目是「确定」），就在右下角，只多一次点击。
- 判定改用 `onMouseDown`（`isBackdropPress`：主键 + `target === currentTarget`），不再依赖 click 的
  祖先语义，拖拽误触天然不命中。
- 首次误点弹一条 toast 说明怎么关（`usePinnedBackdrop` 内的 ref 保证每次打开只说一次）。不提示的话，
  点击像石沉大海，用户会以为界面卡死。
- `isBackdropPress` 是纯函数，`src/lib/modal-backdrop.test.ts` 覆盖三种分支：主键按在遮罩本身上、
  按在弹窗内的控件上、右键/中键。

**为什么不做「表单未改动才允许点遮罩关闭」的脏检查**：判定「这次点击算不算点了遮罩」本身就被上面那条
事件语义污染；而且同一个动作在「关」与「不关」之间摇摆，用户无法预判。「关不关只由两个按钮决定」
才是可预测的规则。实测过一版脏检查，用户复验仍然认为「很容易消失」。

**哪些弹窗不套这条规则**：查看类弹窗（文件预览、图片灯箱、Agent 地图）没有输入可丢，点空白关闭是
期望行为，保持原样。

## 验证

- `npm test` → `src/lib/modal-backdrop.test.ts`。
- 人工：打开任一表单弹窗 →
  在输入框里拖选文字、抬手到弹窗外：不关；
  点遮罩：不关，且首次提示一次「点「取消」或「保存」关闭这个窗口」；
  点「取消」/「保存」：正常关闭。
- 注意：跑的是**已安装的发行包**时看不到改动，需 dev（`npm run tauri dev`）或重新出包，
  见 `troubleshooting/edited-ui-not-visible-installed-vs-dev.md`。
