# 子 Agent 活动面板（输入框里的「N 个子 agent」+ Agent map 弹窗）

日期：2026-09-30

效果图：`doc/mockups/2026-09-30-agent-map.html`（可切换「有子 agent / 空态」与
「显示弹窗 / 只看输入框」两种视图）。

## 背景

子 agent 现在只以「对话流里的一张工具卡片」存在：卡片上有一行任务摘要、一个步数
胶囊，点开能看实时活动流（`doc/2026-09-18-子agent压缩气泡.md`）。一轮里并行派 4~6 个
子 agent（`DEFAULT_MAX_CONCURRENCY = 6`）时，用户想知道"现在到底有几个在跑、各自在
干什么、谁卡住了"，只能把对话往回翻，在连续的 `toolGroup` 里一个个找。

Claude Code 把这件事收敛成一个常驻控件：输入框左下的 `● N agents` 按钮，点开是
一张 Agent map（主会话 + 子 agent 树状连线，点节点看细节）。本次把这套形态搬到
Kalo 桌面端，占用输入框里「逐条插话」下拉的位置——那个下拉只有一个入口，却与
"排队消息怎么送进当前轮"强相关，更适合待在输入队列面板里（见下文迁移）。

## 目标与非目标

目标：

- 输入框工具栏常驻一个 `● N 个子 agent` 按钮（绿点 = 有在跑的），不看对话也知道
  当前会话派了多少个子 agent。
- 点击开一张居中弹窗：左侧主会话、右侧子 agent 列表，连线表示"由主会话派生"；
  点一个子 agent 展开它的任务提示词、实时活动流、转录文件路径。
- 同一子 agent 被 `resume` 多次时合并成一个节点（累计步数/token，标注续写次数），
  而不是按调用次数重复。
- 「逐条插话 / 一次全送」开关迁到输入队列面板头部。

非目标：

- 不新增引擎事件、不新增 RPC 命令：数据全部从现有的 `agent` 工具调用记录里派生
  （见"数据来源"），因此不需要重建 sidecar。
- 不在弹窗里做操作（停止/续写/删除子 agent）：弹窗是只读视图，操作仍走对话。
- 不做历史会话之外的持久化：切到历史会话时按会话文件重建的 timeline 一样能算出来，
  但"运行时长"这类只存在于内存的信息不显示（见下）。
- 不改对话流里的子 agent 卡片（`ToolCallGroup` 的外观不变，只是把活动流的渲染抽成
  共用组件）。

## 数据来源：从工具调用记录派生（契约不变）

子 agent 的全部事实都在 `agent` 工具调用的记录里（`ToolCallRecord`）：

| 位置 | 字段 | 用途 |
| --- | --- | --- |
| `args.description` | 任务摘要 | 节点标题（缺省时退到 `args.prompt` 首行，复用 `tool-labels.rowLabel` 的逻辑） |
| `args.prompt` | 完整任务描述 | 展开后的"任务"段 |
| `args.tools` | 子 agent 工具集 | 展开后的一行元信息 |
| `args.resume` | 续写目标子 agent id | 与上一次调用合并的 key |
| `partialResult.details.steps` / `.tokens` / `.activity` | 运行中的步数 / token / 活动流 | 运行中节点的实时数据（引擎每次 `emit()` 整体推送） |
| `result.details.childId` | 子 agent id | 节点身份的主体（但 id 会跨引擎重启重号，见下） |
| `result.details.turns` / `.tokens` / `.activity` | 结算后的步数 / token / 活动流 | 已结束节点的数据 |
| `result.details.failed` / `.stalled` / `.aborted` | 结束原因 | 状态映射 |
| `result.details.transcriptPath` | 过程转录 md | 展开后的路径（可复制） |

节点 key 按调用自己的自述分配（`assignKey`），**不能只看 childId**：

| 调用 | key |
| --- | --- |
| 新建（无 `args.resume` 且 `details.resumed !== true`），已拿到 childId | `childId`；该 id 已被本会话的新建调用用过则 `childId#N` |
| 续写（`args.resume` 或 `details.resumed === true`） | 并入"最近的同名 id 节点"；没有则用该 id |
| 新建且仍在运行（还没有 childId） | `toolCallId` 占位 |

为什么要按次数编号：引擎的子 agent id 是**进程内自增**的（`children.ts` 的
`nextChildId()`），一次会话跨引擎重启（关掉再打开、离开再回来）后 id 会从 1 重新
计数。实测 `~/.kalo/agent/sessions/--D--opensource-project-cowith--/2026-09-17T…jsonl`
一个会话文件里 `subagent-1` 出现 3 次、`resumed` 全是 false、任务各不相同——只看
childId 会把三个不同子 agent 并成一个节点（标题/token 都错）。续写并入"最近的同 id
节点"是因为引擎自己也是这样认的（`findChildSessionFile` 对同名文件取最新）。

运行中的新子 agent 用 `toolCallId` 占位是安全的：它的 id 还没交到模型手里，任何
`resume` 都指不到它；结果落地时 key 换成 `childId(#N)`，所以弹窗的展开态按 `key`
与 `toolCallId` 两者之一匹配（见下）。

历史会话由会话文件重建 timeline（`buildTimeline`），`args` 与 `result.details` 一样
齐全，因此历史会话的 Agent map 与实时一致；只有 `partialResult` 不存在（那些调用
已有终态）。

状态映射（按优先级）：

| 记录特征 | 节点状态 | 文案 |
| --- | --- | --- |
| `status === "running"` | `running` | 运行中 |
| `details.failed` | `failed` | 失败：<失败原因> |
| `details.stalled` | `stalled` | 卡死中止 |
| `details.aborted` | `aborted` | 已中止 |
| `status === "error"`（无 details，主轮被中止） | `failed` | 失败 |
| 其余 `success` | `done` | 已完成 |

步数与 token 取"最近一次调用"的值：运行中用 `partialResult.details.steps/tokens`，
结束后用 `result.details.turns/tokens`（引擎按子会话全历史累计，天然包含续写前的量）。
最近一次调用还没来得及推送任何数据时（引擎重启、`resume` 刚发出）沿用上一次的值，不
在展示上凭空清零。不显示运行时长：桌面端没有可靠的开始时间戳（`buildTimeline` 只
还原消息，不含条目时间），宁可不显示也不显示一个"实时与历史不一致"的数字；步数是
等价的进度信号。

## 桌面实现（kalo-desktop）

### 纯逻辑：`src/lib/subagent-map.ts`

- `collectSubagents(timeline: TimelineEntry[]): SubagentNode[]`：扫 `toolGroup` 里
  `toolName === "agent"` 的调用，按上面的 key 规则折叠、状态映射、取最近一次的活动流。
- `summarizeSubagents(nodes): { total: number; running: number }`：按钮只要这两个数。
- `sameSubagentNodes(a, b): boolean`：节点列表的浅比较，给 `useChatSelector` 当比较器
  （活动流按引用比，见下）。
- `agentStatusView(node)`：状态 → 文案/色调的纯映射（组件只负责画）。
- `agentActivitySummary(node)`：活动流最后一条 → "正在做什么"一行。

`SubagentNode` 字段：`key / id? / title / prompt / tools? / status / steps? / tokens? /
calls / activity? / errorMessage? / transcriptPath? / toolCallId`。

### 渲染性能

输入框挂在全局 store 上，流式期间每 ~50ms 一次 commit（`queueTimelineFlush`）。因此：

- 按钮用标量选择器 `{ total, running }`，只有数量变化才重渲染输入框。
- 弹窗用 `collectSubagents` + `sameSubagentNodes` 比较器：无关的流式增量不会重渲染
  弹窗；子 agent 自己的 `activity` 数组是引擎每次 `emit()` 新建的（timeline 里按引用
  持有），引用变化即触发一次重渲染，所以展开的活动流仍然是实时的。

### 组件

- `src/components/AgentMapModal.tsx`：`createPortal` 到 body 的居中弹窗（视觉与
  `FileViewerModal` 一致：`bg-black/50` + `rounded-xl border-edge bg-card`，
  Esc / 点遮罩关闭）。结构：
  - 头部：标题「子 Agent」+ 一行汇总（`3 个子 agent · 1 个运行中`）+ 关闭按钮。
  - 主体：左列主会话节点（会话名 + 模型 + 上下文用量），右列子 agent 节点列表，
    左列与右列之间用 `border-l + 横向短线` 画出派生连线。
  - 子 agent 节点：状态标（运行中 spinner，已完成 ✓，失败 ✗，卡死/中止橙色 `!`）+ 标题 +
    元信息（`第 N 步 · 124.8K tokens`、`续写 N 次`）+ 最后一条活动。点击原地展开：任务
    提示词、工具集、id、转录路径（可复制）、实时活动流（`AgentActivityFeed`）。展开态按
    `key` 与 `toolCallId` 两者之一匹配：运行中的新子 agent 在结果落地时 key 会从
    `toolCallId` 换成 `childId(#N)`，只认 key 会在结算那一瞬把面板收拢。
  - 空态：`本会话还没有派生子 agent` + 一句"模型用 agent 工具派生后会出现在这里"。
- `src/components/AgentActivityFeed.tsx`：从 `ToolCallGroup.tsx` 抽出的活动流渲染
  （text / tool / compaction 三类条目，含压缩胶囊），对话卡片与弹窗共用，行为不变。
- `src/components/InputBox.tsx`：工具栏的 `SteeringChip` 换成 `AgentChip`
  （`● N 个子 agent`，绿点脉冲表示有在跑的；点击开弹窗）。`SteeringChip` 迁出本文件。

### 插话模式迁到输入队列

新增 `src/components/SteeringPicker.tsx`（原 `SteeringChip` 的代码与视觉，含"一次全送"
的橙色警示态），挂到 `InputQueue` 头部行右侧：

```
[图标] 排队中 3 条 · 本轮结束后依次发送              逐条插话 ▾
```

理由：这个开关只在"有排队消息"时才有意义，放在队列面板里也是它作用的对象旁边；
输入框工具栏那一格腾出来给子 agent 按钮。会话级的 `steeringMode` 状态与
`set_steering_mode` 命令都不动，队列为空时面板不渲染（沿用现有行为），此时改模式
本来也没有影响。

## 验证

- 单测（`src/lib/subagent-map.test.ts`）：
  - 运行中的 `agent` 调用（只有 `partialResult`）→ `running`，步数/token 取自 `partial`，
    key = toolCallId。
  - 已结束 + 两次 `resume`（`args.resume` / `details.childId`）→ 折叠成 1 个节点，
    `calls = 3`，token 取最近一次结果。
  - 同一 id 被不同子 agent 复用时（引擎重启）→ 不合并，key 依次为 `subagent-1` /
    `subagent-1#2` / `subagent-1#3`；续写并入最近的那个。
  - `details.failed` / `.stalled` / `.aborted`、以及 `status: "error"` 无 details →
    对应的四种状态。
  - `summarizeSubagents` 的 total / running。
  - `sameSubagentNodes`：同值不同引用判等、状态或活动流引用变化判不等。
- 人工验证（桌面）：
  - 派 3 个子 agent（一条消息里多个 `agent` 调用）→ 输入框按钮显示 `● 3 个子 agent`
    且绿点脉冲；点开弹窗能看到三个节点在实时前进，展开能看见工具调用流。
  - 结束一个 → 节点变"已完成"，绿点在全部结束后转为静止灰点。
  - `resume` 一个已结束的子 agent → 节点合并（不是新增一行），`续写 1 次`。
  - 切到历史会话 → 按钮与弹窗仍能列出该会话的子 agent（无活动流时显示任务与步数）。
  - 排队两条消息时，队列头部的插话开关可切换且引擎生效（消息一次性送进当前轮）。
- 回归面：`ToolCallGroup` 的子 agent 卡片渲染必须与改动前一致（活动流抽成组件，
  三类条目 + 压缩胶囊逐项对照）；输入队列空时不渲染头部（原行为）。
