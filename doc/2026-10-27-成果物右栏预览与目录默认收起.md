# 成果物右栏预览与目录默认收起

## 交互方案

- 对话中的独立产物卡与改动汇总卡共用 `ArtifactList`。点击本地成果物的文件行或图片缩略图，将文件交给当前会话的右栏文件区，在文件页签中显示内容，不再打开文件弹窗。
- 文件按既有路径身份规则去重；重复点击激活已有页签，并切回内容预览，避免已打开的 diff 页签遮住成果正文。保留其他文件、浏览器和终端页签。
- 右栏已收起时，点击成果物主动展开右栏；正在显示浏览器或终端时切回文件区。实时成果物的自动打开也主动显示右栏，后台会话的成果物继续等待所属会话被选中，历史回放不触发自动打开。
- 启动时右栏默认收起，不自动占用聊天空间。各会话的文件树默认收起，首次预览只显示文件内容。用户手动展开的文件树仍按会话记忆，后续打开成果物不强制覆盖选择。
- 用户可通过顶栏按钮手动打开右栏；没有激活文件时继续显示文件树，保证目录浏览入口可达。阅读时通过页签条的文件树按钮展开或收起目录。
- 缺失成果物保持禁用；URL 条目沿用既有打开方式。右键菜单与改动文件的 diff 弹窗保持现有语义。正文 Markdown 图片继续使用大图预览；只有成果物缩略图使用右栏文件预览。

## 数据流与边界

- 手动点击复用 `queuePanelArtifactOpen`，使用点击时当前会话的 `sessionUid` 和 `cwd`。`RightPanel` 消费待打开文件，调用 `openFileInMemory` 并明确指定 `source`，消费后清空待打开项。
- `panel-tabs` 提供显示文件区的操作，一次设置 `open: true` 与 `activeId: ""`，不更改已有应用级页签。手动点击与实时自动打开共用此操作，避免仅切换焦点却仍然隐藏右栏。
- `initialPanelState.open` 改为 `false`，会话文件记忆的 `treeVisible` 初值改为 `false`；不持久化新的配置，不改变已有宽度、目录导航或文件读取机制。
- Windows 与 macOS 共用前端路由，原样传递成果物绝对路径，继续使用现有路径身份与文件预览适配；不新增文件系统或进程逻辑，不修改 IPC、引擎契约或内置 skill 安装行为。

- 纯逻辑检查覆盖：默认收起状态、从隐藏的浏览器/终端状态显示文件区且保留页签、按会话记忆目录选择、文件页签去重与内容视图切换。
