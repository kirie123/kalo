# 装完即可用：市场数据运行环境与自带的每日拉取

2026-08-20

四个市场 skill（`market-data` / `macro-pulse` / `filing-digest` / `stock-checkup`）在
8/20 上午已经写完并在开发机跑通，但**只在开发机跑通**。这次补的是"从零装一份 Kalo
的人拿到的是什么"，与 skill 的内容无关，全是环境与接线。

## 原来的三个断点

1. **`~/.kalo/market/venv` 没有任何代码会去创建它。** 它是当时手工用 uv 建的。
   `internal_skills.rs` 会把 `.py` / `.yaml` / `requirements.txt` 递归装进
   `~/.kalo/skills/`，但**解释器不在 skill 目录里**（akshare + pandas 约 178 MB，不
   该跟着 markdown 复制），所以新机器上 `md.py` 一行都跑不了。三份 SKILL.md 里写死
   的 `~/.kalo/market/venv/Scripts/python.exe` 在那台机器上是一条不存在的路径，而且
   Windows-only。
2. **`schedules.json` 初始为空。** "每天自动落盘攒历史"要用户自己去设置页手建任务；
   而 `daily.jsonl` 攒不起来，`macro analyze` 的分位数永远是"样本不足"。
3. **`watch` 任务靠 `spawn("bash")`。** 干净的 Windows 机器上直接进
   `child.on("error")`。

## 做法

### 一条稳定入口：`~/.kalo/market/py`

所有调用方（模型读的 SKILL.md、scheduler 的 watch 任务、用户的终端）一律：

```bash
~/.kalo/market/py ~/.kalo/skills/market-data/md.py macro now
```

它是 `market_env.rs` 在每次启动时写出的 bash shim。解析顺序：
`$KALO_MARKET_PYTHON` → `market/venv` → `.python-path` 缓存 → 现探（uv / `python3` /
`py -0p` / conda / 官方安装器常见位置）→ 都没有就 stderr 打一句「怎么修」并 `exit 1`。

三个刻意的选择：

- **解析写在 bash 里而不是 Rust 里。** 这样 Kalo 没在跑的时候（cron、终端、别的工具）
  同样有效，而且每次调用都重新解析——五分钟前刚建好的 venv 立刻生效，没有缓存要失效。
- **"可用"的判据是把候选跑起来问它自己**（`sys.version_info >= (3,10)` 且
  `releaselevel == "final"`），不是看目录名。这台开发机上的 `Python310` 目录里躺的是
  `3.10.0a5`，pip 在它上面自己会崩。
- **Rust 不重新实现这套搜索，而是执行 shim。** 设置页显示的东西与定时任务真正拿到的
  东西因此不可能不一致。

写入纪律沿用 `internal_skills.rs`：`.shim.json` 记指纹，用户改过就不覆盖。

uv 那条要查两次（先问 `uv` 二进制，再直接翻它的 python 目录），因为这台机器就是反例：
uv 装的 3.12 好好躺在 `AppData/Roaming/uv/python` 下，但 `uv` 自己已经不在 PATH 上，
只问二进制会宣布"没有 Python"。

### 一键初始化：`market-data/setup.sh`

跟 skill 一起装过去，所以设置页、模型、用户手工都能调同一份。没有可用 Python 时用 uv
现拉一份（**运行时按需装，不打包进安装包**）。依赖安装是三段回退链：`uv pip` → venv 自带
pip → `ensurepip` → 装 uv 再用 `uv pip`。第二段是实测倒逼的：`uv venv` 建出来的 venv
**故意不带 pip**，第一版脚本在这台机器上就死在 `No module named pip`。

`--mirror` 传 `UV_DEFAULT_INDEX` / `PIP_INDEX_URL`——era 那张卡片已经证明国内网络必须
留这个口。收尾跑 `md.py doctor` 并 `echo "== 完成"`，这行是与调用方约定的成功标记。

### `md.py doctor`

不联网的自检表：解释器与版本、五个依赖能不能 import、`daily.jsonl` 行数与 cache 文件
数、`sources.yaml` 条数。配套改的是 `md.py` 的导入结构——`lib.store` 之外的导入放进
`try`，任何命令在依赖缺失时给的是两行可执行的提示而不是 traceback：

```
环境未就绪：ModuleNotFoundError: No module named 'akshare'
先跑自检看缺什么：md.py doctor
```

### 设置页卡片

设置 → Skills 顶部一张卡（`MarketEnvCard.tsx`）：状态行（就绪/未就绪 + 解释器 + 走的
哪条路）、依赖逐项 ✓/✗、一键初始化（流式日志）、重新自检。安装走的是 era 那套「安装也
只是一个普通后台 job」：`jobStart` 跑脚本，`readTextSince` 追日志，`/^== 完成$/m` 判
成功。没有新的进程管理机制。

文案里明确写了「**四个市场 Skill 本身已经装好了，缺的只是跑它们的 Python 环境**」——
不然用户看到"未就绪"会以为 skill 没装上。

### 自带那条每日落盘任务

`scheduler.seedDefaults()` 在首次启动写入（守卫条件是 **`schedules.json` 不存在**，不是
"表为空"——用户删掉这条任务之后不该在下次启动被塞回来）：

```
宏观快照每日落盘   12 17 * * 1-5   watch
"$HOME/.kalo/market/py" "$HOME/.kalo/skills/market-data/md.py" macro append
matchMode: nonEmpty   cooldownMin: 1440   enabled: true
```

`kind: "watch"` 是零 token 契约的关键：`agent` 任务每个工作日会拉一个 headless 会话。
`macro append` 正常静默 = watch 不告警 = 不花 token。

环境未就绪时 shim 走 stderr + exit 1，`runWatch` 的 `err.trim() && !out` 分支推一条明确
失败——**宁可可见地失败，不要静默地什么都不攒**。顺带修了一处：原来只有 alerted 分支
更新 `rt.lastAlertAt`，error 与超时分支不更新，所以 `cooldownMin` 对错误告警完全无效，
一个每次都失败的 5 分钟任务能一天推 288 条一模一样的飞书消息。

### `resolveBash()`

两个 Windows 坑，都是这次实测撞出来的：

1. PATH 上的 `bash` 常常是 WSL 的 `System32\bash.exe`，它看到的文件系统跟脚本里写的
   路径不是一回事。
2. `Git\bin\bash.exe`（44 KB）是个 wrapper，它再去拉 `Git\usr\bin\bash.exe`（1.9 MB）。
   多一层进程会让 `child.kill()` 只杀到 wrapper，而且那层进程会占住 detached job 的
   cwd——`jobs.test.ts` 的 owner fencing 用例因此 `rmSync` EBUSY 挂了一次。

所以顺序是：`$KALO_BASH`/`$BASH` → PATH 上非 System32 的 `bash.exe` →
`Git\usr\bin\bash.exe` → `Git\bin\bash.exe`。gateway（scheduler + jobs 两处 spawn）与
Rust 各有一份，注释里互相指名——两个进程互相调不到，而不一致意味着卡片探测用的 shell
和定时任务真正用的 shell 不是同一个。

## "自带"到不了哪里

选定的前提是「只找系统 Python，不打包解释器」+「akshare / pandas 保持必需」，合起来就
意味着**目标机器上必须有一个可用的 Python（或让脚本用 uv 拉一份），第一次要联网装一次
约 178 MB 依赖**。安装包体积因此没变（57.3 MB）。

那 178 MB 里 akshare + pandas + numpy 占了约 170 MB，只为 19 条源里的 1 条（两融余额）
服务。留着它是这次明确保留的决定：以后加 A 股结构化数据的源都会用到，现在拆掉等于把
下一条源的成本提前付掉。

## 顺手清掉的一处

`collect_files` 原来只跳过 dotfile，于是 `market-data/lib/__pycache__/*.pyc` 跟着进了
安装包和 `.internal-skills.json` 记账——开发机上某个解释器编的字节码，装到永远不会用
它的机器上。现在 `__pycache__` 与 `*.pyc` 一并跳过。
