# 粘贴附件与 KALO_HOME

## 行为

- 单次粘贴的纯文本 `text.length >= 6000` 时生成 UTF-8 的「粘贴文本.txt」附件；长度按 JavaScript UTF-16 单位计算，不累计输入框已有文字，不 trim、不改换行。短文本仍由 textarea 原生插入。当前输入框没有富文本模型，不生成 Markdown。
- 有文件时优先处理文件，不重复插入剪贴板伴随的文字。剪贴板图片保存到 `KALO_HOME/attachments/<UUID>/<文件名>`，同时保留图片预览与现有模型 images 输入。
- 已有本地普通文件/目录优先引用原绝对路径，不复制。Tauri WebView 不提供 Electron 文件路径 API，因此使用窄平台适配读取原生文件剪贴板；仅有字节的 File 才保存副本。识别为内联图片的粘贴保存副本；选择和拖入图片沿用原路径。
- 字节附件最大 32 MiB，超限报错；图片内联上限沿用 10 MiB。超过内联上限的图片作为普通文件引用：剪贴板提供原路径时引用原文件，仅提供字节时保存副本后引用。
- 附件摄取期间禁止发送，展示处理中状态。异步结果绑定发起时的会话，切换会话不得把附件加到新会话。失败显示错误；长文本落盘失败保留可重试的原文本，不能静默丢失。
- 每次保存使用 UUID v4 子目录，净化文件名并防止路径穿越、Windows 保留名和重名覆盖。继续保留已保存文件，不做按年龄删除，保证历史消息和输入队列中的路径有效。

## 数据根契约

- `KALO_HOME` 表示完整数据根（例如用户选择目录下的 `.kalo`），不是其父目录。未设置/空值时默认 `USERPROFILE` 回退 `HOME` 下的 `.kalo`。
- 显式路径必须是绝对路径；非法相对路径报错，不静默回落到默认目录。启动后不热切换目录。
- Rust 使用独立 `kalo_home` 模块；引擎、网关使用各自窄适配入口。桌面端给引擎、网关及终端传递解析后的绝对 `KALO_HOME`。用户数据、配置、技能安装、历史、记忆、知识、附件和任务发现都从该根派生。
- 工作区内的 `.kalo/skills`、专家定义内的 `.kalo/memory` 属于项目数据，不随全局根改变；操作系统 home、配置目录与用户 PATH 语义不改变。
- 内置脚本读取 `KALO_HOME` 并保留默认目录行为。已有 agent-dir 专用覆盖沿用原有优先级。
- 设置页提供完整目录迁移，启动定位、复制校验、旧路径兼容和失败恢复遵循[数据目录迁移](2026-10-30-数据目录迁移.md)。桌面端优先使用设置保存的位置，再读取外部环境变量；对子进程统一传递解析后的 `KALO_HOME`。

## 桥接

- 沿用 `save_attachment_bytes {name,dataBase64}` 返回文件路径，目录改为 UUID。图片也经过该命令保存，前端补充 `sourcePath`，仍沿用 images 协议。
- 新增 `clipboard_file_paths {}` → `string[]`，Windows 读取 CF_HDROP，macOS 读取 NSPasteboard 文件 URL；无文件返回空数组。仅在用户粘贴文件时读取，不轮询剪贴板。
- `read_attachment` 接受目录并返回路径引用；不遍历、不上传目录内容。
- `app_paths.kaloRoot` 返回解析后的数据根。sidecar NDJSON 协议不变，新增进程环境契约 `KALO_HOME`。
