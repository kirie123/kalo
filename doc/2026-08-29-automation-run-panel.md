# 自动化页两栏布局：设置左移 + 定时任务运行状态栏

日期：2026-08-29
状态：已实施（2026-08-29）

## 需求

自动化页（定时任务 + 数据源）目前单列居中，宽屏下两侧大片空白；任务行上只有
「已告警 / 错误」一个标签，用户看不到**哪个任务正在跑、上次跑出了什么**——
「已告警」到底告警了什么内容，只能去飞书翻。

改动两件：

1. 布局改两栏：左栏设置（任务表 + 数据源），右栏「运行状态」。
2. 右栏逐任务显示：运行中标记、上次结果与含义、**最近一次输出**（告警正文/错误摘要）、
   下次触发；agent 任务的进行中会话也能对上号。

## 契约变化（gateway → 桌面端）

`schedule-status` 快照（`ScheduleTaskInfo`）加两个字段，**纯增量，旧前端忽略即可**：

```jsonc
{
  // ...原有字段
  "running": false,          // 本次是否正在执行（watch 脚本在跑 / agent 会话活着）
  "lastOutput": "…"          // 最近一次告警正文或错误摘要（≤1500 字符，与推送同源）
}
```

- `running` 来自调度器的 `RuntimeState.running`（重入保护同一个标记），不进
  `schedules.json`——它是运行时状态，进程重启后天然为 false。
- `lastOutput` 进 `schedules.json`（与 `lastRun`/`lastResult` 同级）：重启后用户仍能
  看到「上次告警是什么」。与飞书推送同一份文本，截断规则一致
  （`MAX_ALERT_OUTPUT = 1500`）。
- watch 正常静默（ok）时清空 `lastOutput`——ok 的语义就是「没东西可说」，留着旧告警
  正文会误导。

## 布局

```
┌──────────────────────────┬────────────────────┐
│ 定时任务（设置列表）       │ 运行状态            │
│ 数据源                    │ · 任务当前/上次运行  │
│                          │ · 进行中会话         │
└──────────────────────────┴────────────────────┘
```

左栏 `max-w-2xl` 取消居中改为靠左（`px-6`），右栏固定 `w-80`、独立滚动。
窄于 `lg` 时右栏隐藏（与顶栏跑马灯同一取舍：信息不挤爆设置区）。

## 右栏内容

纯读聚合，数据源全部是现有的：`schedule_list` 快照 + `jobs_list` 的 running 会话。

- 每任务一张小卡：名称、状态点（运行中/已告警/错误/正常，配色复用现有
  `--ok/--warn/--danger`）、上次运行时刻、下次触发；有 `lastOutput` 时折叠展示正文。
- 「进行中」区块：`jobs_list` 里 `source === "gateway"` 的会话（即定时任务拉起的
  无头会话），按 `expertId`/cwd 标注归属。
- 会话行显示**真实会话标题**：`jobs_list` 的运行中会话按 id 关联 `list_sessions`
  的 `SessionMeta.title`（`lib/expert-view.ts` 的 `sessionTitles` + `expertDetail`），
  没有标题时回退到「定时/桌面 会话」。数字专家面板的「进行中」区块同用这套关联。
- 状态文案即含义：「已告警 = watch 脚本有输出，已推送；正文见下方」——把
  「告警是什么」直接印在界面上，不再靠猜。

轮询与事件：沿用 `schedule-status` 推送 + `jobs_list` 10s 轮询（与数字专家面板同策略）。
`running` 翻转时调度器主动 `onChange()` 广播，不等 tick。

纯逻辑（状态点文案/配色映射、会话归属标注、时间格式化）收进
`src/lib/task-run-view.ts` 并配 vitest；组件只渲染。

## 不做

- 不在右栏做操作（停止任务等）——运行控制仍在 Jobs 中心与任务行的按钮。
- 不做历史输出列表，只留「最近一次」。
- 不动 watch 的告警语义与冷却逻辑。
