# 导航收敛、输入区收紧与投行单滚动面

日期：2026-11-11
状态：已实施

## 需求

1. 左侧导航按钮过多，「演化」移出导航，「数字专家」从导航移入设置。
2. 对话区输入卡片过高：收紧高度，底边更贴近窗口底部。
3. 投行板块（ETF 资金观察）出现两条相邻的竖直滚动条，滚轮分不清在滚哪一层，观感不和谐。

## 方案

### 导航

- `NavigationRail` 去掉「演化」「数字专家」两项，保留：对话、工作台、笔记、自动化、投行。分组线仍落在「自动化」之前。
- **演化**：入口留在「视图」菜单（原本就有），不再占导航位。它的整页面板与路由（`page === "era"`）不变。
- **数字专家**：成为设置页的一个分类（`SettingsTab = "experts"`），渲染现有 `ExpertsPanel`。设置页该分类不走 `settings-content` 的窄栏排版——专家面板是列表 + 详情两栏，宽度不够会挤成三条；改为在右栏里直接占满，并把「开始时切换到对话页」接回设置页已有的返回主页回调。
- `AppPage` 去掉 `"experts"`：不再有独立路由，避免留下一个没人能到达的页面分支。菜单「视图 → 数字专家」改为打开设置的该分类。

### 输入区

- 输入卡片内 `textarea` 最小高度 76px → 56px，内边距 18/18/8 → 14/16/6；工具栏与底栏间距各收一档。
- 输入区外容器底部留白 16px → 12px。目标是把整块往下压、上沿更靠近消息区，同时不改变可点区域与换行策略（窄面板仍按 `.composer-toolbar` / `.composer-footer` 的 flex-wrap 换行）。
- 首屏 `EmptyState` 用的是同一个 `InputBox`，随之一起变矮，不再单独调整。

### 投行单滚动面

问题成因：`.investment-main` 是页面滚动容器，`.investment-table` 又用 `max-height` 开了第二层滚动，两条竖条并排贴在内容区右沿；滚轮落在哪一层取决于指针位置，看起来像两个滑块互不相干。

- `.investment-table` 取消 `max-height` 与自身纵向滚动（`overflow-x: auto` + `overflow-y: hidden`：横向仍可滚宽表，纵向交回页面）。表格高度由内容决定，`overflow-y: hidden` 只关掉自开滚动、不裁内容。整页只剩 `.investment-main` 一条竖直滚动条。
- 表头 `th` 随之不再 `position: sticky`：粘性表头只在表格自身是滚动容器时才跟得住，与「单滚动面」不能兼得。取舍是让列头随页面滚出视野，换来只有一条滚动条。
- `窗口明细` 数字列右对齐（复用 `.number`），缺失值改用与总览一致的 `investment-badge` 微标（`缺 N 日`），不再每行重复整句「数据不足」。`所属日` 对整表是同一个值，移到小节标题里（`截至 YYYY-MM-DD`），省出的整列让金额列有空间对齐。
- 资金流向条里缺数据的行改用同一枚「缺口」微标，与表格口径一致。

已知取舍：长表（两融逐日明细等）滚到底时看不到列头。若后续要恢复列头，正确做法是把粘性吸附目标从表格自身换成 `.investment-main` 并给出页头高度的 `top` 偏移，同时确认页头高度变化时同步更新该偏移。

## 验证边界

纯展示与本地界面状态改动，无引擎、磁盘、进程或安装契约变化，Windows/macOS 共用实现。类型检查（`npx tsc --noEmit`）与 Vite 生产构建验证代码，`npm run check` 的 vitest 全量通过；滚动层级、列头随页面滚出、输入区高度需在真实窗口内目测。
