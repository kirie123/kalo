# 数据目录迁移

## 交互和范围

- 设置的数据管理页显示当前数据根，选择一个已存在的文件夹，目标固定为该文件夹下的 `.kalo`。展示目标后点击准备迁移，正常退出并重新打开进入维护模式；保留未保存笔记的既有检查。
- 维护模式不启动引擎、网关、终端或定时任务。确认迁移后复制整个数据根，包括会话、认证配置、附件、工作区、内置环境与资料；显示进度，成功后重启到新目录。
- 目标 `.kalo` 必须不存在，不能与源目录相同或互相嵌套，不覆盖、不合并现有资料。失败提示具体路径和处理方式，未成功切换时继续使用原目录。
- 旧位置变为兼容入口：Windows 使用目录 junction，macOS 使用目录符号链接。历史消息、笔记、工作区书签和虚拟环境中的绝对路径因此继续有效，不做可能损坏二进制或历史内容的字符串替换。
- 原数据重命名为同级 `.kalo-backup-<UUID>`，不自动删除。成功提示备份位置，用户确认新位置工作正常后可清理备份；兼容入口需要保留。迁移过程中请暂停外部编辑器和同步软件。

## 根定位与启动

- 用户 home 下 `.kalo-location.json` 是独立于数据根的启动定位文件，包含版本、已选择的绝对根、历次旧根及最近备份位置；不修改系统级环境变量。资料包导出识别记录中的旧根，将笔记里的旧绝对附件路径映射到当前根后继续执行原有路径安全校验，确保迁移后仍可导出。
- 桌面端优先级为设置保存的位置、外部 `KALO_HOME`、默认 `~/.kalo`。设置选择代表用户最新决定；解析结果通过 `KALO_HOME` 传给子进程。引擎单独运行仍遵守自身环境变量约定。
- 启动时冻结本进程根，迁移完成只更新定位文件并重启，不在运行中切换各模块的根。定位文件损坏或目标丢失时明确报错，不回落到空目录。
- `.kalo-relocation.json` 是同一 home 下的恢复日志。正常启动取得数据锁前先恢复未完成切换；不允许一半模块使用旧目录、一半使用新目录。

## 文件事务

1. 在维护模式持有源 profile 锁、home 下的 `.kalo-location.lock` 应用锁及操作互斥锁，检查路径、目标不存在与空间。启动和专家 CLI 导入共用应用锁，同一用户不能同时打开多个实例写入迁移位置。
2. 在目标父目录创建唯一暂存目录。递归复制普通文件与目录，保留权限；符号链接只复制链接本身，Windows junction 由平台适配复制，不遍历链接指向的数据。拒绝不支持的特殊文件。
3. 对源和副本逐文件流式 SHA-256 校验并复查目录清单，检测外部改动。排除运行时 `profile.lock`、本次迁移请求和维护标记；保留其他数据。
4. 写入恢复日志，将暂存目录独占改名为目标 `.kalo`（macOS 使用排他 rename，Windows 使用不带覆盖标志的 MoveFileExW），取得目标 profile 锁。应用锁仍持有时关闭源 profile 文件句柄，以允许 Windows 改名目录；将源改名为备份并创建兼容入口。任一步失败按日志恢复原位置并重新锁定。
5. 最后原子持久化新根定位文件。定位文件是提交点：提交前恢复旧根，提交后保留新根、兼容入口和备份。跨盘使用复制和同盘改名，不依赖跨盘 rename。
6. 清理恢复日志，关闭维护入口并释放锁，请求重启。崩溃或断电后根据提交点恢复；保留无法确认归属的文件并报错，不猜测删除。

Windows 兼容入口要求源位置所在磁盘支持 NTFS junction，目标使用本机目录，不支持网络共享。macOS 使用原生符号链接。复制失败的暂存副本保留在目标父目录 `.kalo-moving-<UUID>`，错误中显示路径，避免失败清理误删数据；原目录继续可用。

## IPC 契约

- `data_location_status {}` 返回当前根、待迁移目标及最近备份。
- `data_location_prepare {parent: string | null}`：校验并记录目标、进入下次启动维护模式；null 取消目录迁移请求，普通模式同时取消下次进入维护模式。
- `data_location_commit {}`：仅维护模式执行完整迁移，成功后释放锁并重启，返回新根及备份位置；下次启动的设置页显示备份位置。
- 复用 `data-transfer-progress` 显示复制与校验进度；不改变引擎 NDJSON。

## 验证

- 文件系统单测覆盖完整复制、二进制和大文件校验、权限/链接保持、目标碰撞、嵌套拒绝、源变化、提交前回滚及提交后恢复、备份和兼容路径可读。
- 根定位测试覆盖设置优先级、无设置回退、非法配置与重启加载；不依赖真实用户数据。
- 前端执行类型检查，文件系统测试仅使用独立临时目录；不为 IPC/DOM 编造 mock 测试。分别人工验收 Windows 和 macOS 的目录选择、跨盘移动、重启、旧附件和环境访问。

## 本次验证结果

- Windows：桌面端类型检查和 792 个前端测试通过；Rust 127 个常规测试通过。迁移测试覆盖目录锁、空目标碰撞、切换前故障、逐阶段中断恢复、缺失磁盘、位置重载、连续迁移和旧路径读取。
- 单独启用跨卷测试，在两个不同本机磁盘之间迁移临时数据，校验字节、兼容入口和备份，测试通过。测试使用生成的独立目录，未移动实际个人数据。
- 文件行数、IPC 契约和差异空白检查通过。后续修复了网关 PATH 大小写合并及 POSIX 测试分支，网关 164 个测试全部通过，整体 changed-aware 检查通过。
- macOS 已实现原生符号链接和排他改名，加入可执行权限、相对链接的 Unix 测试；当前仅 Windows 环境，未做 macOS 编译/实机验收。Windows 已重建引擎、网关并通过 `bun run build` 生成 `Kalo_0.6.6_x64-setup.exe`；设置页目录选择及自动重启待安装后 GUI 验收。
