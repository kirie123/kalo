# 历史会话恢复与停止隔离

日期：2026-10-24

## 问题与证据

历史会话重新打开时，子任务通知在 session_start 扫描未确认结果，并立即 triggerTurn；停止只中止当时的 agent loop，没有清空 followUp，也没有阻止后台通知重新唤醒。现场日志出现无新 user 消息的 custom_message → assistant aborted → custom_message → assistant stop，说明确实启动了模型调用，不能仅修正界面状态。

## 恢复与通知

新建、恢复、重载会话默认暂停自动通知投递；扫描仍提供后台状态，落盘结果保持未确认。只有 interactive/rpc 输入进入真实 user 消息后，才恢复该会话的自动投递；已有结果在 before_agent_start 随用户消息注入，不能抢先发起另一轮。已经运行的常驻会话切换仅切换视图，不改变其执行状态。

网关 job 通知使用相同的输入门控，暂停期间不领取 completion，避免已领取却丢失结果。异步领取用会话绑定、停止代数校验；同一绑定在停止后收到的响应保留到下次明确输入，不得触发模型。会话替换后的旧响应不能投递给新 owner。本次仍沿用网关既有先领取即标 reported 的契约，不新增跨进程通知重放保证；旧会话结果仍可用任务列表和 output 查询。

## 停止契约

引擎 abort 同步提升取消代数、清空 steering/followUp 队列并中止当前请求，再向扩展发出无返回值的 session_abort 事件。内置通知模块收到事件后暂停自动唤醒，直到下一次真实输入。所有异步 prompt 预处理及运行后的 retry/compaction/continue 必须校验取消代数，停止前已开始的预处理完成后也不能再次运行。

取消控制和续跑循环抽到独立模块，AgentSession 仅负责适配。停止仍等待真实 idle，不伪造已停止状态；桌面显示明确的停止中动画，替换难以理解的加号。正常取消不得被当成失败自动恢复。

主轮次停止继续沿用后台任务所有权契约：不擅自取消已登记的独立后台任务，但其结果不能再次启动已停止的主会话；结果持久保存，下次明确输入再处理。

RPC abort 命令及返回形状保持不变；新增事件仅在引擎扩展层使用。Windows/macOS 共用相同取消与通知逻辑，不引入 shell、进程或路径平台分支。

## 验证

用临时目录、本地 faux provider 与可控制的异步关卡验证：恢复旧结果零模型调用；新输入携带结果；停止后完成的后台任务不唤醒；followUp 与预处理边界取消；下一次明确输入可正常执行；异步 job 领取与会话切换隔离。桌面执行类型检查和现有纯逻辑测试，重建引擎与桌面后交由用户验收原生界面。

2026-10-24 验证结果：

- 引擎 12 个专项测试文件、97 项通过，覆盖通知、取消、队列、RPC preflight、retry、settled 与压缩取消退避；harness `npm run check` 通过。
- 根目录 `npm run check` 通过：桌面类型检查、59 个文件的 754 项纯逻辑测试；文件行数和 77 个 bridge 命令契约检查通过。
- Windows 引擎经离线模型目录构建，桌面 release 编译成功。编译后引擎使用独立临时数据、本机模拟模型服务实测：历史打开零模型请求，旧结果在明确输入后接收确认；流式请求停止回执约 32ms，连接被取消且 queued followUp 未续跑，下一次明确输入成功。该耗时仅为本机模拟服务样本，不是所有提供方的停止时延承诺。
- 未调用真实付费模型；原生界面由用户检查，macOS 未实机验证。
