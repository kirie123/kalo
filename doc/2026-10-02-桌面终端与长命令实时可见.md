# 桌面终端与长命令实时可见

日期：2026-10-02
状态：设计（与实现同批落地）

## 0. 问题

Kalo 跑长命令时对话里只有一个静态行：`执行了 1 条命令` + `正在运行`。pytest 一跑 6–10
分钟，跑到哪、有没有卡住、有没有报错，全看不见；展开工具行甚至只看到
`{"content": []}` 这种原始 JSON（空 content 让 `resultText` 掉进了
`JSON.stringify` 兜底）。

引擎侧其实一直有数据：bash 工具每 ~100ms 就把 stdout/stderr 的累计快照通过
`tool_execution_update` 推给桌面端，`chat-store` 也把每一帧存进了
`ToolCallRecord.partialResult`。缺的是把它用起来，以及一个「能把命令放到终端里看」
的容器。

对照物：右栏目前只有文件树。用户要的是「文件区旁边有一个终端」，长命令点一下就能在
里面看着它跑。

## 1. 目标与非目标

**目标**

1. 右栏新增「终端」视图，与文件区并列切换：真终端（xterm.js + Rust PTY，
   可交互、可开多个 shell 页签）。
2. bash 工具行提供「在终端中打开」：为这条命令开一个**只读跟随页签**，把它的实时
   输出镜像进终端（运行中的、已结束的都能看）。
3. 长命令（≥30s）在对话里自动展开实时输出，并显示已运行时长；空输出的原始 JSON
   不再出现。

**非目标**

- **不 attach 到引擎子进程**。命令跑在 pi sidecar 里、stdio 是 pipe 不是 PTY，
  桌面端没有任何办法把另一个进程的 stdio 挂进新终端。跟随页签是只读镜像；
  想在终端里输入，请开新的 shell 页签。
- 不做终端会话持久化（重启后终端不回来），不做 shell 选择 UI。
- 不改引擎/sidecar 契约，不需要重建 `pi-*.exe`。

## 2. 交互

### 2.1 右栏形态（2026-10-03 已改为页签式）

右栏现在是**页签容器**：页签条 + `+` 菜单（文件 / 浏览器 / 终端），文件、浏览器、
终端、跟随都是页签，宽度记在 `kalo.layout.panelW`。新的交互与代码结构见
`doc/2026-10-03-右栏页签面板.md`；下面关于终端页签的语义（shell / 跟随 / 去重 /
只读）继续适用。

### 2.2 终端页签

- 页签标题：shell 页签是「终端」；跟随页签取命令摘要。`+` 菜单里的「终端」新建
  shell 页签（cwd = 当前会话工作目录）；页签上的 x：shell 页签 kill 掉对应 PTY，
  跟随页签只移除镜像（没有进程）。
- 跟随页签：只读（`disableStdin`）；页签上的小绿点表示运行中（结束后换成眼睛
  图标），tooltip 显示完整命令；正文第一行是命令回显，其后是实时输出，命令结束
  追加一行灰色结束/失败提示。命令结束后页签保留，当作日志看。
- 跟随页签按 `toolCallId` 去重：同一命令重复点击只是激活已有页签。

### 2.3 对话里的长命令

- 运行中的 bash 行每秒刷新：≥5s 在行上显示「已运行 Ns」，≥30s 自动展开该行详情
  （用户手动收起来过的行不再自动弹，尊重操作）。
- 详情输出取结果/`partialResult` 的文本块（结果优先，它带截断脚注）；没有文本
  就显示「运行中…（暂无输出）」，不再落到 `JSON.stringify(result)`。
- bash 行新增「在终端中打开」小按钮：为这条命令开/激活跟随页签，并展开右栏。

## 3. 架构与数据流

### 3.1 Rust：PTY 会话（新 `terminal.rs`）

新增依赖 `portable-pty`（ConPTY / Unix pty 一套接口）。

| 命令 | 参数 | 说明 |
|---|---|---|
| `terminal_open` | id, cwd?, cols, rows | 建 PTY + 起 shell；id 由前端生成（shell 页签 `t-…`，跟随页签 `w-<toolCallId>`），Rust 只校验合法性（字母数字 + `-`/`_`）|
| `terminal_write` | id, data | 键盘输入；主线程执行保持按键顺序，前端 fire-and-forget |
| `terminal_resize` | id, cols, rows | fit 后同步行列 |
| `terminal_close` | id | kill 进程树 + 移除会话 |

| 事件 | 载荷 | 说明 |
|---|---|---|
| `terminal-output:{id}` | string | 合批后的输出批次 |
| `terminal-exit:{id}` | `{ code: number \| null }` | shell 退出 |

实现要点：

- **shell 解析收在 `default_shell()`**（窄适配层）：Windows `powershell.exe`，
  Unix `$SHELL` → `bash`。与 CoWith 桌面端同款默认值，ConPTY 原生支持最好；
  以后要提供 shell 选择只动这一个函数。
- **输出合批**：reader 线程 → mpsc → emitter 线程，16ms 窗口攒起来发一条事件
  （`yes` 类刷屏命令不能一条 chunk 一个事件）；buffer 超 64KB 立即发；退出前
  先 flush 再发 exit，避免尾巴丢在窗口里。
- **UTF-8 增量解码**：chunk 边界可能切在多字节字符中间，直接把字节
  `String::from_utf8_lossy` 会出乱码。保留不完整尾巴（≤3 字节）拼进下一批，
  非法序列替换为 U+FFFD。纯逻辑，带单测。
- **进程清理**：`terminal_close` kill 会话；应用退出（`RunEvent::Exit`）时
  `kill_all`，不留孤儿进程。Windows 上先 kill 再 `taskkill /T`（经
  `proc.rs` 的窄适配层，Unix 只 kill）。

### 3.2 前端桥接（`lib/pi-bridge.ts`）

- invoke：`terminal_open` / `terminal_write` / `terminal_resize` / `terminal_close`
  （命令名双向核对由 `scripts/check-bridge-contract.mjs` 把关）。
- listen：`terminal-output:{id}`、`terminal-exit:{id}`。

### 3.3 前端状态与纯逻辑

- `lib/panel-tabs.ts`：模块级 store —— `{ open, tabs, activeId }` +
  动作（`toggle` / `activate` / `close` / `newShell` / `newBrowser` / `openWatchTab`）。
  页签编排是纯函数，单测覆盖（关闭时顺带清掉 watch 注册表条目）。浏览器页签与
  文件页签的交互见 `doc/2026-10-03-右栏页签面板.md`。
- `lib/tool-watch-registry.ts`：`toolCallId → { status, partialResult, result }`
  的发布/订阅。**跨会话**：parked runtime 的 partial 也照常发布，所以切走会话、
  命令在后台继续跑时，跟随页签仍在刷新。打开跟随页签时用行上的现状 seed 一次，
  历史回放的命令也有内容可看。只有 bash 会往里发布（其它工具的 partial 没有读者，
  全量留在模块级 map 里纯属泄漏）；页签关闭时清掉对应条目，行上仍持有自己的副本。
- `lib/terminal-watch.ts`：累计快照 → 增量。新快照是旧快照的前缀就 append，
  否则 reset（输出滚出滚动窗口时快照会变，不能盲目拼接）。
- `lib/tool-output.ts` 新增 `contentText()`：只取 content 里的 text 块，
  不落 JSON 兜底，供 bash 运行中显示使用。
- `chat-store` 的最小改动：`ToolCallRecord.startedAt`（`onToolStart` 记录）；
  partial/结束两个点向 watch registry 发布。该文件在行数基线里（只许缩），
  同批压缩等量行数保持基线不涨。

### 3.4 组件

- `components/RightPanel.tsx`：右栏容器 + 页签条 + `+` 菜单（文件 / 浏览器 / 终端）
  + 宽度拖拽。
- `lib/terminal-session.ts` + `components/TerminalTab.tsx`：xterm 挂载壳。
  建立过程交给 `startTerminalSession(deps)`（依赖注入：xterm 加载、ResizeObserver、
  pty 桥接都从外面来），在 await 之间检查「还活着吗」——卸载落在 await 中间时
  把已经建出来的东西逐件收掉，不留孤儿 PTY。纯逻辑，单测覆盖。
- `components/TerminalWatchTab.tsx`：只读 xterm + 订阅 registry 喂增量。
- `App.tsx`：视图切换接线；`ToolCallGroup.tsx`：已运行时长 / 30s 自动展开 /
  「在终端中打开」按钮 / partial 文本显示修复。

## 4. 双平台

- shell：Windows `powershell.exe`；macOS `$SHELL`（zsh）。差异只在 `default_shell()`。
- kill：Windows 补 `taskkill /T`（`proc.rs`），macOS 直接 kill。
- 路径：cwd 由前端传会话工作目录，反斜杠原样交给 PTY 层，不做 POSIX 归一化。
- 事件名与命令名两端一致，无平台差异。

## 6. 工具链注意

在 `kalo-desktop/` 装依赖要用 `npm install --workspaces=false ...`。根
`package.json` 声明了 bun workspace 之后，直接 `npm install` 会让 npm 去处理根树
并以 `Cannot read properties of null (reading 'matches')` 崩溃（npm 11 arborist
在处理根 devDeps 时的缺陷）；加 `--workspaces=false` 让 npm 只当独立项目处理。
