# macOS 平台支持（dev 可跑）与 sidecar 命名契约

## 背景

在 macOS (arm64) 上首次启动项目，界面提示「引擎未响应」。

根因是 Kalo 此前为 Windows 专属打包，sidecar 文件名在两处被硬编码：

```rust
// session.rs
const SIDECAR: &str = "pi-x86_64-pc-windows-msvc.exe";
// gateway.rs
const SIDECAR: &str = "kalo-gateway-x86_64-pc-windows-msvc.exe";
```

**为什么症状是「未响应」而不是「找不到引擎」**，是这次要一并消除的诊断陷阱：
`resolve_pi_path()` 的第 3 步 dev 回退只做 `p.is_file()` 检查。那个 `.exe` 确实存在于
`src-tauri/binaries/`（Windows 构建 staging 的产物），于是路径解析**成功**，随后
`Command::new(pi_path).spawn()` 直接拉起一个 Windows PE。macOS 上这会
`Exec format error` / 进程秒退，前端只观测到引擎没有回应。症状与根因相距甚远。

## 目标与非目标

**目标**：`npm run tauri dev` 在 macOS 上完整可用（引擎会话、gateway 任务运行时）。

**非目标**：`.app` / `.dmg` 打包与 Apple 签名公证。发行安装包仍只出 Windows（nsis）。

## 契约变更

### sidecar 命名契约

sidecar 可执行文件名从「硬编码 Windows 文件名」改为：

```
<stem>-<target-triple><EXE_SUFFIX>
```

例：`pi-aarch64-apple-darwin`、`pi-x86_64-pc-windows-msvc.exe`、
`kalo-gateway-aarch64-apple-darwin`。

三元组的**单一事实源**有两个端点，必须一致：

- **Rust 侧**：`build.rs` 把 cargo 的 `TARGET` 透传为编译期环境变量
  `KALO_TARGET_TRIPLE`（cargo 只在 build script 里提供 `TARGET`），
  `src-tauri/src/sidecar.rs` 用它拼出要找的文件名。
- **构建侧**：`scripts/platform.sh` 的平台 → 三元组映射，被
  `scripts/build-engine.sh` 与 `scripts/build-gateway.sh` 共同 source。

把三元组嵌进文件名本身就是主修复：**其他平台的二进制不再可能匹配上**，
`is_file()` 通过但 spawn 失败的那条歧义路径被从根上消除。

### `sidecar.rs`：共用的定位逻辑

`resolve_pi_path()` 与 `resolve_gateway_path()` 原本是逐行重复的三步查找。
现收敛为 `sidecar::resolve(stem, env_override)`，查找顺序不变：

1. `env_override` 环境变量（`KALO_PI_PATH` / `KALO_GATEWAY_PATH`）
2. `binaries/<name>` —— 可执行文件旁（安装后布局）
3. `src-tauri/binaries/<name>` —— `CARGO_MANIFEST_DIR` 开发布局

额外增加一条防线：unix 下校验 exec 位，缺失时返回带 `chmod +x` 的可操作错误，
而不是让 spawn 抛一个用户无从下手的 errno。找不到时的错误直接点名该跑哪个构建脚本。

### 二进制 staging 布局：扁平共存

`binaries/` 是 gitignored 的本机构建产物目录，**不按平台拆子目录**——没必要：

- 可执行文件按三元组区分
- 平台相关资源本身已按名字隔离：`native/darwin/` vs `native/win32/`、
  `clipboard.darwin-arm64.node` vs `clipboard.win32-x64-msvc.node`
- 其余资源平台中立：`theme/`、`assets/`、`export-html/`、`photon_rs_bg.wasm`、`package.json`

因此多平台产物可以同时躺在 `binaries/` 里互不覆盖，staging 是增量的。
本次已实测验证：darwin-arm64 构建完成后，原有的 Windows 产物与 `native/win32/`
仍然完好。

### 构建脚本平台参数化

- 新增 `scripts/platform.sh`：可 source 的公共映射，导出 `KALO_PLATFORM`、
  `KALO_TRIPLE`、`KALO_EXE_SUFFIX`、`KALO_BUN_TARGET`、`KALO_HOST_PLATFORM`、
  `KALO_IS_CROSS`。默认取宿主平台，`--platform <name>` 显式覆盖。
- `scripts/build-engine.sh`：平台参数化。clipboard binding 的强制预取改为
  **仅交叉构建时执行**——目标等于宿主时 `npm ci` 本来就装了对的 binding。
  完整性校验（native helper、clipboard `.node`）按平台查对应文件。
- 新增 `scripts/build-gateway.sh`：替代 `gateway/package.json` 里写死的
  `--target=bun-windows-x64`。目标等于宿主时省略 `--target`，避免 bun 去下载
  target runtime（与 harness 的 `build-binaries.sh` 同一考量）。

### bundle 配置拆分

平台相关的 `bundle.targets` 与 sidecar `resources` 从 `tauri.conf.json` 移入
`tauri.windows.conf.json`（nsis）与 `tauri.macos.conf.json`（app），
由 Tauri 2 按宿主平台自动合并。平台中立的 resources 留在基础 conf。

macOS conf 的 resources 用 glob（`binaries/pi-*-apple-darwin`）而非写死三元组，
否则 Intel Mac 上会指向不存在的文件。

### 双平台等价契约

根 `AGENTS.md` 的「Windows 是默认契约」改为「**Windows / macOS 双平台等价契约**」：
改动默认同时评估两侧，OS 差异收敛在窄适配层。现有窄适配层样板：
`sidecar.rs`、`proc.rs`（`no_window`/`kill_tree`）、`files.rs::open_path`、
`market_env.rs::resolve_bash`；home 目录一律 `USERPROFILE` 回退 `HOME`。

`.github/workflows/ci.yml` 的 `desktop-rust` job 改为
`[ubuntu-latest, macos-latest]` 矩阵，并从 `cargo test --no-run` 改为
`cargo test`——只编译不运行挡不住「又把某平台文件名写死」这类回归，
`sidecar.rs` 的单测必须真跑起来才有意义。

## 已知缺口（留给后续打包任务）

- **macOS `.app` 打包未验证**。app bundle 把资源放在 `Contents/Resources/` 而不是
  可执行文件旁，而 `sidecar::resolve()` 的第 2 步找的是「exe 旁 `binaries/`」
  （`Contents/MacOS/binaries`，不存在）。做打包时这一步需改用 Tauri 的
  `path().resource_dir()`；`internal_skills.rs::source_dir()` 的 release 分支
  有同样问题。dev 模式不受影响：它走第 3 步的 `CARGO_MANIFEST_DIR` 开发布局。
- **Apple 签名与公证**未涉及，需要开发者证书。
- **Windows 侧未在本机复验**。命名与 staging 两侧都由 `platform.sh` 的同一份映射
  推导，`--platform windows-x64` 交叉构建路径予以保留，但需在 Windows 机器上
  跑一次 `bash scripts/build-engine.sh --platform windows-x64` + `tauri dev` 确认。
- **TitleBar 观感**：`decorations: false` 配 Windows 风格 caption 按钮，在 macOS 上
  功能正常（用的是跨平台 Tauri window API）但没有原生红绿灯。纯外观问题，未处理。

## 验证

```bash
bash scripts/build-engine.sh
file kalo-desktop/src-tauri/binaries/pi-aarch64-apple-darwin    # Mach-O 64-bit executable arm64
bash scripts/build-gateway.sh
file kalo-desktop/src-tauri/binaries/kalo-gateway-aarch64-apple-darwin

cd kalo-desktop/src-tauri && cargo check && cargo test          # sidecar.rs 单测
cd kalo-desktop && npm run tauri dev
```

端到端验收点：新建对话能流式回复；**重命名会话**不再弹「引擎未响应」toast
（`chat-store.ts` 走 `set_session_name` RPC 的那条路径）；文件面板可展开预览；
控制台无 `[kalo] gateway autostart skipped`。
