## 产品目标与第一版范围

Kalo 升级为围绕研究问题持续工作的量化决策工作台。用户描述目标，Agent 把目标转成可检查的研究任务，调用确定性数据与计算工具，产出带证据的结论、策略版本与实验报告。界面和 Agent 操作同一组对象，不能形成“聊天里一套结果、图表里另一套结果”。

首发市场已确定为 A 股与场内 ETF；先做日线研究、ETF 资金观察、历史回测与模拟跟踪。第一条完整路径为：发现 ETF 份额变化 → 检查价格和成交证据 → 提出轮动假设 → 审阅策略规格 → 回测与样本外验证 → 加入观察 → 记录失效条件。行情、榜单和回测全部带数据时间及来源。

第一版不包含实盘券商下单、分钟级撮合、融资融券、期权、高频、自动优化后直接部署。A 股日线研究先覆盖沪深，北交所标的进入主数据后按独立规则验收再开放回测；ETF 轮动先限境内股票 ETF。跨境、债券、商品 ETF 可查行情，其交易制度、净值时差和份额数据必须单独验证才能入策略池。

| 视图 | 用户主要问题 | 关键动作 |
| --- | --- | --- |
| 决策台 | 今天哪些研究结论或数据变化值得处理？ | 审阅实验、检查失效条件、查看观察记录 |

## 数据接入与存储

### 第一阶段数据集

必须具备证券主数据、上市/退市日期、历史交易日历、股票和 ETF 日线 OHLCV/成交额、复权因子与分红拆分、ETF 每日份额/净值/规模、停牌和价格限制、必要的历史指数/股票池成分。后续增加公告财报、行业、融资融券、分钟数据。

采用供应商适配器统一能力，不让策略直接调用供应商 API。默认复用 AKShare 接入公开行情、交易所 ETF 份额和基金净值，配合每日本地积累；支持用户 CSV 导入。Tushare 作为优先评估的付费历史补全源，另预留 RQData、iFinD、Wind 适配器。具体启用源由权限探测、真实返回样本、历史覆盖和使用范围决定，不在产品内承诺某源永久免费或永远可用。公开网页可访问和采集库开源不等于上游数据允许再分发；第一版按用户本地取数使用设计。

每个源登记：能力列表、字段单位、日历、更新时间、历史起点、限频、权限状态、使用范围、最近验证时间、适配器版本。备用源不能静默覆盖主源；切换需记录新快照及差异，策略回测仍固定原始快照。网页抓取故障不得把旧值伪装成最新数据。

### 三层存储

1. 原始层：按源和批次存响应与摘要哈希，支持核对和修订追踪。
2. 标准层：按市场/数据集/年份分区的 Parquet；数据服务单写入者提交不可变分区与快照清单。Rust 数据服务与回测进程按需读取 Parquet；回测仅访问冻结清单中的分区，不共享可变分析数据库。
3. 对象层：SQLite 保存数据目录、任务索引、策略版本、实验元信息与观察规则；大表不复制进会话。

目录统一基于应用数据根：`market/raw/`、`market/datasets/`、`market/catalog.sqlite`、`quant/strategies/`、`quant/runs/`。已有宏观 JSONL 保留，通过只读适配器读取；迁移有独立版本和回滚路径，不覆盖旧文件。

核心记录至少包含 `instrument_id`、`event_time`、`available_at`、`ingested_at`、`source_id`、`dataset_version`、`quality_flags`；另保存供应商提供的 `published_at`、本地 `first_seen_at` 和可用时间依据 `availability_method`（已知发布、实际观察、保守假设）。金额统一存元，份额存份，界面再转换亿元/亿份。交易日使用所属交易所日历，时间戳保留时区。

数据状态包括未配置、同步中、可用、陈旧、缺口、源冲突、权限不足。缺失显示为空及原因，不补零；不把停牌伪造成可成交。历史修订产生新版本，已有回测不被后台刷新重写。

默认流程：盘后同步行情，下一交易日上午补齐上一日份额与净值，缺失批次限次重试；按源实际到达时间更新状态，不把定时执行成功等同于数据齐全。上游失效时保留最后有效值及日期，并暂停依赖新数据的信号。

免费模式可以先开放行情研究、价格策略回测和逐日资金观察。每只 ETF 的 20 日净流量需要 21 个连续交易日份额观察点，以及对应 20 日净值；5 日窗口同理需要 6 个份额观察点。数据中心按标的展示可用起止日期、完整天数、事件校正和历史发布时间可信度。历史数据不足时，资金策略只能选择完整区间；价格策略是否可运行单独判断。

## ETF 资金口径

界面明确区分三种数据：

- 成交额：二级市场交易活跃度，不代表资金净进入基金。
- 净申购金额估算：拆分等份额事件校正后的份额增量 × 同日单位净值。用于近似观察申赎方向，标记为“估算”，不是精确现金流或已知主力持仓。
- 供应商资金流：供应商按成交分类计算的指标，单独标注算法口径，不与净申购估算拼接。

规模变化含净值涨跌，不能直接替代净流入。拆分、合并、分红、份额口径变化需事件校正；缺少份额或净值则不生成该日估算，也不能跨缺失日差分后冒充单日流量。

仅有份额净变化只能估算净申购，不能分别还原总申购和总赎回。例如校正后增加 1 亿份、当日净值 2 元，净申购估算为 2 亿元；这不等于已知申购 2 亿元且赎回为零。ETF 可以实物申赎，因此界面用“净申购估算”作为主指标，不宣称现金实际流入；用户查看流入/流出榜时，分别显示净申购为正、为负的标的，并保留口径说明。

支持 1/5/20 交易日净申购估算、份额变化率、流量/期初规模比率、连续流入天数、同类分位数。窗口不完整时展示有效天数并默认排除排名；不同发布时间的数据不能混成同一“今日榜”。

每个点同时标记数据所属日和可用时间。份额数据可能到下一交易日才完整，交易信号按 `available_at <= decision_at` 选择数据。没有可靠历史发布时间的数据默认按保守延迟使用，并标记为延迟假设；上线前进行延迟一到两日的敏感性验证。盘后观察任务分为行情更新和份额补齐两个触发阶段，不假设收盘后所有数据同时就绪。

当前下载到的历史序列不一定等于历史时点实际能看到的版本。缺少发布时间或修订历史的资金数据只能用于标注假设的研究回测；保守延迟不能消除历史修订造成的偏差。严格按当时可见信息评估时，必须使用已保留的历史快照或提供相应保证的数据集，不满足则阻止该模式运行。

## 技术组件选型

复用 React/TypeScript/Tauri 壳层、pi-bridge、gateway Job Runtime。新增 Rust investment-core 负责策略校验、因子、逐日撮合、精确账本与绩效；独立 Rust investment-worker 承担数据服务和回测运行。gateway 只做路由与任务生命周期，不实现量化业务计算。

数据 HTTP 接入采用 reqwest/rustls；元信息采用 rusqlite；行情采用不可变 Parquet；资金账本采用 rust_decimal。以上为拟新增依赖，不代表当前 Cargo.toml 已有。首版不默认引入 DuckDB/Polars。图表继续采用 Lightweight Charts 与 ECharts。

免费数据仍优先，现有 Python/AKShare 仅作为可选取数适配器；CSV 与已验收的 Rust HTTP 适配器保证无 Python 时仍有可用接入路径。回测只读标准快照，不依赖采集语言。RQAlpha、vectorbt 等保留未来候选，不作为默认运行依赖。

## Agent 原生能力与边界

用户可发出：“找出近 20 日份额持续增加、价格尚未明显上涨的股票 ETF，检验周度轮动是否有效。”

系统执行链：解析目标 → 给出研究范围和所需数据 → 确认数据覆盖 → 创建策略草案 → 检查规则完整性 → 冻结数据与代码版本 → 提交计算 → 展示报告及反证 → 用户选择继续验证或观察。

Agent 负责研究意图、策略表达、工具编排、异常解释和报告；程序负责取数、指标、组合权重、撮合、绩效与风险判断的硬约束。首版采用受限的声明式策略规格与已有算子；开放任意 Python 策略属于后续阶段，需要独立进程、无凭证执行环境、资源限制和平台隔离方案。

工具按能力提供：查询数据目录、同步数据、读取行情、查询 ETF 流量、保存策略草案、校验策略、运行/取消回测、读取报告、创建/暂停观察规则。UI 和 Agent 都经过同一服务验证，禁止 Agent 通过修改报告文件宣称一次回测通过。后台无变化的采集和阈值检查保持静默；只在数据阻塞、策略失效或待审阅结果时提示。

## 策略与回测

### 策略规格

一份策略必须明确：历史股票池规则、筛选条件、因子公式、排序、权重、调仓时间、信号可用时间、下一可成交时点、仓位/集中度约束、费用、滑点、成交参与率限制、基准、起止区间、样本内外划分及缺失值处理。模糊描述不能直接跑回测。

首个模板：境内股票 ETF 动量轮动。先形成不依赖资金字段的基线，再增加“份额净申购/期初规模”过滤，比较增量作用。避免只有组合结果、无法知道资金信号是否贡献了收益。研究阶段使用固定可复现候选池；正式历史评估按当时上市状态、流动性和可用数据动态生成，并纳入终止上市标的以减少幸存者偏差。

### 执行与验证

采用独立 Rust 计算 worker；撮合内核通过 BacktestEngine trait 隔离，首版使用受限的 Rust 日线组合模拟器。先以固定样本校验执行与账本，再锁定规则版本；不将任何通用引擎的默认参数当作 A 股交易规则。因子筛选可向量化，最终报告必须经有现金/持仓约束的逐交易日撮合确认。首版境内股票 ETF 回测通过验收后再扩大证券规则覆盖，A 股个股行情研究不等于其回测已开放。

- 信号只用决策时已发布数据，默认下一可成交时点成交；收盘信号不能直接按同一收盘价成交。
- 原始价格用于成交和现金记账，调整序列用于指标或收益计算；公司行为在账本中处理，避免重复计息或重复复权。
- 证券规则按类型、市场、板块及生效日期管理：申报单位、价格最小变动、T+1/T+0、涨跌幅、停复牌、税费；规则未知时阻止回测而非猜测。
- 日线无法精确还原盘口和一字板成交，采用保守不可成交规则，显示未成交/延后订单及原因；限制成交量参与率。
- 成本按成交双向计算佣金/滑点，并按证券与日期处理适用税费；股票费用不能套到 ETF。
- 训练、验证、最终样本外时段按时间切分，参数选择只用训练/验证段；最终测试被反复查看后需要新的留出段。
- 参数稳定性、滚动验证、成本翻倍、信号延迟测试作为实验对照；记录尝试次数与失败实验，避免只展示最优版本。

报告包含累计/年化收益、基准与超额、最大回撤、波动率、Sharpe（展示频率及无风险利率假设）、换手率、成本、敞口、年度/月度收益、成交与拒单、样本外结果和数据质量。净值曲线、指标与成交账本来自同一次运行，不能由模型生成。

### 可复现对象

`StrategyVersion` 保存不可变规格与代码哈希；`DataSnapshot` 保存数据分区清单、哈希与发布时点策略；`BacktestRun` 保存上述 ID、引擎/规则版本、依赖锁、随机种子、时间和运行状态；`DecisionRecord` 保存结论、证据、反证、失效条件及用户动作。

回测状态为排队、运行、完成、失败、取消；阶段为加载、校验、计算、撮合、报告。取消通过 Job Runtime 终止进程树，保留日志与未完成产物，首版冻结输入后以新 attempt 重跑；失败重试产生新的 attempt，不覆写成功报告。每个运行绑定任务与会话，可回到原研究上下文。

## 拟议集成契约

以下是后续实施的契约草案，本轮不新增真实 IPC 或引擎工具：

- 请求封套：`schema_version / request_id / operation / payload`；回包包含 `request_id / result` 或结构化 `error.code / message / retryable / details`。
- 只读查询返回摘要和分页/产物引用；大规模 K 线不通过模型上下文搬运。
- 长任务先返回 `task_id / run_id`，事件带 `run_id / seq / phase / progress / status`；断连后查询持久化状态恢复，重复 seq 去重。
- 创建运行携带幂等键，重复提交返回同一任务；策略内容变化生成新版本。观察规则创建也幂等，暂停后不会被迟到事件重启。
- 桌面请求由 `lib/pi-bridge.ts` 统一进入服务；Agent 工具调用同一量化服务。新工具放入 harness 的内置扩展时同步注册与契约检查。
- UI 位于 `features/investment`，业务计算位于独立 Rust 库；Rust/gateway 桥接保持薄层，采集与回测运行模式分离。新提示工作流仍保存在 `internal-skills/<name>/SKILL.md`。

## 双平台与安全边界

Windows/macOS 共用数据结构与计算接口，路径由现有应用数据根解析，遵循 KALO_HOME 配置，Rust worker 由统一资源和 target triple 规则定位，可选采集 Python 由市场运行环境解析。子进程使用参数数组，不拼 shell 字符串；复用隐藏窗口、进程树终止和资源定位适配层。标准数据写入集中到数据服务管理的 worker；回测读取不可变快照。临时文件在同卷完成后原子提交，文件先关闭再重命名。

凭证不进入策略、日志和模型上下文；供应商鉴权由适配层注入。原始资料不具备工具授权。第一版研究与回测不要求每次人工确认；创建持续观察前展示频率、范围和通知条件。若以后增加实盘交易，必须另立订单权限、限额与确认契约。

## 分期、验收与优先级

以下工期为 1 名全职开发、能复用现有底座且数据权限及时具备时的粗估，需在数据探测后重估。

| 阶段 | 粗估 | 交付与验收 |
| --- | --- | --- |
| P0 数据可行性 | 约 1 周 | 选定样本股票/ETF，验证行情、份额、净值的覆盖、单位、延迟、权限；形成可复现样本集 |
| P1 行情与资金工作区 | 2–3 周 | 数据中心、ETF 资金榜、日/周 K 线、数据证据和缺口状态；同一快照 UI/Agent 数值一致 |
| P2 策略与回测闭环 | 3–4 周 | 模板/规格、任务运行、可复现报告、样本外、成本及拒单；固定样本手算账本与引擎相符 |
| P3 Agent 持续决策 | 2–3 周 | 自然语言生成草案、版本比较、观察规则、模拟跟踪和决策日志；暂停有效、重复触发不重复运行 |

第一版闭环约 6–8 周（P0–P2），连续决策约 8–11 周。价格、数据许可和历史覆盖属于 P0 退出条件；历史份额不完整时先交付价格策略基线与资金观察，不能伪造多年资金策略回测。

P0 默认选取沪深合计约 20 只境内股票 ETF，并纳入不同上市时间、分红和异常缺口样本。交付一张实际覆盖矩阵：各字段最早/最近日期、完整度、单位、更新延迟、事件校正、权限与取数错误。免费源先回填能够核验的历史，并启动日常积累；付费仅在明确缺口后试用评估，不先购买全部供应商。价格基线回测与资金增量回测分别验收。免费积累的 20 日窗口需要真实交易日经过，工程工期不替代数据积累时间；自有模拟器的验证工作量也必须在 P0 后重新估算。

最高优先级：主数据映射、发布时间、资金口径、历史快照、撮合与费用正确性。其次是 K 线、报告比较和 Agent 编排。跨市场、高频、开放代码策略和实盘留待后续。

## 验证计划与本轮交付
