# Widget 沙箱脚本执行修复：`</script>` 截断 + CDN 外链脚本不加载

日期：2026-10-11

## 症状

`show_widget` 的 HTML 卡片永远停在 `loading_messages` 那条文案上，下方一片空白，
卡片按默认 360px 占位；时间线里其他步骤都正常（`read_me × 1`、`show_widget × 1`）。
SVG 卡片没事，**凡是 `widget_code` 里带 `<script>` 的 HTML 组件必现**（图表类组件
几乎都带），历史回放同样如此。

## 根因

### 1. payload 直接 `JSON.stringify` 进沙箱 `<script>`，被 HTML 分词器截断

`buildSandboxHtml` 把整个 payload 当 JS 字面量嵌进沙箱文档自己的 `<script>`：

```html
renderHtml("<payload …><script src=\"…\"></script>…", true);
```

`JSON.stringify` 不转义 `<`。HTML 分词器只在「script data end tag」状态认字面量
`</script`，于是 payload 里第一个 `</script>`（任何内联/外链脚本的闭合标签）**当场
收尾**引导脚本：字符串字面量没闭合 → 整段 `SyntaxError` → 后面的

```js
parent.postMessage({ type: 'widget:ready' }, '*');
```

永远执行不到。宿主以「收到 `widget:ready`」作为渲染完成的信号（未 ready 时 iframe
`opacity-0` + 居中 loading 文案），所以卡片永远停在 loading。截断点之后的 payload
文本被当成正文解析，`\r\n`、`class=\dash\` 之类漏成可见文本，样式与引号全乱。

一次真实 trace：`widget_code` 8318 字节、自带 2 对脚本标签 → 生成的沙箱文档有 3 对
`</script>`，引导脚本在第 136 字节处被切断。

### 2. `<script src>` 从来没有真正加载

`renderHtml` 用 `temp.innerHTML = html` 建树——按规范，innerHTML 造出的 `<script>`
不执行，外链连请求都不会发。随后 `executeScriptsSequentially` 对每个脚本只做
`(0, eval)(s.textContent)`：外链脚本的 `textContent` 是空串，`eval("")` 静默跳过。
Chart.js / ECharts 这类从 CDN 引的图表库因此从未加载——即使修好根因 1，画的也只是
一个空 canvas。

## 方案

### 纯逻辑集中到 `src/lib/widget-sandbox.ts`

`buildSandboxHtml`、`sanitizeForStreaming`、`sanitizeForIframe` 从
`WidgetSandboxFrame.tsx` 搬进 lib（字符串进 / 字符串出，不碰 DOM 与 React），
组件只剩状态与 postMessage。新增 `scriptLiteral(code)`：

```ts
JSON.stringify(code).replace(/</g, "\\u003c");
```

`\u003c` JS 解码回来仍是 `<`，但对分词器完全惰性——`</script>`、`<!--` 都不再可能
提前收尾脚本元素。三个嵌入点（HTML finalize / HTML 流式 / SVG `innerHTML`）统一走它。

### 外链脚本按序真正加载

`executeScriptsSequentially` 分三种处理：

- 有 `src`：`createElement('script')` + `src`（保留 `type`）+ `async=false`，
  `onload` / `onerror` 之后再走下一个；同一 `src` 只加载一次（finalize 会重建 DOM，
  否则同一份 CDN 会重复请求、重复执行）。
- `type="module"` 内联：沿用 blob URL 路径。
- 其余内联：`(0, eval)(textContent)`。

`onerror` 只记 console 并继续，不阻塞后续脚本与高度上报。

### 首帧不再重复渲染

srcDoc 里已经带了挂载时的 payload，宿主在 ready 后又发一次 `widget:finalize`
（全量重建 + 重跑脚本）是多余的一轮执行。`lastSentRef` 用挂载时的 sanitized payload
初始化，内容没变就不发。

## 测试

`src/lib/widget-sandbox.test.ts`（node 环境，纯字符串，14 例）：

- 字面量：`JSON.parse(scriptLiteral(x)) === x`；输出里没有裸 `<`
- 沙箱文档不变量（截断回归点）：带脚本的 widget 生成的文档**只有一对**
  `<script>` / `</script>`；引导脚本 `new Function` 可编译；payload 仍是可原样解码的副本
- 流式路径同样断言；SVG 分支断言 `root.innerHTML = <literal>`
- 外链加载器存在（`getAttribute('src')` + `onload`）
- sanitize 不变量：流式剥 `<script>`/危险标签/`on*`/`javascript:` 且容忍半开标签；
  finalize 保脚本、剥 iframe/form/meta/link/base、中和 `javascript:`

组件层（iframe、postMessage、尺寸钳制）仍按仓库测试边界人工验证。

## 验证

拿出问题的那次真实会话的 payload（`2026_年度经营数据看板`：Chart.js 折线 + 环形 +
堆叠柱 + 表格，CDN 走 jsdelivr），新旧两条路径各跑一遍：

| | 旧路径 | 修后 |
|---|---|---|
| 文档 `<script>` 对数 | 3 | 1 |
| 引导脚本 | SyntaxError（136 字节处截断） | 可编译 |
| `#root` | 空 | 三个 canvas：373×260 / 300×220 / 459×260 |
| 页面 | 原文漏成可见文本、样式与引号全乱 | KPI 卡 + 三图 + 表格正常 |

用 headless Chromium 跑沙箱文档本身（`--dump-dom` 验 DOM、`--screenshot` 出图）。
jsdelivr 在 curl 下走 IPv6 被 RST，Chromium 走 IPv4 正常，因此仍按原样用 jsdelivr 验证。

## 边界

- CSP 白名单不变：外链脚本仍限 cdnjs / esm.sh / jsdelivr / unpkg 四个域。
- 沙箱仍无 `allow-same-origin`，脚本拿不到宿主数据；远端脚本剥除策略只作用于**文件预览**
  那条通道，widget 沙箱按白名单放行。
- 去重按 `src` 字符串：两个不同域的同一份库会各加载一次。
- 外链脚本加载失败只在 console 留一行，不弹提示——widget 是模型产出的片段，
  失败信息对用户没有可操作性，反而该由模型回看渲染结果。
