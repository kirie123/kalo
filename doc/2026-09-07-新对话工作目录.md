# 新对话的默认工作目录

日期：2026-09-07
状态：已实施

## 问题

`新对话` 起的会话默认沿用上一个会话的 cwd：

```ts
// chat-store.ts newChat()
const cwd = opts?.cwd || this.active.view.cwd || localStorage.getItem("kalo.lastCwd") || "";
```

后果有两类：

1. **串目录**：上一次在某个项目里干活，点「新对话」问一个完全无关的问题，agent 却把这个项目当
   上下文——读它的 AGENTS.md、在它里面建文件。
2. **专家身份漂移**：从「数字专家」面板点「开始会话」的 cwd 是专家目录（这条是对的），
   但紧接着点「新对话」会继承专家目录、**却不带 `expertId`**：记忆写回个人 `~/.kalo/memory`，
   产出文件落在专家目录里，两边都被污染。

## 目标

三条来源、三种默认目录，互不串味：

| 入口 | 默认 cwd |
| --- | --- |
| 数字专家「开始会话」 | 该专家的 `workdir`（+ `expertId`） |
| 侧边栏「项目」行 | 该项目的 cwd |
| 「新对话」（侧栏按钮 / 折叠态按钮 / 文件菜单） | **一个新建的空目录** |

## 方案

### 1. 新对话拿一个新工作目录

新增 Rust 命令 `create_workspace`（`src-tauri/src/workspace.rs`），在
`~/.kalo/workspaces/` 下给出一个可用的空目录：

- 目录名是 `chat-<n>`，`n` 取现有最大序号 + 1。**不用时间戳**：本地时区与 UTC 的差会让
  文件夹名和用户的"今天"错开，序号没有这个问题，且排序/测试都确定。
- **空目录复用**：若已存在的 `chat-<n>` 里什么都没有（用户点了新对话但没真正用），
  直接返回最新的那个，不再新建。连点五次「新对话」不会留下五个空壳。
- 会话历史本身写在 `~/.kalo/sessions/`，不在 cwd 里，所以"没用过"就是"目录为空"。

契约（`pi-bridge.ts` ↔ `main.rs`）：

```
create_workspace {} -> string   // 绝对路径
```

前端 `src/lib/fresh-chat.ts` 是唯一入口：

```
startFreshChat() = create_workspace() → chatStore.newChat({ cwd })
```

失败（比如家目录不可写）时降级为旧行为（`newChat()` 继承）并弹一条 warning，
而不是让「新对话」按钮点了没反应。

### 2. 各入口显式传 cwd，不再靠继承

- `App.tsx` 的 `onNewChat` → `startFreshChat()`。
- `App.tsx` 新增 `onNewChatIn(cwd)`，侧边栏「项目」行用它：原来是
  `onNewChat()` + `setCwd(cwd)`（先继承一个目录再改掉），现在一步 `newChat({ cwd })`。
- 「数字专家 → 开始会话」不变（本来就传 `cwd: workdir` + `expertId`）。
- 「数字专家 → 新建专家」走 `startFreshChat()`：expert-designer 会自己规划并创建专家目录，
  它不该在上一个项目里开工。
- era 面板 / 向导保持 `newChat()` + `setCwd(workspace)`：它们要的就是把实验目录记成
  `lastCwd`。

`chat-store.ts` 的 `newChat` 逻辑不动（该文件已超行数预算，只许缩）：所有调用方都显式给
cwd，继承分支只剩内部兜底（`closeSessionFile` 关掉当前会话后的兜底新对话）。

## 影响面

- 新增：`kalo-desktop/src-tauri/src/workspace.rs`、`kalo-desktop/src/lib/fresh-chat.ts`
- 改动：`main.rs`（注册命令）、`pi-bridge.ts`（契约）、`App.tsx`、`Sidebar.tsx`、
  `features/experts/ExpertsPanel.tsx`
- 新的用户数据目录：`~/.kalo/workspaces/`（已加入根 AGENTS.md 的数据目录清单）
- 验证：`cargo test`（workspace.rs 的复用/递增逻辑就近单测）+ 人工确认三个入口的目录标签
  （输入框页脚的目录芯片）。
