# 会话文件诊断定位

日期：2026-09-09
状态：方案（本次实现）

## 背景

上下文压缩后的异常需要直接检查 harness 保存的原始会话 JSONL。桌面端侧边栏已经从 `list_sessions` 获得每个历史会话的真实文件路径，但现有会话右键菜单只支持打开项目目录，诊断时还需要手动进入 `~/.kalo/agent/sessions/` 查找文件。

## 目标

在侧边栏会话行的右键菜单和「更多操作」菜单中增加：

- **定位引擎会话文件**：调用既有 `open_path { path, reveal: true }`，由 Windows 资源管理器选中该 JSONL 文件。
- **复制引擎会话路径**：复制同一个真实路径，便于在编辑器、终端或其他工具中打开检查。

待生成文件的乐观会话没有可定位的历史文件，因此不显示这两个动作。

## 契约与数据流

`SessionRow.path` 来源于 Rust `list_sessions` 返回的 `SessionSummary.path`，对应 harness `~/.kalo/agent/sessions/<编码工作目录>/<时间戳>_<session-id>.jsonl`。前端复用 `src/lib/pi-bridge.ts` 的 `openPath(path, true)` 和共享菜单工厂 `openPathItem`、`copyPathItem`，不新增 sidecar RPC，也不改 harness 会话格式。

Windows 下 `open_path(..., true)` 使用资源管理器的选择文件行为；路径不存在或打开失败时沿用现有 toast 错误提示。会话重命名、项目目录定位、删除确认及两个菜单入口共用一份菜单项，行为保持一致。

## 非目标

- 不在桌面端解析或修复压缩后的 `messages` 内容。
- 不改变会话分页、压缩逻辑或 JSONL 写入方式。
- 不为尚未落盘的 pending 会话伪造文件路径。

## 验证

执行桌面端 TypeScript 类型检查，并人工确认历史会话右键菜单和「更多操作」都能打开资源管理器并选中同一 JSONL 文件；pending 会话不显示定位与复制文件路径动作。
