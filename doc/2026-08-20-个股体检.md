# 个股体检：把一份人写的清单变成可核对的事实 JSON

起点是一份在网上流传的「个股分析框架」——三大类 15 项：风险排查、健康度度量、
催化契机。它写得很具体（"MACD 红柱近 3 天是否持续变长"），但它是**给人看的提问
清单**，不是能执行的东西。这一期做的事情就一句话：**把这 15 项逐条落到
`market-data` 的取数层上，让每一项都有一个可核对的数字，判断规则留在 SKILL.md 里
由模型执行。**

上一期（`2026-08-20-market-data-framework.md`）已经把底座立起来了：源注册表、
重试退避、磁盘缓存、`metrics.py` 纯函数、`macro append` 的零 token 契约。这一期
是在同一个底座上加个股这条线，**没有新造任何机制**。

## 几个决定

### 判断规则一行都不进代码

`checkup()` 里没有一个 `if ratio > 30: return "危险"`。输出的每一项都是数值或原文：
质押 0.04%、`recovery_pct` 46.7、公告标题「贵州茅台2026年半年度报告」。
「30% 算不算高」写在 `stock-checkup/SKILL.md` 的判据表里。

理由和上一期的宏观线一样，但个股这边更明显：**阈值是会变的、是有争议的、是要
因股而异的**（题材股的 BIAS 容忍度和白马股不是一回事）。写进 Python 就等于把一份
可讨论的判据焊死成不可讨论的行为，而且改一次要改代码。写在 SKILL.md 里，用户自己
就能改，模型也能在数值贴边界时说"接近"而不是硬套。

这条线同时还是 token 边界：取数与计算零 token，只有解读才动模型。

### 涨停从日线推，不另找源

没找到可靠的"个股历史涨停"接口，但涨停这件事本身可以从日线判出来：涨幅贴着交易所
限制。阈值按板块分（30/688 开头是 20%，其余 10%），留 0.3 个点余量——**涨停价按
四舍五入到分**，实际涨幅常是 9.98% 或 10.03%，卡死 10% 会漏。

同时给出当天的 `vol_ratio_ma5`（量比）和 `next_day_chg_pct`（次日涨跌），
但**不判断"这个涨停健不健康"**——那是 SKILL.md 的活。

### 回撤必须只算高点右侧

写单测时发现的真 bug：原来的 `drawdown_rebound` 是在窗口里各自找最高价和最低价，
低点出现在高点之前时（50 → 100 → 75 这种上升途中回调的形态），算出来是
「从 100 跌了 50%」——**那 50% 的跌幅根本没发生过**。

改成先定 peak，再在其右侧找 trough。`shape` 也从两态改成三态：`up`（高点就是最后
一根，还在创新高）/ `down`（低点就是最后一根，还在跌）/ `down_then_up`（跌完在
反弹，也就是清单担心的解套盘压力形态）。

这类错误正是"合成序列单测"该抓的：联网数据上跑一百次也未必凑巧撞上这个形态。

### 日线走腾讯的前复权

push2his 实测反复整体限流，而腾讯 `web.ifzq.gtimg.cn` 在同一时刻正常。更关键的是
腾讯这条能给**前复权（qfq）**：不复权序列在分红除权处会造出假跳空，MA/MACD/RSI
全废。新浪那条只有不复权，只能当备份。

对个股体检来说，前复权不是可选项——这份清单一半的项都建立在均线和 MACD 上。

### 缓存按代码分开

`fetch.py` 原来的缓存键就是源 id，宏观源没问题（一条源一个值）。个股源必须加代码：
否则查完茅台再查平安，读到的是茅台的 K 线，而且**不会报错**——这是最坏的一类 bug。

```python
def _cache_key(src, params):
    code = (params or {}).get("code")
    return f"{src.id}-{code}" if code else src.id
```

### probe 要能自检个股源

个股源的 URL 带 `{code}` 之类的占位符，`md.py probe` 不给参数就会打出一条含大括号
的废 URL，看起来像源坏了。所以每条个股源必须写 `probe_with: { code: "..." }`。

样本代码要挑**真有数据的那只**：解禁源用茅台会返回 `9201 返回数据为空`（茅台早已
全流通，没有解禁记录），看起来像挂了，所以那条填的是中芯国际 688981。这是"源坏了"
与"这只票没这项记录"两种情况必须能区分开。

## 实测得来的坑

选源全部按框架自己的规矩来：先在这台机器上裸取到，再写进 `sources.yaml` 并留下
`verified_at` 与 `verified_sample`。过程中撞到的：

- **东财报表名猜不得，但猜错有明确反馈**。质押试了四个想当然的名字全部
  `9501 报表配置不存在`，最后是去 akshare 装好的源码里 grep 出真名 `RPT_CSDC_LIST`。
  `9501`（报表不存在）与 `9201`（报表活着但没数据）是两回事，反馈清晰反而是好事。
- **`RPT_SHARE_HOLDER_INCREASE` 的排序列只能用 `NOTICE_DATE`**，
  `CHANGE_END_DATE` 会明确报「排序列不存在」。
- **F10 概念板块必须 `source=HSF10&client=PC`**，用 `WEB/WEB` 返回 9201；
  且报表名是 `RPT_F10_CORETHEME_BOARDTYPE`，`..._CONCEPT` 不存在。
- **`akshare.stock_gpzy_pledge_ratio_em` 已坏**（`TypeError: 'NoneType' object is
  not subscriptable`），直接打接口。
- **push2his 的限流是断续的**：写这份文档的当天，个股资金流先是取不到、几小时后
  又恢复了。所以它仍然注册着，限流时进 `errors[]`，恢复后自动可用——资金流没有
  可靠替代源，宁可缺一格也不换个口径凑数。

## 验证

- `md.py probe` → **19/19 条源可用**（10 条宏观 + 9 条个股）。
- `pytest tests/` → 29 passed，其中 9 个是这期新加的形态类单测（均线排列、回撤形态、
  K 线形态、滞涨），全部用合成序列与手算对照，不联网。
- `md.py stock checkup 600519` → 7.6 KB，三大类齐全，`errors` 为空。
- `md.py stock checkup 300750` → 识别出 20% 涨跌停板；资金流限流时落进 `errors[]`
  而其余照常返回。

## 不做

- **仍然零 TS / Rust 改动**：这一期只加了 skill 与脚本。
- **不做实时盘中监控、不做图表、不做回测**。
- **不给投资建议、不自动下单**——SKILL.md 里写死了收尾那句"这是事实体检，不构成
  投资建议"。
