# 投行：Rust 架构与回测交互

日期：2026-11-03。状态：首条真实数据与 Rust 回测路径已实现，其余为后续设计。本文替代 2026-11-02 方案中的 Python 回测、gateway 业务服务和默认 DuckDB 选型；免费数据优先、份额口径、历史可用时间及不可变实验原则继续适用。

## 产品与工作流

模块名称统一为「投行」，顶部、主导航、第二列和助手同步命名；技术标识 `quant` 暂保留，不做无收益的数据路径迁移。现有工作空间只在首页显示。投行第二列为：决策台、ETF 资金、行情研究、策略回测、数据中心；自选池和策略列表留在其下方。助手默认折叠。

首版服务研究员和个人投资者的盘后研究：发现资金变化 → 判断是否值得研究 → 查看价格与数据证据 → 编写可检验规则 → 回测与反证 → 人工判断是否观察。产品不将“收益高”自动转成“推荐买入”。

## 投资人员视角走查与界面要求

以下为设计者的角色模拟，不是投资人员访谈或真实可用性实验。每个页面必须回答一个问题并提供可执行下一步，不能以指标数量代替有用性。

| 页面 | 使用者要作的决定 | 必须可见 | 主要动作 | 空、错与陈旧状态 |
| --- | --- | --- | --- | --- |
| 决策台 | 今天先处理什么？ | 待审阅实验、数据阻塞、策略失效；所属日期与影响范围 | 继续研究、审阅报告、处理数据 | 没有变化则显示上次检查时间，不生成虚构线索 |
| ETF 资金 | 哪个变化值得进一步研究？ | 净申购金额、占期初规模比例、份额变化、分类、价格涨跌和窗口完整性 | 切换金额/比例排序、查看证据、加入研究 | 缺失标的不按零排名，显示排除数量；不同所属日不混榜 |
| 行情研究 | 资金变化与价格发生在什么时点？ | 价格、成交量、份额/流量、净值日期、复权方式、信号实际可用时间 | 定位异常日期、核验事件、带标的与区间创建策略 | 不足窗口禁止指标；缺口断线，不画成平盘 |
| 策略回测 | 规则能否执行、收益是否经得起检验？ | 可编辑策略规格、运行前检查、样本外、基准、成本、拒单、版本 | 校验、运行、取消、对比、记录结论 | 缺失关键数据阻止运行并给补齐入口；旧报告标注对应旧版本 |
| 数据中心 | 哪项缺口影响我的研究？ | 数据集覆盖、更新、缺口、来源、权限与受影响策略 | 补齐、重试、导入、切换来源 | 保存失败原因和上次成功时间；不把 HTTP 成功当作数据完整 |
| 投行助手 | 下一步要验证什么？ | 当前对象、证据链接、可执行动作、反证 | 生成草案、检查数据、比较实验 | 无证据时说明缺口，不编写业绩；操作结果落到同一对象 |

设计走查发现及修正：资金金额榜偏向大基金，增加规模归一化排序；原回测只有收益曲线，增加规则、可用时间、成交和反证；运行按钮缺少阻塞说明，增加前置校验；更换参数容易误读旧报告，报告固定规格摘要；观察不能等同上线，显示通知条件与暂停入口。界面避免展示 Rust、crate、线程等实现信息。

## 回测界面详细交互

「策略回测」是单一入口，内部按任务阶段组织，不再添加一层全局导航。

1. 策略配置：选择价格动量/资金过滤模板，选择证券池、动量窗口、资金窗口、持仓数量、权重与调仓频率。基本参数默认展开，费用与成交假设折叠但运行摘要始终显示。自然语言生成的值必须能逐项查看和修改。
2. 实验设置：起止日期、预热窗口、初始资金、基准、训练/验证/样本外时段、佣金最低额、滑点、参与率、数据时间模式。基准使用相同区间、币种和公司行为口径，明确是否含交易成本。
3. 数据校验：分别列出行情、份额、净值、历史池、公司行为、交易规则、发布时间的覆盖。分为通过、带假设可研究、阻止运行；严格模式不允许跳过发布时间/历史版本缺口。按需列出受影响日期与标的，按钮跳到对应缺口。
4. 创建运行：保存不可变策略版本和数据快照，返回 run_id，进入排队/读取/校验/撮合/统计阶段。保留已处理交易日、总交易日、耗时、取消动作；未知耗时不显示伪造剩余时间。
5. 报告：概览、成交与持仓、稳健性、数据证据。概览展示成本后净值、基准、回撤与水下期；指标有区间及年化口径。成交可定位下单、成交/拒绝原因、费用和资金余额；拒单不能从交易表消失。
6. 对比：相同快照、区间、基准与费用下比较纯价格基线和资金过滤；不同条件显示差异，不排名为“最好”。压力测试包括信号延迟、成本提高、窗口扰动和滚动样本外，必须重新计算。
7. 结论：保留假设是否获得支持、失效情形、待补数据和观察条件。观察操作独立于回测成功；可暂停，默认只在变化和异常时通知。

原型只使用两份固定预置报告，不提供会使预置结果看起来随任意参数重新计算的控件。可体验模板切换、运行前检查、真实数据阻塞、报告分区、实验对比和观察入口；生产版才开放完整参数表单与真正计算。示例成交明细只用于展示字段，不宣称能重建预置曲线。

## Rust 优先的技术决策

现有 Cargo.toml 直接依赖 Tauri 2、serde/serde_json、sha2、uuid、fs2 等，当前没有直接声明 reqwest、rusqlite、rust_decimal、Parquet 或量化内核。下表明确区分复用与拟新增，具体版本经过双平台构建后锁入 Cargo.lock。

| 层 | 选择 | 边界 |
| --- | --- | --- |
| UI | 复用 React + TypeScript + Tauri | 前端负责展示/参数录入，收益和账本不在浏览器重算 |
| 桥接 | 复用 pi-bridge、Rust gateway 通道 | UI 和 Agent 汇入相同命令，不散落 invoke |
| 业务与计算 | 新增 Rust investment-core 库 | 主数据、校验、因子、撮合、账本、统计；不依赖 Tauri/网络/UI |
| 隔离运行 | 新增 Rust investment-worker 可执行文件 | 数据服务与回测运行模式分离；计算退出不拖垮桌面进程 |
| 网络 | 拟新增 reqwest + rustls，按异步需要显式声明 Tokio | 限频、超时、重试、代理、取消；不因 Tauri 间接依赖而省略显式依赖 |
| 元信息 | 拟新增 rusqlite，评估 bundled 构建 | 数据服务独占写入，保存策略、运行及快照目录；只读查询经服务返回 |
| 历史数据 | Apache Arrow Rust 的 Parquet crate | 不可变分区、冻结 manifest；首版直接读必要列，不默认再装 DuckDB/Polars |
| 精确账本 | rust_decimal，序列化为十进制字符串 | 金额、数量、费用使用显式精度和舍入规则；统计用 f64，拒绝 NaN/无穷值 |
| 图表 | Lightweight Charts + ECharts | 延续前案，分别承担 K 线与分析图；图表不包含数据权限 |
| 调度 | 复用 gateway Job Runtime | TS 只做命令路由与任务生命周期；不复制 Rust 策略和收益计算 |
| 免费源兼容 | 现有 Python/AKShare 可选采集适配器 | 仅取数转标准批次；Rust 负责校验、入库和计算；不成为回测运行依赖 |

优先使用有明确字段契约的 HTTP 数据源由 Rust 直连。免费网页源在 Rust 适配器验收前，允许调用已有 AKShare 采集器；缺少 Python 时明确禁用该适配器，并保留 HTTP/CSV 路径。不能宣称 AKShare 是 Rust 库，也不为了“纯 Rust”立即重写所有脆弱网页抓取。

## 模块和通信

拟议目录：`kalo-desktop/investment-core/` 放纯 Rust 库，按 instrument/data/strategy/execution/ledger/metrics/report 拆分；`kalo-desktop/investment-worker/` 放进程入口、供应商、存储和运行适配；`src-tauri/src/investment/` 仅桥接与状态转发；`src/features/investment/` 放视图、表单和对象状态。发布脚本使用现有 target triple 命名机制定位 worker；资源走 resources.rs，数据根由现有数据管理模块统一解析。

统一路径：UI → pi-bridge → Tauri → gateway；Agent 内置工具 → gateway。gateway 内的薄 InvestmentAdapter 将请求送给 Rust 数据服务，或经 Job Runtime 启动 Rust 回测进程。数据服务是目录唯一写入者；运行进程只读快照，写自己的临时成果，由服务验证后登记。gateway 不直接打开数据目录数据库。

命令草案：`investment.catalog / sync / bars / flows / strategy.validate / strategy.save / backtest.preflight / backtest.start / backtest.status / backtest.cancel / report.read / watch.upsert / watch.pause`。外层沿用现有 requestId 关联，payload 带 schemaVersion；不能把已有 job_start 直接宣称为新协议已支持。

运行参数为 strategyVersionId、snapshotId、experimentSpec、idempotencyKey；事件为 runId、attempt、seq、phase、processedDays、totalDays、status。错误包含稳定 code、用户说明、可重试性和受影响字段/日期。事件去重只影响 UI，持久化状态为最终依据；进度可以重读恢复，不靠聊天文本推断。

回测子进程标准输入/输出使用有长度限制的逐行 JSON，日志走标准错误，大表返回受控产物引用。取消先协作通知并在每交易日检查，超时由现有进程树机制终止。终态按 attempt 比较并只提交一次；已完成报告不能被迟到取消覆盖，取消运行不能被迟到进度改回成功。进程异常标记失败或中断，首版从冻结输入重跑新 attempt，不承诺尚未实现的中途账本恢复。

## 日线回测内核

首版限定境内股票 ETF、多头、现金账户，无杠杆和开放代码。用可序列化的策略规格和有限算子表达规则。提供 BacktestEngine trait；可替换实现，但第一版以 Rust 确定性逐日事件循环为准。

每交易日依次：处理生效公司行为与可卖数量 → 执行此前已提交且当时数据可用的订单 → 扣费并更新现金/持仓 → 收盘估值 → 更新当时已发布的指标 → 若到调仓时点产生下一可交易时点的订单。排序并列时按稳定 instrument_id 决定，先卖后买、余额不足按明确规则缩减；不能因线程完成先后改变成交顺序。

执行价使用未复权价格并按买卖方向计入滑点，成交数量符合证券单位，费用按账户合同及生效日期处理。日线参与率只能是粗粒度容量假设，不能代表开盘时已知全日成交量；若用当日总量限制模拟成交，报告必须标为事后容量近似，并做更保守场景验证。信号不得使用当日成交量作盘前决策。

账本分离：现金、持仓数量、可卖数量、公司行为、订单、成交和费用。分红/拆分按明确生效和现金到账日处理；未支持事件出现时阻止受影响区间，不忽略事件。价格缺失不生成买卖；已有仓位缺失估值时标记陈旧估值，超过允许范围报告不完整。

输出 daily_equity、drawdown、positions、orders、fills、fees、rejections、metrics 和 provenance，所有表属于同一 run。期末净资产等于现金加持仓估值；收益、回撤从净值序列计算，费用可从成交逐笔核对；无波动或样本太短时 Sharpe 返回不可计算及原因。

## 交付顺序与验收

### 首条生产路径实施契约（2026-11-03）

新增独立 crate investment-core，纯撮合与数据/文件适配分模块，附独立 CLI。桌面通过 pi-bridge 的 investment_start/status/cancel/catalog 调用 Rust；后台以当前应用可执行文件的 `--investment-worker` 模式运行隔离进程，复用现有隐藏窗口、终止进程树和应用数据目录解析，无额外 Python 依赖。首阶段不改 Agent sidecar 协议，Agent 工具与 gateway 自动调度是后续接入项。

初始范围为 510300/510500/512100 三只沪市宽基 ETF 的近期日线，采用不可变 JSON 快照/报告及 UUID、哈希契约；扩大数据量后再替换为 Parquet/SQLite。成功报告落盘，重启可读取；运行中可取消，退出终止进程。免费源为腾讯公开原始/前复权日线、上交所份额、东方财富基金净值。排除当日未最终完成的日线，保存原响应与抓取时间；失败显示缺口，不写演示数据。

回测先提供固定池研究：上一日信号、下一日开盘成交、现金/整手/费用/滑点、价格动量与可用资金过滤。资金过滤必须使用在决策前实际观察到的完整份额数据，刚下载的历史不得冒充当时已知；不足阻止运行。份额按交易日差分，净值日期不齐则不计算净流量。原始与复权序列比率变化用于阻止疑似公司行为区间，此检测不能替代完整事件和历史版本认证，报告明确保留研究局限。不宣称精确开盘容量或全市场无偏回测。

1. 本轮：更新设计与交互原型，逐页进行角色走查；不将预置报告称为真实回测。
2. Rust 纵向样本：先读固定 CSV/Parquet，执行买入持有和简单轮动，输出账本与报告。无网络、无模型也能完整运行。
3. 数据接入：免费源抽样验证、每日份额积累、数据健康页；随后评估付费补全，不把免费历史缺口留给策略猜测。
4. UI/Agent 接入：相同规格触发同一运行，支持取消、重新打开、结果比对和观察。

纯 Rust 核心必须测试：现金守恒、费用最低额、份额拆分、分红到账、可卖数量、涨跌限制/停牌、价格缺失、排序并列、同日信号不可同收盘成交、净值与收益一致、时间过滤、数据修订冻结、取消终态。手算小样本用于验算；基准买入持有作为独立公式核对，不只验证实现自己的输出。双平台读取同一快照应得到相同账本；统计允许明确浮点误差。

界面验收：五页可达、切换保留研究对象、侧栏收起仍能导航；空数据、过期、缺口和取消均有下一步；样本外与样本内不混淆；参数变更不覆盖旧报告；窄屏不产生页面横向溢出。角色模拟与浏览器检查只能证明交互可达，真实用户价值需后续实际研究任务验证。

文档影响为 improve + create：原总体方案同步更名并收敛到本次 Rust 决策，本文件承载新的具体执行契约与逐页验收；不修改既有金融技能、纸交易账本或用户数据。

前期原型验证记录：五页导航、首页/投行切换、侧栏折叠、日/周 K 线、资金窗口和规模比例排序、两种策略案例、报告四分区、真实数据未就绪阻塞、观察加入/暂停均通过；320、736、1024 像素内容宽度未出现页面级横向溢出，未发现脚本运行错误。已检查回测页截图。此次仅修改设计文档、索引及会话原型，未修改生产 Rust/TS，未执行生产编译或真实市场回测。

## 生产落地记录

### Agent 工具接入契约（2026-11-03）

投行新增可展开的「研究助手」，复用当前会话的 ChatView、模型选择、审批、提问与停止能力。助手与聊天页使用同一会话，面板明确显示这一点；快捷示例发送带当前快照 ID 的自然语言请求。聊天中的投行请求也使用相同工具，返回面板时恢复最近任务和目标结果。桌面启动会话时建立投行连接，已有旧引擎会话需重启后获得新增工具。

引擎新增内置 investment 扩展，提供 investment_catalog、investment_sync、investment_flows、investment_backtest、investment_status、investment_cancel 六个工具。catalog 返回数据覆盖、完整默认回测规格、报告摘要；sync/backtest 返回真实运行 ID 并有界等待终态，等待超时只返回仍在运行，不伪称完成。flows 按指定快照和 1/5/20 交易日生成有日期、完整度、缺失日、净申购估算和排名的确定性结果；缺口不补零，也不将份额资金称为二级市场主力买卖。backtest 必须传完整规格，默认规格来自 catalog，不能静默改变用户要求或省略费用。

桌面为每个有人值守的引擎会话创建一个仅监听 127.0.0.1 随机端口的 NDJSON 连接，端口和随机令牌通过子进程环境 KALO_INVESTMENT_PORT / KALO_INVESTMENT_TOKEN 传递，不落配置、不写聊天记录。无人值守和子任务不授予连接。请求为 `{version:1,id,token,command:{operation,...}}`；响应为 `{version:1,id,ok,result?,error?}`，一连接一请求，请求上限 64 KiB、响应上限 16 MiB、读取/写入超时 10 秒，拒绝未知字段、版本和令牌。连接随会话退出撤销，异常不能占住桌面 UI。传输只接受结构化操作，不接受任意路径、URL、命令或代码。

连接调用与 Tauri 按钮共用 InvestmentManager 的 start/status/cancel/catalog 服务和同一互斥运行槽。任务记录来源会话；Agent 只能读取/取消自己启动的活动任务，桌面操作者可取消任一投行任务。开始请求带 requestId 幂等键；同一会话重发相同键及相同规格返回原任务，不重复计算，键复用不同规格报错。会话停止工具时发送取消；若启动响应中断无法确认，错误必须保留可追踪请求 ID，禁止盲目重复启动。所有工具遵循维护模式。只读权限允许查询与资金分析，同步和回测须走已有写操作审批。

面板通过 investment_activity 获取递增 revision、来源、任务状态与目标视图。开始任务、成功提交、失败、取消和资金分析均更新状态；面板按 revision 更新，不依赖模型输出文本，也不在每次轮询抢走用户手动选择。页面卸载后任务继续，重进可恢复；报告仍以冻结快照落盘。资金分析选中对应窗口/快照，回测完成选中对应报告，错误在面板和工具结果两处可见。研究助手中的模型解读与数据表并列呈现。

验证包括资金缺口与排名、请求校验/幂等/归属、客户端分帧/错误/取消、模型工具注册与调用链、面板恢复与定位；使用本地测试代理驱动真实工具和 Rust 服务，不调用付费模型。Windows 构建及 sidecar 更新后才能视为当前桌面可运行，macOS 仅做平台中立代码评估，实机状态单列。

### Agent 接入落地与验收记录

本轮原生桌面验收补充：使用独立用户数据目录和现有模型配置，从窗口中的研究助手提交自然语言任务，核对同步、资金分析、回测、报告及停止行为；只提交投行功能自己的文件/变更块。投行数据根改为复用数据管理模块公开的根目录解析接口，避免依赖尚未提交的数据迁移模块，保证独立分支可构建且与当前工作区目录选择一致。
