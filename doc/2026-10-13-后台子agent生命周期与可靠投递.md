## 本期实现边界

采用引擎内运行管理器 + 每次运行独立持久记录 + 原会话完成通知。后台登记成功后立即返回 queued 的 childId/runId；queued、initializing、running 阶段的 resume 都追加到同一 pending entry，并复用同一 run，不创建第二个 run、监视器或并发槽位。主轮次自然结束后，子任务继续运行；主轮次停止不会连带取消已确认登记的后台子任务，显式取消走任务工具。应用或引擎进程退出会中断子任务；重新打开原会话后报告 interrupted 并提供 resume，不自动重放写操作。本期不引入独立常驻 worker，不承诺应用退出仍连续计算。

后台子任务不登记为 gateway command job；gateway 统一 job 尚未完成，本次不修改 `claimCompletions`，也不复用其先消费后投递流程。后续若统一 gateway job 列表，需另行实现租约领取、接收确认及 owner 路由，不得直接将当前 reported 布尔值用于可靠消息。

## 工具契约

- `agent(prompt, description?, tools?, resume?, run_in_background?)`：默认前台等待；后台先持久登记，立即返回 childId/runId，再排队执行。创建和续写均可后台化。
- tools 接受名称数组或逗号/空白分隔字符串，规范化后白名单校验；非法名称明确失败。初始工具权限持久化为同目录 `<childId>.tools.json`，并写入子会话 custom entry；恢复时沿用 sidecar metadata 持久化的权限，不从 resume 参数扩权。旧会话没有权限 metadata 时按 `[]` 恢复，不能执行工具，不回退到默认工具集；需要工具时必须新建子会话并显式赋予工具。
- `agent_tasks(action, run_id?)`：list 查看本会话任务；output 查看状态、结果、转录路径；cancel 取消指定运行。取消支持队列中任务；不同父会话互不可见。
- 稳定 childId 使用随机唯一后缀；新执行生成新 runId，旧子会话 ID 仍可恢复。
- 同一 child 的执行串行化。queued/initializing 阶段的 resume 直接进入原 entry 的追加队列，启动时消费；running 阶段追加 `followUp`，复用当前 run/runId，不创建新 run、运行监视器或并发槽，也不重复释放槽位。只有空闲 resident resume 才新建 run 并申请并发槽。
- 独立取消控制器归后台任务所有，不依赖已返回工具的 signal 和 onUpdate。

## 持久状态与完成投递

记录放在现有 `subagent/<parentSessionId>/` 目录内，使用平台无关 path/fs API 与临时文件 rename 写入。每次后台运行记录 owner、childId、runId、状态、描述、时间、结果与转录路径，工具权限单独存于 child 元数据；先登记后返回成功。运行记录与可读输出不依赖 gateway 是否在线。

状态为 queued/running/completed/failed/cancelled/interrupted。只要进程内运行仍存在，切换后重开原会话不判为 interrupted；进程重启后没有对应运行的 queued/running 转为 interrupted，不自行继续执行。

所有后台运行结果先落盘，并保持 pending，直到父会话成功处理并确认；后台登记工具已经返回也不能提前视为结果已确认。通知只绑定原 owner，自动投递在 busy 时使用 followUp、idle 时使用 triggerTurn。2026-10-24 修正：session_start 仅扫描、展示状态，不启动投递；恢复历史、重载和新建后的首次投递，等待明确的 interactive/rpc 输入。`input` 只 reset 通知预算，不发送通知或触发独立 turn；待后续 `before_agent_start` 注入 pending 通知，真实 user 消息进入 agent 后才允许自动投递。session_abort 立即暂停投递，后台完成不得再次唤醒停止的父会话，直到下一次明确输入。session_shutdown 解除通知绑定但不取消进程内后台执行；旧异步回调必须检查会话绑定有效性。未加载的原会话保留待投递，不投递给新会话，也不为非 active 父会话自动启动引擎。

每次用户输入最多允许 3 批通知，busy 也计一批；达到上限后停止自动投递，不做无限定时唤醒。每批最多 20 条结果，整批通知总长度不超过 12,000 字符；超限结果仍 pending，可由 `agent_tasks` 读取。ack 需要同时具备通知 custom message 已实际接收、后续 assistant 以严格的 `stopReason === "stop"` 成功结束（strict stop）与 `agent_settled`，此后才持久化 ack；仅 sendMessage、入队、收到消息、报错或 aborted 均不算成功确认。确认前崩溃允许重放同一 runId，提供至少一次投递语义，不承诺模型调用或副作用 exactly once。应用/引擎退出会中断运行；恢复只报告 interrupted/pending，不能自动重跑写操作。

owner 围栏限于单进程管理与原父会话绑定，不是跨进程锁或租约；不支持同一 session 由两个 engine 同时加载并写入。

## 桌面保活契约

复用现有 RPC `extension_ui_request` 的 `setStatus`：保留键 `kalo-subagent-background`，非空文本表示该引擎仍有排队/运行子任务或正在等待主会话接收的结果；空值表示释放保活。桌面 runtime 缓存此状态，普通 parked LRU 必须跳过有此标记的引擎。用户显式关闭会话或应用退出仍可终止引擎，下一次打开按 interrupted/待投递处理。

此协议不改 RPC 外层结构；Windows/macOS 共用同一状态与持久路径逻辑，不增加 detached 进程、shell 或信号差异。保活标记是生命周期提示，不当作主会话正在生成，避免输入队列/停止按钮语义混乱。

保活只保护已有引擎进程内的执行，不能让子 agent 在应用退出后存活。非 active 父会话已有引擎时可继续进程内工作；没有引擎时不自动开引擎。重新打开原会话恢复已落盘结果或报告 interrupted，不自动重跑任务；需要继续时显式 resume。

## 本次工具失败改进

bash 后台模式接受 timeout 缺省/null/0 表示无超时；正数超时继续明确拒绝，不忽略用户实际指定的时间限制。前台 timeout=0 仍非法。工具描述与测试同步。工具 tools 字符串按明确分隔符解析，拒绝未知名称，返回实际启用工具列表。空参数来源尚未定位，禁止据此加入命令长度截断或自动猜测参数。

schema 根因调查（截至本次文档同步）：本地 `astra` 的 `openai-completions` 请求发送 `strict:false`，且 timeout 是 optional；但本会话实际看到的模型工具 schema 将 timeout 表成 required number。代理最终下发给模型的 schema 尚未采集，因此责任方未证实，不能把参数变空或把 `timeout:0` 归咎于 provider、代理或模型中的任一方。`Record` 形态的空开放 object 在 strict 模式下仍有风险，尚未修复。`multi_tool_use` 不在本仓库，无法在仓库内追踪其 schema 或参数转换责任。

运行时修复边界：普通 bash 的后台 timeout 缺省/null/0 表示无超时，正数继续明确拒绝；前台 timeout=0 仍非法。该兼容修复不等于已经确认代理最终 schema。

## 子 agent 确定性工具失败循环保护

仅在子 agent 的 `runTurn` 内创建独立 `FailureGuard`，不注册主 agent 事件，不改主 agent 工具执行策略。每次显式 resume 开始新的计数预算，保护触发后不自动续跑。

- `tool_execution_start` 按调用 ID 保存工具名和参数指纹；参数递归排序对象键后计算哈希，保留数组顺序、值类型、字符串内容及字段缺省差异，不改写命令或路径。`tool_execution_end` 按 ID 和工具名配对，读取 `result.content` 的文本块与事件 `isError`，每个调用最多计数一次。参数摘要不写入用户提示，避免暴露命令内容。
- 只将明确的执行前错误纳入计数：`Validation failed for tool` 的 schema 拒绝格式、bash 后台与 timeout 互斥的固定错误、bash `Invalid timeout` 的固定范围/数值校验错误。普通 shell 非零退出、rg 无匹配、测试失败、真实执行超时、服务过载和正常重读均不计入。未知错误、成功回执及无法可信配对的结束事件中断连续序列并清零；其他模型/进度事件不改变计数。
- 以结束事件到达顺序判定连续：同工具、同规范化参数、同错误类别连续 3 次，或整个连续确定性失败序列达到 12 次即触发。后者覆盖交替工具、空参数和不同 timeout 参数绕开同形阈值的情况。
- 触发前同步锁定保护状态，再调用一次 `session.abort()`；同批并行任务后续完成事件不再触发。停止仍等待 `session.waitForIdle()`，保留实际完成的工具回执与历史转录；不承诺撤回同批已开始的副作用。
- `outcome.failed` 与转录结局写入错误类别、触发计数、停止原因和修改指令后显式 `agent(resume=childId, prompt=...)` 的提示。保护引起的 assistant aborted 不标为用户取消，后台沿现有 `failed` 结果持久化与通知路径处理；外部显式取消仍遵循原取消语义。通知仍由主进程的独立通知模块负责。

验证覆盖分类正反例、参数键顺序、三次同形阈值、十二次混合阈值、成功/未知错误清零、重复/缺失配对、并行批次只触发一次、恢复后预算重置、实际转录与后台失败状态，以及已落盘通知模块下的普通 wiring 专项命令。保护逻辑不依赖 shell、路径大小写或 OS 信号，Windows/macOS 使用相同规则。

## 排队与初始化阶段的 resume 合并

进程内以 owner + childId 建立唯一 pending entry，覆盖 queued、initializing、running 全阶段。后台登记返回前 entry 已存在，保存 runId、初始 tools、执行 signal、取消状态与追加指令队列；resume 先查 entry，再查 resident/session 文件。已有 child 的排队恢复同样复用 entry，追加调用不生成第二个 runId、不另申请槽位，也不能通过 tools 参数扩权。

初始化前收到的指令按接收顺序附在原 prompt 后，一次启动，保留原任务全文。运行期间 session 非 idle 时使用 followUp；prompt 预处理或结束边界尚 idle 时保留在 entry 队列，由同一执行器在当前 turn settle 后顺序消费，仍归同一 runId，不并发创建监视器。取消或执行失败不自动消费余下指令，提示查询原运行结果。

正常执行由 entry 拥有者 finally 清理；后台管理器可能在调用执行器前取消或拒绝运行，这一路径由该 entry 的终态订阅清理。清理后持久运行记录仍可查询。取消期间拒绝追加；从未创建 resident/session 的 child 取消或初始化失败后不能 resume，返回明确的无可恢复历史错误及原 runId，不推测权限或自动新建。追加队列是进程内状态，进程退出不自动重放。
