# 自动压缩气泡常驻与摘要展开

**日期**: 2026-09-09
**影响范围**: `kalo-desktop/src-tauri/src/session_paging.rs`、`kalo-desktop/src/types.ts`、`kalo-desktop/src/lib/timeline.ts`（新建）、`kalo-desktop/src/lib/compaction-entries.ts`（新建）、`kalo-desktop/src/lib/chat-store.ts`、`kalo-desktop/src/components/CompactionBubble.tsx`（新建）、`kalo-desktop/src/components/MessageList.tsx`

**动机**: 自动压缩发生后，时间线上只留下运行期临时文案，继续对话后往回看找不到压缩痕迹；希望每次压缩在时间线上留一个常驻气泡，点击可向下展开压缩摘要。

---

## 背景

用户反馈：自动压缩后继续输出文本与工具调用，往回看时看不到自动压缩的气泡；期望气泡一直显示，且点击气泡能向下展开压缩摘要文本。

## 现状与根因

现状有两个独立问题：

1. **live 视角的压缩痕迹是临时 notice，且从不带摘要。**
   `chat-store.ts` 在收到 `compaction_start` 时往 timeline 追加 notice「正在压缩上下文…」，`compaction_end` 时原位改成「上下文已压缩」。引擎事件里其实携带完整摘要（`compaction_end.result.summary`，由 LLM 生成的结构化摘要 + 文件操作清单），但桌面端丢弃了 `result`。这类 notice 只存在于运行期内存：引擎重启、会话被回收后重开、或翻页到历史区（从文件重建 timeline）时全部消失。

2. **历史分页器把「链条节点」与「可渲染消息」混为一谈，导致压缩点前后的历史整体截断。**
   引擎把每次压缩写成一个 `{"type":"compaction", ..., "summary": ..., "tokensBefore": ...}` 条目，**插入** parent 链中间（后续消息的 `parentId` 指向该压缩节点）。而 `session_paging.rs` 只把 `type="message"` 的条目收进 `by_id` 参与 branch 行走：
   - 行走遇到压缩节点时查不到父节点，链条在此断裂；
   - 断点之前的全部消息都不可见，历史被截断到最近一次压缩之后；
   - 压缩摘要永远不出现在历史里。
   `session_info`（桌面重命名会话时追加、同样带 `parentId` 且推进 leaf）也属于链节点，续聊后再回看同样会截断。

根因是分页器没有忠实表达文件的 parent 链语义：**凡是带 `id`+`parentId` 的条目都是链节点**（引擎追加、桌面重命名均如此），可渲染的只是其中一部分。

## 目标

- 每次压缩在时间线留下一个**常驻气泡**：live 与历史回看（重开会话、翻更早页面、引擎恢复）表现一致。
- 气泡默认收起，点击后**向下展开**压缩摘要文本，再点收起。
- 顺带修复历史截断：链上出现任意非消息节点（压缩、重命名、模型切换等）不再截断链条。

## 方案

引擎侧不改（压缩事件与 session 文件结构已具备能力），全部改动在桌面端。

### 1. 历史分页器忠实行走 parent 链（Rust）

`session_paging.rs` 调整：

- 扫描阶段不再按 `type == "message"` 过滤，而是把**所有带 `id`+`parentId` 的条目**（message / compaction / session_info / model_change …）都登记为链节点；`message` 行额外借用其 message 载荷（延续现在「窗口外的行不建 DOM」的借用策略，只多存整行字符串切片，不解析）。
- 从文件最后一个链节点起沿 `parentId` 回溯行走（visited 集合防环），得到完整分支。
- 窗口 `[start, end)` 输出时：
  - `message` 节点 → 原样输出消息载荷（现状）；
  - `compaction` 节点 → 合成一条消息载荷 `{"role":"compactionSummary","summary":…,"tokensBefore":…}` 输出（引擎已有同形态消息类型；时间戳省略，顺序由数组位置表达，见备注）；
  - 其它类型节点只作连接，不输出。
- 窗口与分页下标（`total`/`start`/`hasMore`）按**可渲染条目**（消息 + 压缩）计数，与客户端既有语义一致；链条行走内部才包含全部节点类型，连接节点不会泄漏给客户端。

### 2. 消息与时间线类型扩展（TS）

- `types.ts`：新增 `CompactionSummaryMessage`（`role: "compactionSummary"`，`summary`、可选 `tokensBefore`），并入 `AgentMessage` 联合。这是对引擎同名消息类型的镜像（桌面分页器合成的形态）。
- 新建 `src/lib/timeline.ts`：把 `chat-store.ts` 里散落的 timeline 视图类型收拢过来（`UserEntry`/`AssistantEntry`/`ToolGroupEntry`/`RetryEntry`/`NoticeEntry`/`ChangesEntry`/`ToolCallRecord`/`TurnUsage`/`TodoItem`/`TimelineEntry`），并新增
  `CompactionEntry { id, kind:"compaction", summary, auto, tokensBefore? }`（`auto`：live 下由事件的 `reason != "manual"` 判定；历史恢复因文件字段不可靠一律 `false`，见备注）。
  `chat-store.ts` 已超行数上限，类型外移同时为其腾出增长空间。

### 3. live 事件落常驻气泡（chat-store + 新纯逻辑模块）

新建 `src/lib/compaction-entries.ts`（纯函数，可单测），提供：

- `pushCompactingNotice(timeline, id)`：开始压缩时追加 notice；
- `settleCompaction(timeline, noticeId, end, nextId)`：压缩结束时把 notice **原位替换**为 `CompactionEntry` 气泡（成功且有摘要时）；失败/取消/无摘要则按现状更新 notice 文案。

`chat-store.ts` 的两个事件分支瘦身为对这两个函数的调用；`compaction_end` 把 `ev.result.summary` 传进气泡。

### 4. 气泡组件与渲染

新建 `components/CompactionBubble.tsx`：

- 居中胶囊样式（与压缩 notice 的位置一致，视觉上是一枚小气泡），标题文案：`auto ? "上下文已自动压缩" : "上下文已压缩"`，带展开/收起箭头；
- 点击后向下展开：摘要文本用现有 `MarkdownBlock` 渲染（压缩摘要是结构化 markdown），面板限高可滚动，再点收起（展开态为组件本地状态，与用户气泡折叠的既有约定一致）。

`MessageList.tsx` 的 `TimelineItem` 增加 `case "compaction"`。

### 5. 数据流总览

```
引擎压缩（手动/自动）── compaction_start/end 事件 ──▶ live: notice → 原位换成 CompactionEntry 气泡
引擎把压缩写入 session 文件（compaction 链节点）
重开/翻历史 ── read_session_page ──▶ Rust 合成 compactionSummary 消息 ──▶ buildTimeline ──▶ 同款气泡
```

- 检查：`npx tsc --noEmit`、`npm test`、`cargo check`/`cargo test`、根目录机器检查。

## 备注

- 引擎 session 文件的 `fromHook` 字段当前实际写入的是「是否由扩展提供摘要」（fromExtension），不代表自动/手动；因此**历史恢复的气泡一律中性标题**，不做自动/手动标注；live 路径用事件 `reason` 精确标注。
- 合成的 `compactionSummary` 消息不携带 `timestamp`：历史顺序由数组位置表达，桌面端渲染不需要时间戳。桌面类型中该字段为可选。
- 引擎侧零改动：无需重建 sidecar。
