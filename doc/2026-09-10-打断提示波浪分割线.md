# 打断提示改为波浪分割线

## 问题

用户点「停止生成」后，引擎把这一轮收尾成一条 `stopReason: "aborted"` 的 assistant 消息，
`errorMessage` 是底层的 `Request was aborted`。桌面端 `AssistantMessage` 只看
`stopReason === "error"` 之外没有别的分支——实际上 `aborted` 一直走的是同一条渲染路径的兄弟情况：
红底红字的 `ErrorBanner`（`--error-bg` / `--error-border` / `--danger`）。

结果是「我自己按了停止」这件完全正常的事，在对话流里长得像一次故障：一块红色矩形横在中间，
和上下的浅灰气泡完全不是一个色系，视觉噪音很大。

## 目标

打断是**状态转折**，不是**错误**。它在语义上和「上下文已压缩」同类：都是这一段对话被人为切了一刀。
所以视觉上也应该向压缩气泡看齐——低饱和、dim 文字、虚线感，并且横贯整行像一条分割线，
而不是居中的一颗红药丸。

## 方案

### 1. 新组件 `InterruptDivider`

`kalo-desktop/src/components/InterruptDivider.tsx`：

- 一条横贯可用宽度的**波浪线**（SVG `path`，`stroke="currentColor"`，`pattern` 方式横向平铺），
  颜色取 `text-dim`，透明度 ~0.45，和压缩气泡的 `border-dashed border-edge` 处在同一个灰阶。
- 波浪线中间留一段文字：「已打断」，`text-xs text-dim`，两侧各留 padding 让波浪不压字。
- 无边框、无背景色块（压缩气泡有 `bg-card/60` 是因为它可点击展开；打断不可展开，
  所以只留线和字，更轻）。
- 波浪由 `<svg>` + `<pattern>` 实现，可任意拉伸，不随缩放糊掉。

布局用 `flex items-center gap-2`：左波浪 `flex-1` + 文字 `shrink-0` + 右波浪 `flex-1`。

### 2. 时间线不新增 entry 类型

打断信息已经在 assistant 消息的 `stopReason` 上，没必要再造一个 `TimelineEntry`。
`AssistantMessage` 内部判断：

```
const interrupted = message.stopReason === "aborted" || isAbortError(message.errorMessage);
const failed = !interrupted && message.stopReason === "error" && message.errorMessage && !errorRetried;
```

- `interrupted` 为真时渲染 `<InterruptDivider />`，**不**渲染 `ErrorBanner`；
  底层的 `Request was aborted` 是实现细节，不给用户看。
- 一条 aborted 消息可能已经流式吐出了部分文本，这部分正常保留在分割线上方。
- 内容为空的 aborted 消息只剩一条波浪线，这正是想要的效果：
  「这里被你切了一刀」，没有多余的红块。

### 3. 工具执行中打断：只看 `stopReason` 不够（2026-09-12 补）

`stopReason: "aborted"` 只覆盖**模型正在流式输出**时的打断。如果打断落在**工具执行中**
（例如一条跑着的 `bash`），引擎是用 `AbortError` 把这一轮收尾的，前端收到的是
`stopReason: "error"` + `errorMessage: "The operation was aborted."`——同一个用户动作，
两种形状，于是这一支又掉回红色 `ErrorBanner`。

所以判断补一条消息文本识别，放在纯逻辑层 `src/lib/error-format.ts`：

```
export function isAbortError(raw: string | undefined): boolean
```

- 去掉 `AbortError:` / `Error:` 前缀与结尾句号后，与整条消息做**全等**比较
  （`aborted`、`operation was aborted`、`the operation was aborted`、
  `this operation was aborted`、`request was aborted`）
- 刻意不用 `includes`：`upstream aborted the connection`、
  `command aborted with exit code 130` 这类是真故障，必须继续红着
- 按消息文本而不是错误码匹配，因为跨 sidecar 边界传过来的只有字符串
- 被打断的那条工具调用本身仍显示 ✗（它确实没跑完），只是这一轮不再多一块红砖

### 4. 历史回放一致

`buildTimeline` 从会话文件重建时，assistant 消息的 `stopReason` 原样带回，
所以重开会话看到的还是同一条波浪线，不需要额外的合成逻辑。

`pushAssistantEntry`（retry-fold.ts）里把连续同错误的 assistant 消息折叠成一条，
只匹配 `stopReason === "error"`，aborted 不受影响。

## 不做的事

- 不给打断加展开/收起（没有可展开的内容）。
- 不在打断分割线上放时间戳或 token 用量（本轮 usage 已经由 `agent_settled` 的
  footer 负责，打断的那一轮同样会拿到）。
- 压缩失败/取消的 `notice` 文案不动，它们走的是 `NoticeEntry`，与本改动无关。

## 验证

- `kalo-desktop` 下 `npx tsc --noEmit`
- `src/lib/error-format.test.ts`：打断文案（含前缀/句号/大小写变体）判 true；空值判 false；
  「提到 abort 的真故障」判 false；顺带覆盖 `formatApiError` 的三条摘要路径
- 手工：发一条长任务 → 点停止 → 看到浅灰波浪线「已打断」，无红块；刷新会话后仍是波浪线。
  工具执行中（长 `bash`）点停止同样只出波浪线。
