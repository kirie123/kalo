# 版本号管理

## 背景

仓库此前没有统一的版本管理入口，版本号散落在 5 处，改一个漏四个：

| 文件 | 字段 | 谁在读 |
| --- | --- | --- |
| `package.json` | `version` | 仓库元信息 |
| `kalo-desktop/package.json` | `version` | 前端 workspace |
| `kalo-desktop/src-tauri/tauri.conf.json` | `version` | **安装包/NSIS 显示的版本** |
| `kalo-desktop/src-tauri/Cargo.toml` | `[package] version` | crate 版本 |
| `kalo-desktop/src-tauri/Cargo.lock` | `[[package]] name = "kalo"` | 漏改会在下次 `cargo build` 时被自动改写，混进无关 diff |

真正决定用户看到的版本的是 `tauri.conf.json`，最容易被忘的也是它。

## 方案

`scripts/version.mjs`：一条命令改全部。

```
bun run version:show           # 打印各文件当前版本，不一致时退出码 1
bun run version:patch          # 0.1.0 -> 0.1.1
bun run version:minor          # 0.1.0 -> 0.2.0
bun run version:major          # 0.1.0 -> 1.0.0
bun run version:set 1.4.2      # 指定版本
bun scripts/version.mjs patch --dry-run   # 只看会改什么
```

设计要点：

- **文本级替换**，不做 `JSON.parse` + `stringify`，保证缩进、键顺序、TOML 注释原样不动，diff 里每个文件只有一行。
- **先全部读完再写**，任一文件找不到版本字段就直接失败退出，避免改到一半导致版本不一致。
- 允许修复已经漂移的状态：检测到不一致时 `version:show` 报错并提示，带目标版本执行则统一写平。
- **不碰 git**：不自动 commit、不打 tag，只在结尾打印建议命令。发版流程还没定，脚本不预设。
- 脚本名故意不叫 `version`，避免被 `npm version` 的生命周期钩子意外触发。
