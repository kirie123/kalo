# 中止正在进行的上下文压缩

**日期**：2026-09-09  
**影响范围**：桌面端输入区、`kalo-harness` RPC 会话中止流程

## 问题

桌面端在上下文压缩期间仍显示停止按钮，但点击后 RPC `abort` 只中止 agent 主循环，不会中止压缩使用的独立 `AbortController`。压缩摘要请求继续等待模型返回，RPC 又等待 agent idle，因此按钮没有即时效果。

## 方案

### 引擎侧

`AgentSession.abort()` 同时执行：

1. `abortRetry()`，取消自动重试；
2. `abortCompaction()`，取消手动或自动压缩的摘要请求；
3. `abortBranchSummary()`，取消相关摘要任务；
4. `agent.abort()`，取消当前 agent 请求；
5. 等待 agent 回到 idle。

压缩方法已经把对应 signal 传给摘要模型调用，并会发出 `compaction_end(aborted: true)`，因此桌面端可沿用现有“上下文压缩已取消”的时间线结算逻辑。

### 桌面端

点击停止后立即设置本地 `isAborting` 状态，按钮显示“正在停止”，避免用户误以为点击没有生效；RPC 返回或失败后清除该状态。压缩和普通生成共用这条中止路径，不新增通信命令或改变 RPC 契约。

## 用户可见行为

- 压缩中点击停止：摘要请求被取消，时间线显示“上下文压缩已取消”。
- 普通生成中点击停止：保持原有行为。
- 停止请求尚未返回期间：停止按钮禁用并显示“正在停止”，避免重复发送 abort。

## 验证

- 引擎侧运行 coding-agent 相关检查。
- 桌面端运行 TypeScript / 纯逻辑测试。
- 重建 sidecar 后同步 Windows 二进制；若本机无法构建，必须明确标记未完成。
