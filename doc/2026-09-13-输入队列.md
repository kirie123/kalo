# 运行中输入进入「输入队列」（默认等执行完，可手动立即插入）

## 问题

对话运行中在输入框敲一句话按 Enter，桌面端当前的行为是**立刻 steer**：
`chat-store.sendPrompt` 在 `isStreaming` 时给引擎的 `prompt` 命令带上
`streamingBehavior: "steer"`，引擎把消息压进 steering 队列，当前工具调用一结束就
塞进这一轮。

副作用：

- **没有反悔余地**：一旦回车就进了引擎队列，桌面端既看不到它，也删不掉、改不了。
- **默认打断**：多数时候用户只是想「等它跑完再说这句」，却总是打断当前轮的思路。
- **附件语义模糊**：图片/文件在回车瞬间就被消费掉，无法确认「这张图跟的是哪句话」。

## 目标

在输入框**上方**加一条可见的「输入队列」：

1. 运行中回车 → 消息（文字 + 图片/文件附件）进入队列，**默认等本轮执行完再发**。
2. 每个队列条目是一个条形控件：左侧显示文本预览与附件缩略图，右侧一个投递方式
   按钮，可选「立即插入（steer）」或「等执行完」。
3. 选「立即插入」= 立刻交给引擎 steer，条目从队列消失（与今天的行为等价）。
4. 空闲时回车不走队列，直接发送（保持现有手感）。

## 方案

### 状态：会话级、客户端持有

队列是**桌面端**的状态，不是引擎队列的镜像：只有真正被投递出去的条目才会到引擎，
因此队列里的条目随时可删、可回填编辑、可改投递方式。

`SessionView`（`src/lib/chat-store.ts`）新增一个字段，随会话走（切到别的会话再切
回来，队列还在；后台会话跑完也照样自动发送）：

```ts
inputQueue: QueuedInput[];
```

条目类型与全部纯逻辑放在新文件 `src/lib/input-queue.ts`：

```ts
export interface QueuedInput {
  id: string;
  /** 用户敲的原文，不含 <attachments> 标签 */
  text: string;
  /** 入队瞬间的附件快照（图片带 base64，文件带路径） */
  attachments: AttachmentDraft[];
  createdAt: number;
}
```

该模块导出的纯函数（可单测，不碰 IPC/DOM）：

| 函数 | 职责 |
| --- | --- |
| `createQueuedInput(text, attachments)` | 组装条目；文本与附件都为空时返回 `null` |
| `removeQueuedInput(queue, id)` / `takeQueuedInput(queue, id)` | 删除 / 取出并返回条目 |
| `shouldEnqueue(state)` | 判定这次回车是「入队」还是「直接发送」 |
| `buildPromptPayload(text, attachments)` | 把文本 + 附件拆成 `{ message, images }`（复用 `formatAttachmentTag`），发送路径与队列路径共用 |
| `queuedPreview(item)` | 条形控件上的一行预览（无文本时退化为附件名） |

`buildPromptPayload` 是从 `sendPrompt` 里抽出来的既有逻辑：直接发送与队列投递必须
拼出**同一种** prompt，否则「排队发的」和「直接发的」会在附件标签上出现分叉。

### 投递时机

| 场景 | 行为 |
| --- | --- |
| 空闲时回车 | 直接发送（`prompt`，无 `streamingBehavior`） |
| 运行中（`isStreaming` / `isCompacting`）回车 | 入队，默认「等执行完」 |
| 队列非空时回车 | 也入队（保序，避免后敲的先发） |
| 条目点「立即插入」且仍在运行 | 立刻 `prompt` + `streamingBehavior: "steer"`，条目移出队列 |
| 条目点「立即插入」但已空闲 | 直接发送 |
| `agent_settled`（本轮真正结束） | 自动取队首一条发送；其余留在队列，下一轮 settled 再发 |

一次 settled 只发一条，是因为发出去就会立刻开新一轮：队列天然被后续的 settled
依次抽干，用户在这期间仍可删掉还没轮到的条目。

**中止是一个例外**：用户按停止也会走到 `agent_settled`，但「停止」的意思是别再自己动。
`abort()` 会给运行时打一个 `queueHold`，本次 settled 不自动发，只 toast 提醒「队列里还有 N
条」；条目原地留着，用户自己选「立即发送」或删掉。下一轮 `agent_start` 会清掉这个标记，
队列恢复自动投递。

发送失败（引擎已退出等）时条目**放回队首**并 toast，不会静默丢消息；下一次回车入队时，
若会话已空闲且不在 hold，会立刻再抽一次队首。

### 附件

入队时把 composer 上的附件快照进条目，并清空 composer 的附件区——这样「这张图跟的
是哪句话」是确定的，用户可以接着为下一条排队消息挑新附件。

投递时用条目自带的快照（不是当前 composer 的附件），因此 `sendPrompt` 增加一个可选
的附件参数：

```ts
async sendPrompt(text: string, rt = this.rt, drafts?: AttachmentDraft[])
```

- 不传 `drafts`：消费 `rt.view.attachments`（原行为），发完清空。
- 传 `drafts`：用队列条目的快照，不动 composer 的附件。

`rt` 参数是为了让**后台会话**的队列也能在它自己的 `agent_settled` 上投递（原来的
`sendPrompt` 写死了活动会话）。

### 引擎契约

**不变**。队列只用现有的 `prompt` 命令与 `streamingBehavior: "steer"`，引擎侧
（`kalo-harness`）无需改动，`queue_update` 事件继续忽略（引擎队列里的消息此时已经
不属于桌面端管辖）。

### UI

新组件 `src/components/InputQueue.tsx`，渲染在 `InputBox` 的输入卡片**上方**（同一
个 `max-w-3xl` 容器内，所以首屏 EmptyState 与会话页共用）：

```
┌────────────────────────────────────────────────────────────┐
│ 排队中 2 条 · 本轮结束后依次发送                            │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ [🖼][🖼] 帮我把这两张图里的表格转成 markdown …  [等执行完 ▾][×] │
│ └──────────────────────────────────────────────────────┘   │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ 顺便跑一下 npm run check                        [等执行完 ▾][×] │
│ └──────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────┘
```

- 条形控件左侧：图片缩略图（点击开大图沿用 `ImageLightbox`）、文件名 chip、文本预览
  （单行截断，`title` 显示全文）。
- 右侧下拉：`等执行完`（当前态，打勾）/ `立即插入（打断当前轮）`。选后者即刻投递。
- 最右 `×`：删除条目。
- 点条目正文：回填输入框编辑（条目出队，文本进 `inputDraft`，附件回到 composer）。
- 空队列不渲染任何东西。

输入框 placeholder 在运行中改为「输入消息，Enter 加入队列（本轮结束后自动发送）」。

## 影响与验证

- 纯逻辑测试：`src/lib/input-queue.test.ts`（入队/出队、payload 组装、入队判定、预览）。
- 竞态防护：`prompt` 命令已发出但 `agent_start` 还没回来的窗口里，`SessionRuntime.dispatching`
  同样算「运行中」，避免这一瞬回车的消息绕过队列直接撞上即将开始的那一轮。
- 组件与 IPC 路径人工验证：
  1. 运行中敲两句 → 队列出现两条 → 本轮结束后依次自动发送。
  2. 队列条目选「立即插入」→ 当前轮工具调用结束后模型立刻读到该消息。
  3. 带图片入队 → 缩略图在条形控件上可见 → 发送后用户气泡里带图。
  4. 点条目正文 → 文本与附件回到输入框，队列里少一条。
  4.5 排队中按停止 → 队列不自动发，提示可逐条立即发送。
  5. 切到别的会话再切回 → 队列还在；后台会话跑完 → 自动发送生效。
- `chat-store.ts` 仍在 `.quality-baseline.json` 的超限名单里（只许缩），所以这次顺手把三块不需要 store 私有
  状态的逻辑搬出去，净行数反而从 1405 降到 1385：
  - `src/lib/attachment-intake.ts`：路径/File → `AttachmentDraft` 的读取与追加（含去重改名）
  - `src/lib/input-queue.ts`：队列纯逻辑 + `buildPromptPayload`
  - `src/lib/assistant-stream.ts`：流式 assistant 消息的块拼装（`applyBlockEvent` / `seedMessage`）
